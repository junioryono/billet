# billet Ansible collection

`junioryono.billet.host` turns an already installed Linux machine into a billet control plane and Firecracker compute host. It installs the billet binary supplied by the operator, creates the service identity and systemd units, installs Firecracker and Ceph client tooling, loads the RBD kernel client now and after every boot, creates isolated DHCP/NAT guest bridges, renders `billet.yaml`, checks the Ceph pools, and configures a periodic Ceph health check. The guest policy admits the configured image-verification callback only on the trusted bridge, so `billet images verify` works without exposing arbitrary host ports. It drains the node before changing any live guest-network input and restarts it after a selected Firecracker binary changes. An installed `billet_service_user` or `billet_service_group` change is refused before account or state ownership mutation because moving the ledger and credentials is an explicit offline migration. A binary upgrade is transactional: the role inspects the controller's candidate digest, copies that binary and every generated candidate artifact into one unique recovery journal, rechecks the journaled digest, preserves the installed configuration, units and binary, records prior identity, exact supported systemd enablement and active-service state in a durable manifest, and claims `/var/lib/billet/upgrades/active` with a no-replace hard link. It refuses redirected configuration or unit inputs and masked, linked, alias, or transient enablement before mutation because those symlink topologies and in-memory definitions cannot be reconstructed from an enablement label. It then proves only the configured Firecracker images this node can run, preferring to boot-verify an already imported generation that records the required guest contract before it fetches another compatible signed replacement, drains the node, stops the server, removes the installed executable so operator commands cannot race the migration, establishes and durably flushes the maintenance fence, preserves and commits the stopped-ledger snapshot, and installs and validates the journaled candidate as the only ledger writer. Candidate units run explicit quiescent probes: the server opens and validates the fenced ledger without polling GitHub or dispatching work, while the node initializes its provider without registration or workload polling. Each candidate process notifies systemd only after that initialization completes; ordinary no-binary convergence preserves each installed unit's `Type=notify` or `Type=exec` readiness protocol so updating the collection cannot impose notification on an unchanged legacy binary or restart an already upgraded service merely to remove it. The role proves both candidates remain stable before it installs steady-state units with no maintenance bypass, persists desired enablement, flushes every mutated host filesystem, and records the durable commit. The shared finalizer then opens administration, replaces probes with full services in server-then-node order, proves their stability, and removes the active pointer only after success. The role accepts only distinct dedicated state directories below `/var/lib/billet`, derives recovery paths and ownership from the validated manifest, and refuses symlinks before it changes ownership or restores privileged files. If Ansible or the host is interrupted while the active pointer exists, the next converge inspects it before account, package, Firecracker, networking, Ceph, or other desired-state work and then asks for a fresh converge. An uncommitted transaction first proves both services terminal with zero main/control PIDs and conclusively empty or absent cgroups, validates the completed snapshot before removing current ledger entries, disables candidate units and removes their persistent and runtime enablement links before restoring or removing the previous unit files, restores the exact prior configuration, units, binary, enablement and ledger, durably records the rollback, then opens administration and returns only the previously active services; a failed first installation therefore cannot leave dangling links that enable a later installation. A transaction whose upgrade or rollback commit record already exists retries only finalization and retains the pointer until full services are stable; it never restores old state after operator writes may have been admitted. A compatible verified generation remains published because another upgraded host may already depend on that fleet-wide fact; unused immutable generations are left for retention. If process or recovery evidence is inconclusive, restoration stops before modifying the ledger and leaves the active pointer and recovery directory for manual inspection. It never creates a GitHub App, invents capacity, chooses disks, or starts billet until the supplied configuration passes `billet check`. An existing GitHub App private key is never replaced implicitly: a matching source is accepted idempotently, while a different source is refused so credential rotation remains an explicit operator action. Setting either service enable flag to false stops and disables a service previously installed by the role. Setting `billet_alert_email` back to empty or disabling Ceph stops and removes the Ceph health timer and removes `/etc/msmtprc` only when this role created it, including configurations created before the ownership sidecar existed.

The role can bootstrap a new single-host Ceph cluster only when `billet_ceph_bootstrap` is explicitly true and `billet_ceph_devices` names every device to consume. That path is destructive by definition and is never inferred from available disks.

Set `billet_binary_src` to the Linux binary the role should install. A repository can pin the collection and binary to one release by downloading it into a controller-side staging directory, then passing the verified file directly to the role:

```bash
billet_stage=$(mktemp -d)
curl -fsSL https://raw.githubusercontent.com/junioryono/billet/v0.3.0/scripts/install.sh | BILLET_VERSION=v0.3.0 BILLET_OS=linux BILLET_ARCH=amd64 BILLET_INSTALL_DIR="$billet_stage" sh
ansible-playbook site.yml -e "billet_binary_src=$billet_stage/billet"
```

A Billet contributor can instead build the binary from the same checkout as the collection. Keeping the binary input explicit makes the requested version auditable; the role owns the safe drain, image-compatibility, migration, recovery, and restart sequence when that input changes. An unchanged candidate and compatible recorded generation are metadata-only checks, so an ordinary second converge neither downloads the guest again nor reports a binary change.

The destructive host acceptance harness kills the Ansible controller at every claim, executable, snapshot, migration, quiescent-probe, durable-decision, full-service, fence-removal and pointer-removal boundary. It requires a maintenance-window host already running Billet plus two valid binaries with different hashes; it checks exact binary/config/unit hashes, owners, modes, active and enabled service state, full rather than probe service processes, ledger validation, fence cleanup, manager-environment cleanup and final idempotence after every recovery. It never reads the GitHub App private key. Point it at an inventory that supplies the ordinary role variables:

```bash
BILLET_ACCEPT_DESTRUCTIVE_HOST_UPGRADE_TEST=1 ansible_collections/junioryono/billet/tests/host-upgrade-live.sh inventory.yml host-a /tmp/billet-candidate-a /tmp/billet-candidate-b
```

See `roles/host/defaults/main.yml` for the complete input surface.

`junioryono.billet.development_host` is a separate, reusable developer-machine layer for Debian-family systemd hosts and macOS. It installs current Caddy and Terraform from their publishers' repositories, installs mkcert, stages and validates a caller-defined certificate/key pair before installation, and keeps a caller-supplied Caddyfile running across reboots through systemd or launchd. The role has no application or domain defaults: a repository supplies its SANs, proxy configuration and environment, while Billet owns package verification, CA trust, private-key permissions and service lifecycle. Disabling the proxy unloads and removes the prior systemd or launchd definition.

The role defaults to a localhost-only certificate and an empty proxy routing table. Set `billet_development_tls_sans` and `billet_development_proxy_config_src` for a real project. On macOS, Homebrew must already be installed; every formula and the launchd service are then converged by the role. See `roles/development_host/defaults/main.yml` for the complete input surface.

Run the playbook with `--check --diff` before converging a new or existing machine. The role still runs read-only identity, package and version probes in check mode, while deferring generated certificate validation until the files exist, so a first dry run can describe the installation without failing on tools it has not installed yet.

```yaml
- name: Configure development machines
  hosts: development
  gather_facts: true
  roles:
    - role: junioryono.billet.development_host
      billet_development_tls_sans:
        - "*.dev.example.test"
        - dev.example.test
        - localhost
        - 127.0.0.1
        - "::1"
      billet_development_proxy_config_src: "{{ playbook_dir }}/Caddyfile"
      billet_development_proxy_environment:
        DEVELOPMENT_CERT_FILE: "{{ billet_development_tls_cert_path }}"
        DEVELOPMENT_KEY_FILE: "{{ billet_development_tls_key_path }}"
```

Add a new Linux or macOS machine to that inventory group and rerun the playbook; package installation, local trust, certificate renewal on SAN changes, configuration validation and boot persistence all converge through the same role.
