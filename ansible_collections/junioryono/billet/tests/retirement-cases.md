# Corpus gaps

The existing continuation classifier fixtures all report `intent`; there is no classifier fixture for each later phase or for a journal already at `done`. Thus R3 cannot prove every phase and R4/R5 and the boundary prove the done ANSWER and bypass, not a done-shaped classifier observation. There is no settled `unchanged` answer with `postconditions.status: republished`, so the changed-reporting branch has no positive fixture control.

R10 has no retained-node journal classifier at intent, after the archive or done. R11 has no unexplained status-only or stage-only classifier; the incapable-answerer screen does exercise those path vetoes, and the marker classifier is covered. R14 has no another-host row classifier for either request flag. R15 has no node-only or never-commissioned unreadable-row classifier; those admissions are covered only in the role's incapable-answerer path. R18 has no abnormal-claim classifier fixture: substituting the unexplained-marker answer after damaging a claim would prove a different refusal, so that case was not fabricated. R8 still lacks a settled-journal/closed-status pair from the producer corpus; its three independent path vetoes do not establish that paired state. No file under `tests/fixtures/` was written, edited or staged.

The two inventory transports in the tail case share one namespace and its real prepared guard; this proves caller sequencing and document binding, not independent machine custody. Fleet preparation and the remaining reservation cases belong to 5c.d.

# Contract notes

The complete-classifier floor is `v0.11.0`, the next minor cut from `main`; `v0.10.1` remains an incapable maintenance-release control. The caller accepts one UTF-8 YAML mapping with string mapping keys, no anchors, aliases, merge keys, explicit tags or duplicate keys anywhere, and non-empty absolute string locators without padding. It validates both supplied locators before selecting identity_dir over state_dir. A null state block is absent; a non-null state block supplies no default, but inherits a supplied state_dir just as applyStateDefaults does before semantic validation. The caller uses the packaged identity path only for a positively absent configuration; undecodable bytes or an unestablished locator hold by name. A server with neither locator and no state block (or a null state) holds because Go's defaultStateDir depends on the running account: it uses os.UserConfigDir and falls back to .billet/server if that lookup fails. Only an absent server key beside a node mapping yields a node-only hint; a configuration with neither section or a non-mapping node holds by name. This deliberately tightens revision 12's undecodable-config fallback in the caller. Python does not implement Go's KnownFields or typed configuration decoding: roles and locators are hints, never permission. Both compatibility admissions additionally require a successful `systemctl show billet-server.service --property=LoadState,UnitFileState,ActiveState,MainPID`, run with `check_mode: false` and `changed_when: false`. Complete exact property lines must show `LoadState=not-found` (empty UnitFileState, inactive, MainPID=0), or a loaded/masked unit with UnitFileState in disabled/masked, ActiveState=inactive and MainPID=0. Failed or unreadable reads, missing or duplicate properties and unknown words hold by name. Darwin holds because retirement is Linux-only. A running enabled controller cannot be cleared by any installed bytes.

The accepted pre-release compatibility residual is a controller whose server unit is disabled and stopped, whose installed configuration Go cannot decode, and whose identity lives at a custom location: it can still be admitted. This is the same shape as the Go classifier's own accepted residual for an undecodable configuration; the Python hint may name a clean location while Go cannot recover the custom locator.

Only YAML directive 1.1 is accepted. Every decoded scalar, keys included, is checked for surrogate code points, and every unexpected exception at the filter boundary returns a named hold. The unknown `note` field vector intentionally retains its server locator expectation as a hint; the section R service-state matrix proves it cannot admit the host without independent no-controller evidence. The Go classifier's recovery reason says to retry classification, while revision 12's explicit caller boundary requires a fresh converge: this implementation ends the invocation and lets the next preparation/classification do that retry. The older `dry-run-request`, `dry-run-adopt` and `dry-run-unknown-ledger` filenames describe dispatch, not route; the command's route wins. No command behaviour was changed.
