# The identity directory's exclusion

Part of the `billet-identity-and-ca` skill. Each rule is stated in full, with the measurement or incident behind it.

**A retirement's own exclusion acquires and never admits.** `Hold.Admit` is the ordinary writers' gate and refuses a closed status; the status a transition publishes is its own, and the transition is the one writer it allows, because it holds the host's transaction lock and this converge's guard, which no ordinary writer does. `wirecert.ResolveRetiringExclusion` is that path (a PREPARED host only: a host with no record has no global exclusion to close), and `openRetireIdentity` (with `retiring` set) takes the inner `ca.lock` inside the directory under it, after the retirement's own admission for that step and again after the global lock's wait, so a legacy writer holding only the inner lock is excluded from the rename too. The access is told the directory MOVED (`moved()`), because after the rename there is nothing at its name to hand back. Every other writer meets the closed status and exits with status 6 (`exitRetiring`), which is what makes the backup's refusal recognisable to the transition that caused it — `openIdentityAccess` wraps `ErrRetiring` in a `*cli.ExitError` that KEEPS the cause, so `errors.As` still reaches it.

**An observer of the authority takes no lock and creates nothing.** `wirecert.SnapshotAuthority` reads the public half of the authority (`ca.crt`, `ca-previous.crt`, `authority-created`) twice and answers only when the two reads agree, an absent file and an empty one being different observations (`bytes.Equal` alone calls them equal and would confirm a read that saw no predecessor with one that saw a malformed one), three attempts, else `ErrAuthorityChanging`: the same confirming-read shape `LoadServing` uses, because a rotation or a retirement can cross a single read. It must not take `LockAuthority`, which does `MkdirAll` and opens `ca.lock` with `O_CREATE`, so a read-only inspection of a freshly commissioned controller would otherwise leave a root-owned lock file in service-owned state; a controller can serve without `ca.lock` ever existing. The key files are never opened. `ParseCertificates` reads every `CERTIFICATE` block of a bundle's CA file in order, because a node mid-rotation legitimately holds a predecessor beside the current authority, and it follows the TLS loader's line rule rather than being more forgiving: a BEGIN marker counts only at the start of the text or after a newline (Go's `pem.Decode` skips an indented one, so the loader's pool would not hold that certificate and the report must not say it does), an END marker must end its line, trailing spaces or tabs allowed as Go allows them (two blocks glued together are a malformed boundary, not two certificates), a malformed block is refused rather than skipped, and only whole blank lines are permitted around and between blocks. `isOnePEMBlock` rests on the same `decodeFirstPEM` and `skipBlankLines`.

**Every writer of the identity directory takes the exclusion before its first access, and borrows it downward.** `internal/retirement` is the leaf `wirecert` and `cmd/billet` both import: the global lock (`/var/lib/billet/authority.lock`, root:`billet` 0660, opened read-only because `flock(2)` needs no write access), the world-readable status (`authority-status`) a retirement closes the authority with, the service-account record (`service-account`, root's assertion), the fresh-initialisation lock beside an identity directory (`<parent>/.billet-identity.lock`), `Bootstrap` for installers and `Classify` for everyone. `cmd/billet`'s `openIdentityAccess` is the one entry: it classifies the host (prepared, legacy, fresh; a lock or a status beside a missing record is damage and refuses), takes what the mode needs in the one order (init lock, lifecycle lock for a root initialiser, global lock admitted, inner `ca.lock`), and `Release` hands root-created artefacts back to the recorded account through lifeops' descriptor repair (one link, same filesystem, named files only, relative to the CLEANED directory through `filepath.Rel`, since the producers clean their paths and a trailing slash once left every target absolute) before it drops the locks in reverse; the account is READ AT RELEASE, under the locks still held, because an installer can publish the record while a legacy root writer holds the inner lock. AN ABSENT DIRECTORY IS NEVER RECREATED BY AN ORDINARY LOCK, AND NO RESOLUTION GRANTS CREATION ON LINUX: `Exclusion.Create` is true off Linux and, on Linux, only for a caller holding the INIT LOCK beside the directory that re-established the four absences under it (`openIdentityAccess`'s fresh branch, and `wirecert.LockAuthority`'s own `resolveForLibraryCaller` for a caller with no command around it, whose init hold travels with the lock); a cached FRESH classification authorises nothing, because an installer can prepare the host and a retirement archive its directory in the gap. A prepared host's absent directory, or a legacy host's that vanished since classification, refuses in `LockAuthorityWith` before `lockInner`. THE LEDGER FACTORIES RUN UNDER THE SAME EXCLUSION (`underIdentityExclusion` in `ledger.go`): a command that already holds an access is found in the process-wide registry (`heldAccesses`, keyed by cleaned directory, registered by `openIdentityAccess` and cleared by `Release`) and lends it; a command that holds none (`billet status`, the upgrade timer's `openStateForDecision`) takes one for the open and releases it once the handle exists, so `state.OpenAdmin`'s `MkdirAll` can never race a retirement's rename and a `billet status` five minutes later cannot mint a second identity beside the archive. `deployarchive.Execute` and `Abandon` take the authority BEFORE they create the directory or its lock on their unborrowed paths, the same order as the commands. `Release` hands back the identity artefacts AND the ledger artefacts, because a ledger open made before an installer published the record found no account at the time. Every existing lock file (global, init, inner, and the repair's) is opened through `regularfile.Open` with `NoFollow`, so a FIFO planted at a lock's name refuses instead of blocking inside the open before any deadline runs. `wirecert.LockAuthority(ctx, dir)` resolves the exclusion itself for a caller with no command around it; `LockAuthorityWith` takes a resolved one; `RotateWith`/`RetireWith` run under a lock the command already holds, since a second flock in one process is denied. `deployarchive.Write` and `Execute` borrow `Authority` when the command passes it. The ledger factories hand back on the OPEN ATTEMPT (`handBackLedger` after `OpenAdmin`, success or failure), because `openDir` creates `billet.lock` before it connects.
