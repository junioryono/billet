# Measured facts

Part of the `billet-lifecycle` skill: what was measured, dated where it was recorded.

- On the reference systemd node, `ProtectSystem=strict` made `/var/lib/billet/upgrades` and `/usr/bin` read-only to the node's children: its first dispatched upgrade refused `open /var/lib/billet/upgrades/transaction.lock: read-only file system` on 2026-09-06 (#98). `setsid` does not escape the unit's cgroup; `KillMode=mixed` kills that child when the updater stops the node. Node upgrades therefore launch through `systemd-run` in a transient root oneshot of their own; opening more writable paths in the node unit would leave the lifetime defect.
- A focused `ExecUpgrader` probe on Ubuntu 24.04 arm64/systemd 255.4-1ubuntu8.17 (2026-09-06) received a fixture PostgreSQL variable through `systemd-run --setenv=NAME` without its value in argv, acknowledged through the node's state-directory socket, stopped a parent unit with `ProtectSystem=strict`, `PrivateTmp=true` and `KillMode=mixed`, and wrote outside the parent's writable paths after that stop returned. Both units exited successfully and the socket was gone. This proves the launch boundary, not the full host-upgrade transaction.
- Ubuntu 24.04 / systemd 255 for every systemd fact above; macOS 26 for every launchd fact, in `internal/lifeops/launchd/reallaunchd_test.go`.
- launchd default `ExitTimeOut`: 5 seconds.
- macOS 27.0 (2026-09-29, a Mac mini) clamps a launch agent's `ExitTimeOut` to 60: declared 30 loads 30; 61, 120, 600, 3600 and 88200 load 60. A throwaway agent draining 90s on SIGTERM, with `KeepAlive{SuccessfulExit:false}`: SIGTERMed directly it drained the full 90s, exited 0, was not restarted, and a bootout afterwards took 0s; booted out while draining it was SIGKILLed at 61s with the drain unfinished. `launchctl kill TERM <service>` measured the same as a direct SIGTERM: drained 90s, exited 0, not restarted, bootout after 0s. `TestStopAndProveOutlastsTheClampedExitTimeout` (`BILLET_LAUNCHD_LONG_DRAIN=1`) is the real-launchd witness.
- A CGO_ENABLED=0 Go 1.26 binary that never called `signal.Notify` for SIGUSR1 survived two SIGUSR1s and exited 0 when it finished (macOS 26, 2026-09-30, a throwaway probe); the Go runtime's handler drops an unwanted `_SigNotify` signal (`runtime/signal_unix.go`, `sighandler`). The drain-request gate is therefore about a stop waiting on a drain nobody began, and about the instant before a process's runtime installs its handler. The request path is not yet witnessed against a real launch agent; `internal/lifeops/launchd/drainreport_test.go` drives it through the fake.
- A `Setsid` child of a launch agent survives `bootout` of that agent and keeps running after the agent's process exits (macOS 26, `realscheduled_test.go`); this is what lets the node agent start the updater that boots it out.
- A oneshot with `StartInterval` and no `KeepAlive` runs at load and stays loaded, with no process, after exiting 0.
- `bootout`: returns in 0 seconds with the process still draining.
- A launchd-managed node ran a real Actions job to green and destroyed its guest.
- The restore rehearsal found the ownership gap `StateDirectory=` cannot repair.
- `make systemd-lifecycle` is the only test of the lifecycle against a real service manager and the real package; it skips without a working App credential.
- A unit with `PrivateTmp=true` cannot require a path under `/tmp` or `/var/tmp` in `ReadWritePaths`: systemd resolves it inside the fresh private directory and refuses the start with `226/NAMESPACE`, even when the host has the directory (systemd 255.4, ubuntu-24.04, 2026-09-22; a leading `-` or no entry starts, and the private `/var/tmp` is writable under `ProtectSystem=strict`). `billet-images-refresh.service` carried `/var/tmp/billet-images` and never started once on a systemd host, so nodes kept their first guest image while the timer failed daily; `TestNoPrivateTmpUnitRequiresAWritablePathUnderTmp` covers every packaged unit.
