# Conventions, parallelism and concurrency

Part of the `billet-testing` skill. Each rule is stated in full, with the measurement or incident behind it.

**Conventions.** `t.Context()` and `t.TempDir()` (enforced by `usetesting`), `t.Cleanup` for teardown so it runs on the `t.Fatal` path, table tests for pure functions and named tests for invariants so a failure names the invariant. Open a throwaway SQLite ledger with `state.Open(t.Context(), ledgertest.Dir(t))`: a fresh directory per test is still what makes the process lock and the pragma verification run for real, and `internal/state/ledgertest` puts a copy of a template migrated once into it, so the open verifies every recorded checksum without replaying the migrations (1.27s a fresh open under `-race`, 31ms a seeded one, measured 2026-10-03). A test about migrating itself, a restore, or a ledger an earlier billet wrote still opens an empty directory, and a directory that may already hold a ledger is seeded only when it does not (`internal/e2e`'s stack). Each test binary builds the template once with its own state.Open and keeps it in memory, never in a file shared between runs: a template under a shared temporary directory could be planted by another account with forged migration records that the open would accept. PostgreSQL ledgers are untouched.

**`t.Parallel()` turns on the sharing, not the disk.** `paralleltest` is disabled as a default rather than a ban, and 37 directories use parallel tests. A test with resources of its own (a `t.TempDir`, its own database, an `httptest` port) parallelises happily. What must run alone is a test sharing process-global state: one SQLite file two tests open, a fixed port, a daemon, the environment (`t.Setenv` refuses in a parallel test), or a package variable one of them mutates. The `parallelshared` analyzer reports the last case. Match the file you are adding to.

**A parallel test that writes an executable and then execs it can exec something else.** Between the open and the close of `os.WriteFile`, a fork in any other parallel test inherits the write descriptor, and until that child execs, exec of the file fails with ETXTBSY (Go issue 22315). `/bin/sh` does not stop there: it records the error and carries on down `PATH`, so a fake `df` lost to the real one, whose ample free space made `TestTheFreeSpaceGuardRefusesWhatItCannotRead` accept "not-a-number" (CI run 34827346038, 2026-09-14); `internal/guestassets` failed the same way exec'ing a shim it had just written. Where the thing faked is a command a shell script runs, define it as a shell function in the script under test; where a real executable is unavoidable, write it while holding `syscall.ForkLock` (`internal/guestassets`' `writeExecutable`), because syscall's forkExec, the path every `os/exec` start takes, holds that lock while it creates the child, so no such child can copy an open write descriptor (a raw or native fork is not covered). Retrying a start Go makes (`retryETXTBSY`) cannot help when a script execs the file itself, which is how `TestTheDockerShimLeavesEverythingElseAlone` failed (CI run 34831856345). Never let a fallback down `PATH` reach a real binary. The same inheritance holds a flock: a lock belongs to the open file description, a forked child shares it until its exec closes it, so a release that only closes the descriptor can leave the lock held (`TestASecondVerificationOnThisMachineIsRefused`, 2026-09-26). Every billet lock unlocks with `LOCK_UN` before it closes, and `TestReleasingTheProbeLockReleasesItWhileADuplicateIsOpen` stands in for the child with `unix.Dup`. Every package whose tests write an executable does it through that package's `forkSafeWriteFile` (in `forksafe_test.go` or `forksafe_ext_test.go`), which holds `syscall.ForkLock` across the write; a bare `os.WriteFile` with an executable mode is the flake (#233).

**Concurrency tests use the scheduler under test.** A race whose window is nanoseconds is not tested by two goroutines and a `WaitGroup`: the fake delays inside the operation, holding both callers in the transition. A wait that something else already satisfied is not a wait (count from a baseline taken before the thing under test exists). One timeout knob must never serve a deadline that must expire and deadlines that must not; compare the deadlines the code handed out instead (`context.WithTimeout` on a bounded parent keeps the parent's deadline, so an inherited context compares exactly equal). A clean `-race` run is evidence, not proof: it sees only the interleavings that occurred. A test whose observation shutdown can also produce (a destroy that `releaseAll` performs anyway) proves nothing about the loop.

**A test about time runs in a `testing/synctest` bubble, and nothing in the bubble waits on a real socket.** The listener's renewal tests once fed the heartbeat loop its ticks through test-only fields and moved the allocator's clock by hand, and still lost passes on a loaded runner, because each pass's budget, a third of the TTL, stayed on the wall clock (#188). Inside `synctest.Test` the loop's own ticker, every `context.WithTimeout` and `time.AfterFunc`, and the allocator's default clock read one fake clock that moves only when every goroutine in the bubble is durably blocked, so `time.Sleep(ttl/3)` followed by `synctest.Wait()` is one heartbeat interval with its pass finished when nothing in the pass can durably block, and a pass's budget cannot run out while it works. `Wait` says only that everything is durably blocked, not that anything completed: a pass held on a channel is still running when it returns, so judge such a pass by what it did, a channel it signalled or a lock now free; the six fields that drove the listener's loops were deleted (2026-10-08). Three things decide whether a bubble works. A SQLite ledger opened inside it works, template copy included. Every loop the code runs must block on something durable, so a fake that stands in for a long poll has to wait (`fakeSession.longPoll` in `internal/server`): a poll loop that returns at once keeps the bubble busy and fake time never moves. And nothing inside may wait on a real socket, a real process, or a `sync.Mutex` whose holder is itself waiting, none of which is durably blocking: the node wire goes through an in-memory transport (`bubbleTransport` in `internal/nodeclient`) rather than `httptest.NewServer`, and the `real*` tests that poll a real service manager stay on the wall clock. A hang guard inside a bubble is a `time.After` in fake time, because a loop that goes on taking its ticker's ticks keeps fake time advancing indefinitely, so a test stuck waiting on it never reports a deadlock; it runs on (a ticker nobody is receiving from is dropped from the bubble's timers, so a loop blocked inside a pass does not keep time moving). Judge renewal by what the reaper can take rather than by a hook in the loop: step through two TTLs reaping at every step (`throughTwoTTLs`), then ask `Heartbeat`.

**A stand-in must stay alive and be observable.** `sleep --id <id> 30` exits immediately on real coreutils; put the marker in `$0` via `sh -c <script> <name>` and poll `/proc` until the process is there, so "not appeared yet" and "exited" stop being the same observation. An image that exits at once (busybox) makes adoption untestable; the e2e suite uses one that keeps running. A fake that ignores `ctx.Err()` cannot distinguish cleanup on a cancelled context from cleanup on a fresh one. A queue that pops on read cannot model redelivery; hold the head until its exact id is acked.

**Structural tests assert order and call graphs where a unit test cannot reach the call site.** They parse source with `go/ast`: `TestOnlyTheProvingStepsMakeTheirProofs` (`internal/app/proofs_test.go`, which holds the control plane's order to its types; the two order tests it replaced parsed `runServer`), `TestOnlyTheForceOperationDestroysRunningWork` (`internal/server/forcecallers_test.go`), `TestAHealthyUpgradeRunsInOrder` and its siblings (`internal/hostupgrade/upgrade_test.go`), `TestANoOpUpgradeRecordsTheDecisionBeforeAcceptingIt` (`internal/ops/host/upgradefence_test.go`), the query-set tests in `internal/state/queryset_test.go`, `internal/rollout/dispatchguard_test.go`, `internal/node/reap_test.go`, `internal/ops/host/preservedpaths_test.go`, `scripts/onelinerblock_test.go`. Use one when the failure mode is a step moving rather than a property changing.
