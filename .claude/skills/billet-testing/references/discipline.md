# A test must be able to fail

Part of the `billet-testing` skill. Each rule is stated in full, with the measurement or incident behind it.

**A test must fail when the code is wrong, and the way to know is to break the code once.** Two of the original state tests passed regardless: one read `journal_mode` through the reader pool, where SQLite reports the file's persistent value whatever the writer configured; the other exercised the single-connection writer pool and called the result serialization. Before submitting a test for an invariant, neuter the production line it names (comment out the `syscall.Flock` in `internal/state/lock_unix.go`, run `TestSecondOpenIsRefused`, watch it fail, restore) and confirm the test goes red. A test whose mutation survives must be shown redundant, out loud, or fixed.

**A mutation harness must prove it changed the file, and a mutant must change behaviour.** Verify by hash, not by grepping for text that may already be absent: a substitution that matches nothing reports SURVIVED, which is indistinguishable from a vacuous test. A mutant that applies but changes nothing (an `_ = id` beside a `delete`) also reports SURVIVED; if you cannot name the assertion it should break, it is not a mutant. A mutant that does not compile is caught by the compiler and reads as a pass until the failing-test count says zero. `make no-mutants` runs first in `check` because an interrupted run leaves the original holding the mutant.

**Assert the diagnostic, not the shape.** Counting error lines stays green when the six errors are the wrong six. `installation_id is required; creating an App does not install it` exists because the failure is otherwise baffling, so the test asserts the clause. A test satisfied by "an error came back" cannot tell a refusal from a panic: deleting the guard that checks a request carries a client certificate made the handler dereference a nil `r.TLS`, the client saw an error, and `err != nil` passed. Assert the sentinel or the status.

**A discarded error is a vacuous assertion waiting to happen.** `n, _ := a.Headroom(ctx, "x"); if n != 0` passes when the call fails, because these APIs return the zero value beside an error; it bit seven times. Comma-ok is the same trap: `v, _ := m["k"].(T)` yields zero for an absent key. `errcheck` is enabled on tests for this reason (19 sites, two real bugs). Ask, for anything the linter cannot see: if this call errored, would my assertion still pass?

**Prove the mechanism is used, not only that it works.** Five instances in one day: `printAdmission` rendered a seal and nothing proved `billet status` called it; a fake converger carried its own copy of `StopAndProve`'s refusal so deleting the production one left the test green; `TidyStagedRegistration` had only test callers while its doc comment named a production one. Drive the caller, not the helper. A fake must return what it is told and judge nothing. Where the call site cannot be reached from a unit test, assert it structurally with `go/ast` (below).

**The test written to prove a fix tends to prove the adjacent thing.** Four rounds on the deployment lock: a gid comparison proved `20 == 20` because a temp dir is owned by the primary group; setgid was set before the file existed so the kernel supplied the gid; an `O_NOFOLLOW` test proved `os.Root` refuses an escape rather than a symlink; a "second process is refused" test ran both opens in one process, which a package mutex satisfies. The real one re-executes the binary (`internal/state/deploymentlock_process_test.go`), which is also the only way to prove SIGKILL frees the lock.

**When a platform behaviour matters, write a throwaway probe and run it where the code runs.** `os.Root` and symlinks, umask stripping mode bits, BSD versus Linux gid inheritance, `os.UserCacheDir` reading the environment: three defects were documented behaviour that read the other way. A probe on the development Mac is not evidence about the Linux builder (see `billet-shell-gates` for the four ways one lied); run it in `ubuntu:24.04`.

**Silence looks like success, and each silence has a guard.** A scripted substitution that matched nothing (assert `old in s` and check the hash changed); a mutant that changed nothing (name the assertion it breaks); a review prompt file that did not exist (refuse to launch without one); a scripted edit that deleted a whole test (`make tests-kept`); a killed mutation run that left its mutant in place (`make no-mutants`). The thing that would have objected was itself missing. And pass commit messages with `-F`: backticks in `git commit -m` are command substitution.
