# The suites: end to end, replay, real, live and the rehearsals

Part of the `billet-testing` skill. Each rule is stated in full, with the measurement or incident behind it.

**The end-to-end suite assembles billet the way `cmd/billet` does.** `internal/e2e` opens its control plane with `app.OpenControlPlane` and walks the steps `runServer` walks (`assemble_test.go`), and its node processes run `app.NewNodeClient`, `app.NewNodeRunner` and `app.RunNodeLoop`, as `billet node` does (ADR-015); the hand-copied adapter it began with had already drifted (it dereferenced a scale set the client returns as nil). What a test must change is steered through `app.Steering` (an allocator clock or lease TTL, node-plane pacing, scheduler pacing, an ordered provisioner), each applied after what the assembly sets, and an in-process runner through `ScheduleOptions.NodeRunner`; the wire-protocol scenarios (enrollment, mTLS, revocation, restore) still build a plane alone, on purpose. `internal/fakeactions` answers the handshake and serves what a test tells it to; it is deliberately not a simulator of GitHub, has no production callers and must acquire none. It exists because the worst defect in the project (`AcquireJobs` called with ids from `JobAssigned` instead of `JobAvailable`) lived in the relationship between billet and the wire, where billet's types agreed with billet's mistake. The one thing steered there is the allocator's clock, through `alloc.WithClock` in `app.Steering`. A stack can run over another backend through `withBackend(kind, build)`; the simulated one (`internal/provider/simulated`, `internal/e2e/simulated_test.go`) needs no docker daemon, so its scenarios run wherever the tests do, and it steers the provider's clock rather than the ledger's, because jumping the ledger past the lease TTL while heartbeats arrive on wall time would measure the reaper. Every scenario that is about the plane and the wire rather than about docker (lifecycle, wire, multiday, compute barrier, restart) runs through `forEachBackend`, once on docker and once on the simulated backend over one shared `simulated.Host` per leg, so a restarted stack (`sameBackend`) re-adopts what the previous process launched and a second deployment is on the same machine; the docker leg skips without a daemon and the simulated leg never does. A scenario stays docker-only when its subject is docker itself: the generated docker config launch.

**The replay harness drives a workload through the real scheduler at compressed time, and steers exactly two things.** `internal/replay` takes a trace of arrivals (tier, repository, workflow, duration; synthetic from `MorningBurst`, `MonorepoFanOut` and `LongTail`, or exported from a repository's Actions history by `scripts/export-actions-trace.sh`) and drives it through a scripted Actions service into the real listener, allocator, placer, node wire and node runtime over `internal/provider/simulated`, then reads every job back from `job_history` and joins it to the trace on the request id; a job the ledger has no row for is reported as missing, never filled in. What is steered: one virtual `Clock` that the allocator and every simulated provider read (the plane, the heartbeat and the node loops stay on wall time, because a plane on the simulated clock would expire a node parked across a jump of hours), and the order in which tiers open their sessions and contest freed room (fixed to the fleet's tier order, since escrow is placement and goroutine order would otherwise decide where a tier's first job lands). The reaper never ticks, for the multi-day scenario's reason. Determinism comes from delivering one event at a time to quiescence, where quiescence means every listener is parked on an empty queue with its advertisement unchanged since its last poll, because the listener hands surplus escrow back only after a poll carrying the smaller number has returned. When any tier has waiting work, the harness nudges every listener, including positive-advertisement donors: a donor parked forever cannot complete the withdrawal that releases its backing. Discovery rotation creates multiple unused escrow rows per tier; the capacity sweep must include them all. The four proofs that must stay green: two replays of one trace place and date every job identically; pack and spread leave different footprints; the ledger's own intervals never overcommit a host or the deployment (dropping the host term from `placer.roomFor` fails it); and every trace job has a ledger row (swallowing one completion fails it). The suite replays three hundred jobs by default; `BILLET_REPLAY_JOBS=2000` is the acceptance-size run, about a minute and a half on a laptop without the race detector and too slow for CI's shared race-instrumented test job, so CI runs it in its own `replay` job without `-race`; `-replay.out DIR` keeps each run's records and summary. The record's provider, charged shape, site, price and cache observations are the history row's own columns (migration 49, read through `ReadJobPlacement`); cost is derived from the recorded price or, for a host-backed lease that records none, from the fleet's per-host rate and labelled `fleet-rate`; locality is derived from placement and named as such, because a simulated guest observes nothing about the cache. It has no production importer, proved by the same importer walk `internal/importcheck` runs for `fakeactions` and the simulated backend.

**Generated shell is executed, never pattern-matched.** `scripts/` holds thirty-odd Go test files that run the build scripts against fixtures; `internal/provider/codebuild/buildspec_test.go` parses the buildspec and runs its commands under `/bin/sh`; the EC2 boot script is run with the runner command replaced by one that prints what it would have read.

**Real and live tests skip without their resource and never spend money by accident.** `real*_test.go` files assert that what billet says matches what the real system does, because the firecracker backend's two launch-killing defects survived every unit test and died on the first real run. Gates: `realdocker_test.go` needs `docker` on PATH; `realtart_test.go` needs `tart` (each test gets its own `TART_HOME`); `realguest_test.go` needs `BILLET_TART_GUEST_TESTS=1` (`BILLET_TART_GUEST_IMAGE`, `BILLET_TART_SOFTNET_TESTS=1`, `BILLET_TART_XCODE_TESTS=1` widen it); `realfirecracker_test.go` needs root plus `BILLET_TEST_GOLDEN_IMAGE`, `BILLET_TEST_BRIDGE`, `BILLET_TEST_KERNEL`, `BILLET_TEST_CACHE_POOL`, `BILLET_TEST_IMAGE_POOL`, `BILLET_TEST_CEPH_USER`; `realcodebuild_test.go` and `holdergone_live_test.go` need `BILLET_TEST_CODEBUILD_PROJECT` and AWS credentials; `realwalk_test.go` adds `BILLET_TEST_CODEBUILD_WALK=1` and records rather than asserts; the two `reals3_test.go` files (`internal/provider/ec2` for a presigned URL, `internal/awss3` for the two codes a 404 carries) need `BILLET_S3_TEST_BUCKET` and `BILLET_S3_TEST_REGION`; `internal/provider/ec2/live_test.go` needs `BILLET_LIVE_EC2_REGION` and friends; `internal/integration/sessionreplacement_test.go` needs `BILLET_LIVE_ORG` and `repositoryscope_live_test.go` needs `BILLET_LIVE_REPOSITORY`, each with `BILLET_LIVE_APP_ID`, `BILLET_LIVE_INSTALLATION_ID`, `BILLET_LIVE_APP_KEY` and `BILLET_LIVE_SCALE_SET`, and both record a JSON report under `BILLET_LIVE_REPORT_DIR` rather than asserting what GitHub answers; `reallaunchd_test.go` needs the macOS `launchctl`, and each test derives its own label because a launchd agent is not gone when its test ends. `cmd/billet/codebuildchecklive_test.go` is named live but drives a fake endpoint; it exists because a structural test proves a judgement is called and not that its result reaches the output.

**PostgreSQL is tested against a real server or not at all.** `BILLET_TEST_POSTGRES_DSN` gates `internal/state` and `internal/alloc`; `cmd/billet/localbackup_test.go` fails rather than skips when `CI` is set and the DSN is missing. CI runs `postgres:18-alpine` as a service and then re-runs only `./internal/alloc/` with `BILLET_TEST_LEDGER=postgres`, without `-race`.

**Coverage is a signal, not a goal.** `.codecov.yml`: project target `auto` (no regression from base, 1% threshold), patch target 80% (5% threshold), and only `cmd/billet/main.go` ignored, which is why nothing carrying real semantics may live in that file. A hard 85% on a project at 79% fails every PR and is learned to be ignored.

**The host rehearsals run the real commands on packaged hosts under real systemd, and each needs a real App.** `scripts/rehearsal-lib.sh` starts privileged `ubuntu:24.04` containers with systemd as PID 1 (the shape `scripts/test-systemd-lifecycle.sh` measured), installs a `.deb`, issues certificates as the service account and asserts on unit state, journals and files, never on an exit code alone. `make rollout-rehearsal` moves two hosts from one PUBLISHED release to the next by `billet rollout start` alone and rolls a downgrade candidate back (`BILLET_REHEARSAL_FROM`/`_TO`); `recover-rehearsal`, `ca-rotation-rehearsal` (twenty-minute leaves through `billet ca issue --lifetime`) and `promotion-rehearsal` (a PostgreSQL pair partitioned with `docker network disconnect`, keepalives set on the server) use the tree's own package from `make dist`. `retirement-rehearsal` adds a node on the retiring PostgreSQL controller, moves both nodes to the survivor, and submits a retained-node request built from fresh real inspections after reservation; it uses the tree's package too. All five skip without `BILLET_REHEARSAL_APP_CONFIG` and `BILLET_REHEARSAL_APP_KEY`, because a control plane cannot start without GitHub and nothing honest stands in for it; nothing runs them on a schedule (`rehearsals.yml` was removed on 2026-09-25 with the test organization's App), so they are run by hand before a release that touches what they drive. The architecture is the docker daemon's, not `uname -m`'s, so they run on a Mac's Docker Desktop too. Three rules the first review round wrote down: a registration is proved by the server journal's `node registered node=<name>` line after a clock mark taken before the boundary, never by the name appearing in `billet status`, which prints every node the ledger knows whether or not one has connected; a negative assertion captures the producer's exit status and greps a here-string, because `cmd | grep -q` under `pipefail` and `|| true` both turn "could not tell" into the absence being asserted; and a teardown that fails fails the run, since a green rehearsal that left a scale set behind hides the one thing an operator has to act on. Results go in `docs/reference/records/host-rehearsals.md`.
