# Testing billet

## What this area is

billet's suite is 450-odd `_test.go` files across unit tests, structural tests that parse Go source, cross-package integration tests in `internal/integration`, the end-to-end suite in `internal/e2e` (a real control plane, real node wire and real container runtime against `internal/fakeactions`), `real*_test.go` files that assert billet's model against a real tart, docker, firecracker, CodeBuild, S3 or launchd, and opt-in live tests that spend money. `make test` runs the ordinary suite with `-race -count=1 -covermode=atomic`; CI adds a real PostgreSQL and a second `internal/alloc` run with `BILLET_TEST_LEDGER=postgres`.

## Rules

**A test must fail when the code is wrong, and the way to know is to break the code once.** Two of the original state tests passed regardless: one read `journal_mode` through the reader pool, where SQLite reports the file's persistent value whatever the writer configured; the other exercised the single-connection writer pool and called the result serialization. Before submitting a test for an invariant, neuter the production line it names (comment out the `syscall.Flock` in `internal/state/lock_unix.go`, run `TestSecondOpenIsRefused`, watch it fail, restore) and confirm the test goes red. A test whose mutation survives must be shown redundant, out loud, or fixed.

**A mutation harness must prove it changed the file, and a mutant must change behaviour.** Verify by hash, not by grepping for text that may already be absent: a substitution that matches nothing reports SURVIVED, which is indistinguishable from a vacuous test. A mutant that applies but changes nothing (an `_ = id` beside a `delete`) also reports SURVIVED; if you cannot name the assertion it should break, it is not a mutant. A mutant that does not compile is caught by the compiler and reads as a pass until the failing-test count says zero. `make no-mutants` runs first in `check` because an interrupted run leaves the original holding the mutant.

**Assert the diagnostic, not the shape.** Counting error lines stays green when the six errors are the wrong six. `installation_id is required; creating an App does not install it` exists because the failure is otherwise baffling, so the test asserts the clause. A test satisfied by "an error came back" cannot tell a refusal from a panic: deleting the guard that checks a request carries a client certificate made the handler dereference a nil `r.TLS`, the client saw an error, and `err != nil` passed. Assert the sentinel or the status.

**A discarded error is a vacuous assertion waiting to happen.** `n, _ := a.Headroom(ctx, "x"); if n != 0` passes when the call fails, because these APIs return the zero value beside an error; it bit seven times. Comma-ok is the same trap: `v, _ := m["k"].(T)` yields zero for an absent key. `errcheck` is enabled on tests for this reason (19 sites, two real bugs). Ask, for anything the linter cannot see: if this call errored, would my assertion still pass?

**Prove the mechanism is used, not only that it works.** Five instances in one day: `printAdmission` rendered a seal and nothing proved `billet status` called it; a fake converger carried its own copy of `StopAndProve`'s refusal so deleting the production one left the test green; `TidyStagedRegistration` had only test callers while its doc comment named a production one. Drive the caller, not the helper. A fake must return what it is told and judge nothing. Where the call site cannot be reached from a unit test, assert it structurally with `go/ast` (below).

**The test written to prove a fix tends to prove the adjacent thing.** Four rounds on the deployment lock: a gid comparison proved `20 == 20` because a temp dir is owned by the primary group; setgid was set before the file existed so the kernel supplied the gid; an `O_NOFOLLOW` test proved `os.Root` refuses an escape rather than a symlink; a "second process is refused" test ran both opens in one process, which a package mutex satisfies. The real one re-executes the binary (`internal/state/deploymentlock_process_test.go`), which is also the only way to prove SIGKILL frees the lock.

**When a platform behaviour matters, write a throwaway probe and run it where the code runs.** `os.Root` and symlinks, umask stripping mode bits, BSD versus Linux gid inheritance, `os.UserCacheDir` reading the environment: three defects were documented behaviour that read the other way. A probe on the development Mac is not evidence about the Linux builder (see `billet-shell-gates` for the four ways one lied); run it in `ubuntu:24.04`.

**Silence looks like success, and each silence has a guard.** A scripted substitution that matched nothing (assert `old in s` and check the hash changed); a mutant that changed nothing (name the assertion it breaks); a review prompt file that did not exist (refuse to launch without one); a scripted edit that deleted a whole test (`make tests-kept`); a killed mutation run that left its mutant in place (`make no-mutants`). The thing that would have objected was itself missing. And pass commit messages with `-F`: backticks in `git commit -m` are command substitution.

**Conventions.** `t.Context()` and `t.TempDir()` (enforced by `usetesting`), `t.Cleanup` for teardown so it runs on the `t.Fatal` path, table tests for pure functions and named tests for invariants so a failure names the invariant. Open the state store with `Open(t.Context(), t.TempDir())`; there is no shared helper, because a fresh directory per test is what makes the process lock and the pragma verification run for real.

**`t.Parallel()` turns on the sharing, not the disk.** `paralleltest` is disabled as a default rather than a ban, and 37 directories use parallel tests. A test with resources of its own (a `t.TempDir`, its own database, an `httptest` port) parallelises happily. What must run alone is a test sharing process-global state: one SQLite file two tests open, a fixed port, a daemon, the environment (`t.Setenv` refuses in a parallel test), or a package variable one of them mutates. The `parallelshared` analyzer reports the last case. Match the file you are adding to.

**Concurrency tests use the scheduler under test.** A race whose window is nanoseconds is not tested by two goroutines and a `WaitGroup`: the fake delays inside the operation, holding both callers in the transition. A wait that something else already satisfied is not a wait (count from a baseline taken before the thing under test exists). One timeout knob must never serve a deadline that must expire and deadlines that must not; compare the deadlines the code handed out instead (`context.WithTimeout` on a bounded parent keeps the parent's deadline, so an inherited context compares exactly equal). A clean `-race` run is evidence, not proof: it sees only the interleavings that occurred. A test whose observation shutdown can also produce (a destroy that `releaseAll` performs anyway) proves nothing about the loop.

**A stand-in must stay alive and be observable.** `sleep --id <id> 30` exits immediately on real coreutils; put the marker in `$0` via `sh -c <script> <name>` and poll `/proc` until the process is there, so "not appeared yet" and "exited" stop being the same observation. An image that exits at once (busybox) makes adoption untestable; the e2e suite uses one that keeps running. A fake that ignores `ctx.Err()` cannot distinguish cleanup on a cancelled context from cleanup on a fresh one. A queue that pops on read cannot model redelivery; hold the head until its exact id is acked.

**Structural tests assert order and call graphs where a unit test cannot reach the call site.** They parse source with `go/ast`: `TestEverythingAuthoritativeHappensAfterTheControllerClaim` and `TestTheAuthorityIsAdoptedBeforeTheWireAndPublishedAfterIt` (`cmd/billet/promotionorder_test.go`), `TestOnlyTheForceOperationDestroysRunningWork` (`internal/server/forcecallers_test.go`), `TestAHealthyUpgradeRunsInOrder` and its siblings (`internal/hostupgrade/upgrade_test.go`), `TestANoOpUpgradeRecordsTheDecisionBeforeAcceptingIt` (`cmd/billet/upgradefence_test.go`), the query-set tests in `internal/state/queryset_test.go`, `internal/rollout/dispatchguard_test.go`, `internal/node/reap_test.go`, `cmd/billet/preservedpaths_test.go`, `scripts/onelinerblock_test.go`. Use one when the failure mode is a step moving rather than a property changing.

**The end-to-end suite assembles billet the way `cmd/billet` does.** `internal/e2e` goes through `internal/wiring`; the hand-copied adapter it began with had already drifted (it dereferenced a scale set the client returns as nil). `internal/fakeactions` answers the handshake and serves what a test tells it to; it is deliberately not a simulator of GitHub, has no production callers and must acquire none. It exists because the worst defect in the project (`AcquireJobs` called with ids from `JobAssigned` instead of `JobAvailable`) lived in the relationship between billet and the wire, where billet's types agreed with billet's mistake. The one thing steered there is the allocator's clock, through `alloc.WithClock`. A stack can run over another backend through `withBackend(kind, build)`; the simulated one (`internal/provider/simulated`, `internal/e2e/simulated_test.go`) needs no docker daemon, so its scenarios run wherever the tests do, and it steers the provider's clock rather than the ledger's, because jumping the ledger past the lease TTL while heartbeats arrive on wall time would measure the reaper. Every scenario that is about the plane and the wire rather than about docker (lifecycle, wire, multiday, compute barrier, restart) runs through `forEachBackend`, once on docker and once on the simulated backend over one shared `simulated.Host` per leg, so a restarted stack (`sameBackend`) re-adopts what the previous process launched and a second deployment is on the same machine; the docker leg skips without a daemon and the simulated leg never does. A scenario stays docker-only when its subject is docker itself: the generated docker config launch.

**The replay harness drives a workload through the real scheduler at compressed time, and steers exactly two things.** `internal/replay` takes a trace of arrivals (tier, repository, workflow, duration; synthetic from `MorningBurst`, `MonorepoFanOut` and `LongTail`, or exported from a repository's Actions history by `scripts/export-actions-trace.sh`) and drives it through a scripted Actions service into the real listener, allocator, placer, node wire and node runtime over `internal/provider/simulated`, then reads every job back from `job_history` and joins it to the trace on the request id; a job the ledger has no row for is reported as missing, never filled in. What is steered: one virtual `Clock` that the allocator and every simulated provider read (the plane, the heartbeat and the node loops stay on wall time, because a plane on the simulated clock would expire a node parked across a jump of hours), and the order in which tiers open their sessions and contest freed room (fixed to the fleet's tier order, since escrow is placement and goroutine order would otherwise decide where a tier's first job lands). The reaper never ticks, for the multi-day scenario's reason. Determinism comes from delivering one event at a time to quiescence, where quiescence means every listener is parked on an empty queue with its advertisement unchanged since its last poll, because the listener hands surplus escrow back only after a poll carrying the smaller number has returned. The four proofs that must stay green: two replays of one trace place and date every job identically; pack and spread leave different footprints; the ledger's own intervals never overcommit a host or the deployment (dropping the host term from `placer.roomFor` fails it); and every trace job has a ledger row (swallowing one completion fails it). The suite replays three hundred jobs by default; `BILLET_REPLAY_JOBS=2000` is the acceptance-size run, about a minute and a half on a laptop without the race detector and too slow for CI's shared race-instrumented test job, so CI runs it in its own `replay` job without `-race`; `-replay.out DIR` keeps each run's records and summary. The record's provider, charged shape, site, price and cache observations are the history row's own columns (migration 49, read through `ReadJobPlacement`); cost is derived from the recorded price or, for a host-backed lease that records none, from the fleet's per-host rate and labelled `fleet-rate`; locality is derived from placement and named as such, because a simulated guest observes nothing about the cache. It has no production importer, proved by the same importer walk `internal/importcheck` runs for `fakeactions` and the simulated backend.

**Generated shell is executed, never pattern-matched.** `scripts/` holds thirty-odd Go test files that run the build scripts against fixtures; `internal/provider/codebuild/buildspec_test.go` parses the buildspec and runs its commands under `/bin/sh`; the EC2 boot script is run with the runner command replaced by one that prints what it would have read.

**Real and live tests skip without their resource and never spend money by accident.** `real*_test.go` files assert that what billet says matches what the real system does, because the firecracker backend's two launch-killing defects survived every unit test and died on the first real run. Gates: `realdocker_test.go` needs `docker` on PATH; `realtart_test.go` needs `tart` (each test gets its own `TART_HOME`); `realguest_test.go` needs `BILLET_TART_GUEST_TESTS=1` (`BILLET_TART_GUEST_IMAGE`, `BILLET_TART_SOFTNET_TESTS=1`, `BILLET_TART_XCODE_TESTS=1` widen it); `realfirecracker_test.go` needs root plus `BILLET_TEST_GOLDEN_IMAGE`, `BILLET_TEST_BRIDGE`, `BILLET_TEST_KERNEL`, `BILLET_TEST_CACHE_POOL`, `BILLET_TEST_IMAGE_POOL`, `BILLET_TEST_CEPH_USER`; `realcodebuild_test.go` and `holdergone_live_test.go` need `BILLET_TEST_CODEBUILD_PROJECT` and AWS credentials; `realwalk_test.go` adds `BILLET_TEST_CODEBUILD_WALK=1` and records rather than asserts; the two `reals3_test.go` files (`internal/provider/ec2` for a presigned URL, `internal/awss3` for the two codes a 404 carries) need `BILLET_S3_TEST_BUCKET` and `BILLET_S3_TEST_REGION`; `internal/provider/ec2/live_test.go` needs `BILLET_LIVE_EC2_REGION` and friends; `reallaunchd_test.go` needs the macOS `launchctl`, and each test derives its own label because a launchd agent is not gone when its test ends. `cmd/billet/codebuildchecklive_test.go` is named live but drives a fake endpoint; it exists because a structural test proves a judgement is called and not that its result reaches the output.

**PostgreSQL is tested against a real server or not at all.** `BILLET_TEST_POSTGRES_DSN` gates `internal/state` and `internal/alloc`; `cmd/billet/localbackup_test.go` fails rather than skips when `CI` is set and the DSN is missing. CI runs `postgres:18-alpine` as a service and then re-runs only `./internal/alloc/` with `BILLET_TEST_LEDGER=postgres`, without `-race`.

**Coverage is a signal, not a goal.** `.codecov.yml`: project target `auto` (no regression from base, 1% threshold), patch target 80% (5% threshold), and only `cmd/billet/main.go` ignored, which is why nothing carrying real semantics may live in that file. A hard 85% on a project at 79% fails every PR and is learned to be ignored.

## Measured facts

- Discarded-error vacuity: seven instances (five in `internal/alloc`, two in `internal/github`).
- `errcheck` on tests: 19 sites, two real bugs.
- The onboarding fake's concurrent slice read survived six clean `-race` runs.
- A 700ms mutex stall against a 300ms TTL reproduced `TestACancellationInsideTheLongPollStillDrains`'s CI failure exactly, and only under the old heartbeat ordering (`Listener.heartbeatLock` is the seam).
- `TestImportGenerationConfirmsRemovalAfterCallerAndRemovalDeadlinesExpire` set one 20ms knob for two opposite purposes and produced two distinct CI failures under a 30ms stall.
- Test build tags: exactly one (`//go:build unix`) across the suite.

**The host rehearsals run the real commands on packaged hosts under real systemd, and each needs a real App.** `scripts/rehearsal-lib.sh` starts privileged `ubuntu:24.04` containers with systemd as PID 1 (the shape `scripts/test-systemd-lifecycle.sh` measured), installs a `.deb`, issues certificates as the service account and asserts on unit state, journals and files, never on an exit code alone. `make rollout-rehearsal` moves two hosts from one PUBLISHED release to the next by `billet rollout start` alone and rolls a downgrade candidate back (`BILLET_REHEARSAL_FROM`/`_TO`); `recover-rehearsal`, `ca-rotation-rehearsal` (twenty-minute leaves through `billet ca issue --lifetime`) and `promotion-rehearsal` (a PostgreSQL pair partitioned with `docker network disconnect`, keepalives set on the server) use the tree's own package from `make dist`. All four skip without `BILLET_REHEARSAL_APP_CONFIG` and `BILLET_REHEARSAL_APP_KEY`, because a control plane cannot start without GitHub and nothing honest stands in for it; `.github/workflows/rehearsals.yml` runs them weekly with the acceptance App and never on `pull_request`. The architecture is the docker daemon's, not `uname -m`'s, so they run on a Mac's Docker Desktop too. Three rules the first review round wrote down: a registration is proved by the server journal's `node registered node=<name>` line after a clock mark taken before the boundary, never by the name appearing in `billet status`, which prints every node the ledger knows whether or not one has connected; a negative assertion captures the producer's exit status and greps a here-string, because `cmd | grep -q` under `pipefail` and `|| true` both turn "could not tell" into the absence being asserted; and a teardown that fails fails the run, since a green rehearsal that left a scale set behind hides the one thing an operator has to act on. Results go in `docs/reference/records/host-rehearsals.md`.

## Where the tests are

- `internal/state/*_test.go`: single writer, pragmas on the writer connection, reader cannot write, migration checksums, forward compatibility, schema CHECK constraints.
- `internal/config/*_test.go`: build cases by `strings.Replace` on a known-good config; cover both directions of every guard.
- `internal/integration`: config boundary, generated tier over the wire, release boundary, live session replacement, real Ceph into firecracker capacity.
- `internal/e2e`: lifecycle, wire, enroll, revocation, restart, restore, compute barrier, holder-gone, multiday, codebuild, ec2, init launch.
