# Leases: the state machine, the fence and renewal

Part of the `billet-capacity` skill. Each rule is stated in full, with the measurement or incident behind it.

**The lease state machine is written down and terminal phases have no successors.** `capacity → assigned → launching → online → busy`, with `custody`, `teardown` and `quarantine` as holding states and `done`/`failed` terminal; `quarantine` exits only to a terminal. `requiresPlacement` (launching, online, busy) refuses to enter a running phase without a bound, still-legal placement, re-checked against policy in force then; `hadCompute` decides whether an expired lease is failed outright or quarantined. A row whose placement facts are unverifiable fails closed, and `Reap` and `Release` deliberately skip those checks so it can always be cleaned up.

**A remote lease is charged for the shape, not the tier request.** A node registers its ordered shapes; placement picks the first that fits and stores both the requested resources and the charged shape. A fallback is a new purchase decision authorised atomically against node and deployment ceilings before the request is sent. The predicate is `RunsOnHost`, not `== ec2`; a third remote backend added without touching that line would be charged the smaller tier request while buying the shape. The shape's price (`leases.price_micros_per_hour`) and the placed host's site are written on the lease when the shape is charged, at escrow and again on a resize, and `archive` copies them with the provider, the shape and the charged vector onto `job_history` (migration 49); the price is never re-read from the node's catalogue, because `sameEC2PlacementShapes` ignores price and a node may re-register with new rates while the lease is open. `ListExpiredLeases` selects `chosen_provider` because the reaper archives from that projection; before it did, every reaped lease was archived as having run on nothing.

**The epoch is a fence and a reclaim bumps it.** Every lease write presents its epoch and a stale one is refused with `ErrFenced`, or a holder declared dead keeps writing to a lease somebody else owns. A registration bumps the node's epoch; the process's incarnation is separate (a restart re-registers with a new epoch and the same process registers again after every control-plane restart), which is why `leases.holder_incarnation` records the incarnation of the process holding compute and never the epoch.

**A heartbeat pass's budget starts after it holds the mutex.** Created at the tick, the deadline is spent waiting for billet's own lock, the pass reaches the allocator already expired, and `renew` reads its own silence as the allocator's; past the TTL that is `renewalStale`, which tears down a healthy job. Measured: a 700ms stall against a 300ms TTL reproduced a CI failure exactly. `Listener.heartbeatLock` is the seam a test stands in. Heartbeats are never bounded by the poll (the first real poll ran 88 seconds against a 90-second TTL), the cadence derives from the allocator's actual TTL rather than `DefaultLeaseTTL` (measured at six times the budget otherwise), and `assign` holds the mutex across the ledger write. A transient heartbeat error keeps the lease; only `ErrFenced` and `ErrLeaseNotFound` mean it is somebody else's.

**Exactly one party renews a lease, and every defect here was a moment when that count was zero.** Three handovers: the node renews from the moment it commits to launching, because the plane gives up at the command timeout while the provider is still working; the plane records a tombstone for every launch it abandons so a late success is told "this lease is yours" rather than filed unrenewed; and `settle` drains the result channel under the plane mutex so a result racing the timeout is answered exactly. A listener holds no compute, so on `ErrHolderUnavailable` it parks the obligation without the lease (`parkUnreachable`); renewing a lease it could not reach the holder of built a loop with no exit, measured against real CodeBuild.

**An inventory that shrinks is capacity that gets resold.** A provider's `List` must error rather than answer short, because reconciliation frees every lease absent from it. Ask what makes a row appear in the inventory, then what could make that stop being true while the compute keeps running (a chroot named after a resolved binary an operator can retarget, a teardown that removed the pid file it needed, an identity mismatch collapsed into "not running").

**billet attributes a lost job, and re-runs one only for a tier that asks and only on GitHub's proof of a lost runner.** `retry.disrupted` is 0 by default, and ADR-029 is the decision: a disruption from the closed `alloc.RerunCauses` (`reclaimed` and `guest-absent`: `node-forgotten` is not one, since a partitioned host goes on running the job, and `held-past-limit` is not, since a custody bound is an operator's choice a hung job would meet again) on a job that ended after its tier started asking (`rerun_tiers`), and GitHub's record of a lost runner (`AttemptJob.RunnerLost`, from a record whose every field it reads is present), decided per run by `server.rerunDisrupted`, a background loop that cannot stop a tier; one request per attempt by the key of `job_reruns`, written `asking` before it leaves, settled by a 201 or, for any other answer, by reading the run, or `unconfirmed` and counted when the run cannot be read in time, never by asking again while it may have landed, and settled on its own whatever became of its jobs. `leases.disruption` is a token from a closed set written in the transaction that observed the disruption (`NodeGone`, `ResolveQuarantineFor`, `MarkFailure`), never reconstructed at completion, because `ForgetEveryNode` sets `live = 0` fleet-wide at every start and a later verdict would blame every host. `job_history.result` is GitHub's word. `billet leases failures` shows both side by side and says the pairing is circumstantial. `disruptionGuard` keeps the first observation and refuses a lease that already carries a result. The token is decided by the exact reason and by `job_history.started_at` before the reason's text, so a node cannot suppress it for a job the ledger saw start; `force-released` is refused over the wire.

**A job GitHub stopped offering is found on GitHub's word and billet's own record, never on a timer alone, and decided once (#911).** On 2026-11-20 a consumer's job whose launch started nothing was assigned, cancelled unrun twice, and never offered again, and the run sat queued with its tier advertising capacity and waiting for nothing. A launch that started nothing keeps its job's identity on its `job_history` row (`failure_reason = 'billet:launch-failed'`), and `server.findStranded`, on the re-run loop's pass and within its own two reads per installation, asks about each one 15 minutes after its lease ended: `stranded` only when GitHub's REST record of the run still has a job of that name queued with no runner and none taken, while admission was unsealed and the tier's own report, under ten minutes old, advertised more than 0 and waited for nothing, and the tier has been assigned nothing for the run since its lease ended that is, or may be, a job of that name (another job of the same run says nothing about this one, and an assignment whose row has no job name yet, because a row learns it only when its job starts, ends or its launch fails, may be this job offered again, so it holds the decision); `offered` when the run is over, a job of the name was taken, or the tier was assigned a job of the name again; `expired` for a row naming too little to ask about or a day old. Every other answer, a failed read included, is could-not-tell and asked again on a later pass, no sooner than ten minutes after, and the launches due are asked least recently asked first, so two that never decide cannot keep a third unread (Codex measured 21 undecided rows starving the last for a day under oldest-first). A read is bounded to the run and four pages of jobs, five requests, and a job record without a name is could-not-tell. What the ledger said before the read is said again in the write of a `stranded` decision (`DecideJobStranded`), because an assignment recorded while GitHub was being read may be the job offered again. Each pass lists one page of 200 from where the last ended, and from the start again once a page reaches the launches too young to ask about or the end, so older launches that never decide cannot keep a younger one from being listed. An assignment whose job is never named (one whose process died before its job started, say) holds every launch of its run on the tier undecided until it expires: could-not-tell, and stated as such. The row's `job_name` comes from the scale-set message and is matched against the REST record's `jobs[].name`; measured equal on 2026-11-22 for every job billet ran in two runs, billet's own CI run 45007092814 (46 of 46, the matrix names such as `host-lifecycle (endpoint)` included) and the consumer's run of 2026-11-20 (10 of 10, `Lint App` included). A job of a reusable workflow, which REST names `caller / job`, was in neither and is unmeasured: if the two differ there, the read finds no job of the name, which is could-not-tell, and the launch expires undecided rather than being misjudged. The detector rides the re-run loop, which runs whether or not a tier asks for re-runs (`TestAPassWithNoTierAskingForReRunsStillFindsIt`); a throttle or a refusal pauses the installation as a re-run's read does. The decision is written once (`DecideStranded` updates only `stranded = ''`), and a `stranded` decision logs an ERROR with the run's URL and asks for nothing unless its tier sets `retry.stranded` (below).

**A stranded job is recovered only for a tier that asks, by a cancel that ends nothing running and a re-run sent only once that very attempt is over, once per run, with the ledger between the two.** `retry.stranded` is false by default, and turning it on needs the App's `actions: write`; ADR-029's amendment is the decision.

- **Where it runs.** `server.recoverStranded` rides the same pass as the detector, with a share of two reads per installation of its own.
- **Gating.** It takes a stranded launch only of a tier that asks and only if the launch ended after the tier started asking (`stranded_tiers`, as `rerun_tiers` is for re-runs). Turning the option on never cancels an older run.
- **Before the cancel,** it re-reads the ledger (no assignment since that is, or may be, the job) and GitHub's whole latest attempt (`QueuedAttempt`). It cancels only when the job of that name is queued with no runner and every job of the attempt is queued with no runner or over. A job listed against another attempt is could-not-tell. The ledger is asked again in the transaction that authorises every cancel, the first and each sent again (`alloc.ErrMayBeOffered`), from the launch's end kept on the row (`ended_at`), because an assignment recorded while GitHub was being read may be the job offered again; Codex reproduced the cancel without it.
- **The row.** `stranded_recoveries` (migration 85) is written `cancelling` before the cancel leaves. It moves to `rerunning` only when GitHub records that very attempt completed, and the re-run is sent then. Every move is from the state the row was read in, so a restart between the two requests neither cancels twice nor leaves the run cancelled. A recovery under way is taken on whether or not its tier still asks.
- **A cancel still in progress a pass later** did not land; a landed one completes the run in 3.5 s (measured 2026-11-22). It is sent again only while the run is still safe to cancel, otherwise the recovery is `superseded`, and three sends end it `failed`.
- **A re-run** is settled `recovered` by GitHub's 201, by the run going on the same attempt, or by a later attempt. A later attempt before billet's re-run is a person's: `superseded`, and left alone.
- **A recovery older than a day** is `expired`. One that cancelled and could not re-run is an ERROR with the run's URL.
- **Once per run, guarded twice.** A run is recovered once on any attempt: `ListStrandedToRecover` leaves out a run with a recovery, and `BeginStrandedRecovery`'s insert refuses one on its own. The list holds only what a tier asking may take (a join on `stranded_tiers`) and is read a page a pass from a cursor that goes round; recoveries under way and candidates are taken least recently read first, so neither unreadable runs nor launches that stay unsafe to cancel keep another waiting (each measured by Codex before the fix).

**A reserved fleet's claim is released by a proof.** Two nodes naming one CodeBuild fleet each register its whole capacity. Refusing a second claimant while the holder was `live` was wrong (liveness says nothing about remote compute), and while it was not decommissioned was wrong (`--force` is not a proof). What releases it is `decommission_proven = 1`, which the drain's compute barrier writes. Permission to hand over shared capacity comes from what is proved, never from what is broken.
