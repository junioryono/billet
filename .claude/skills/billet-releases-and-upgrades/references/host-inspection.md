# Host inspection and endpoint moves

Part of the `billet-releases-and-upgrades` skill. Each rule is stated in full, with the measurement or incident behind it.

**`billet release inspect --json` is the host's own account of what it runs, and every field is a value or an explicit unknown with a reason.** It is what a converge that follows the fleet's installed release reads before it selects a collection, so it must never guess and must never change the host: it opens no ledger, mints no identity and creates no file, and the one lock it touches is the upgrade transaction's, tried non-blocking through a read-only descriptor and released at once to answer `lock_held`. Every hash is of a descriptor opened by a link path (`/proc/self/exe`, `/proc/<pid>/exe`; `os.Executable` returns a pathname, and a pathname opened after a replacement is the replacement) or by the file's path, and is BRACKETED BY THAT DESCRIPTOR'S OWN METADATA: a stat before and after the read that disagree in size or mtime are could-not-tell, a write after the second stat is outside the observation, and equal metadata is not proof the bytes never changed. A running service is ONE SAMPLE bound to one incarnation: the start time (`/proc/<pid>/stat` field 22, a zombie or dead state refusing, because a zombie keeps its start time) before, then the image, the command line, the environment and the process's own view of its `--config` path opened under `/proc/<pid>/root` with root-scoped resolution (`openat2` with `RESOLVE_IN_ROOT` and `RESOLVE_NO_MAGICLINKS`; a plain open of the joined path would resolve an absolute symlink against the inspector's root and open the inspector's own file), then systemd's `MainPID`, `InvocationID`, exec-shaping properties, remapping directives and the structured ExecStart records read again and required equal (a reload that adds a bind mount or moves an argument boundary behind an unchanged rendering discards the sample), then the start time again after that systemd read, so a restart, a pid reuse or a unit edited under the sample is could-not-tell rather than image evidence attributed to a process the other reads saw; on darwin there is no process-bound image and the report says the hash is path evidence. The provenance verdict (`proved`, `none`, `contradiction`, `unreadable`) is computed the way `provenance.Installed` computes it from one read of the record and that hash. ONE CONFIGURATION BINDS THE REPORT, AND IT IS ONE OBSERVATION: the file is read once through one descriptor, bracketed, those bytes are parsed and their digest is `installed_config.sha256`, that descriptor's identity is what every process's view is compared with, a service whose view is that file publishes the observation's digest rather than a second open of the pathname, and at the end of the report the descriptor is re-checked by its own metadata and the name by identity and metadata (`config.same_as_installed`: a rewrite in place STILL PRESENT at the closing checks withdraws a true binding, the observation's digest and every service field copied from it; a replacement by rename STILL PRESENT at the closing name check makes the binding false; a replacement or rewrite undone before those checks is outside what they observe, and a write after them likewise); `config.presence` is the typed answer `present`, `absent`, `malformed` or `unreadable`, so a consumer never reads a failed read as absence (an ENOENT through a dangling symlink is absence of the resolved configuration, not of the directory entry); each unit's `unit_file_state` is systemd's literal answer and `enabled` is derived from it, true for `enabled` and `enabled-runtime`, false for every other state systemd defines and unknown outside that set; false means a recognised state other than those two and NOT "positively disabled" (`static`, `alias`, `indirect` and `generated` units can still be started by something else), so a consumer that needs a particular state reads the literal against its own accepted set, and one is never handed an empty answer as either; a service that names another configuration than the inspector's publishes the digest and mtime verdict of ITS OWN VIEW of that path, read through its root in the sample, never the inspector's file at that name, while a service naming the inspector's path has its view opened for identity alone; ONLY THE SUPPORTED COMMAND LINE IS FOLLOWED INTO THE FILESYSTEM, the one predicate the sample and the report share, and `/proc/<pid>/cmdline` is decoded losslessly (one terminator off, every empty argument kept, because trimming every trailing NUL turns a five-argument command line into the supported four), so an unsupported process's fourth argument is never opened, whatever it names; the view is an `O_PATH` descriptor on Linux (no read, no wait on a FIFO, no device open), reopened for reading on the same inode through `/proc/self/fd` only for a regular file (by duplication off Linux, where only the fixtures run a view), so a special file at the inspector's path makes the binding false with the content evidence unknown, and one at another path is could-not-tell; EVERY PATHNAME THE COMMAND READS DIRECTLY goes through `regularfile.Open` (`internal/regularfile`, the one identity-first open: `O_PATH`, fstat, fstatfs refusing an enumerated kernel pseudo-filesystem (configfs included, whose attributes dispatch reads to a subsystem), and a NON-BLOCKING reopen through `/proc/self/fd` on Linux, so a device is never opened, `/proc/kmsg` is never read and a write lease answers EWOULDBLOCK (its holder is still signalled and the lease marked for downgrade: the wait is avoided, not the break); a non-blocking open and fstat elsewhere, where a device is opened and then refused and the package says so; a reopen that fails is `ErrReopen` with the cause quoted, never `fs.ErrNotExist`, so a missing `/proc/self/fd` cannot read as an unheld lock or a missing record; `ReadFile` refuses a file over its limit rather than cutting it), for its configuration, the transaction lock with `NoFollow`, an environment file systemd names, `guard.json`, the recorded release executable, darwin's managed binary and every `readPublicFile` read, each whole-file read and every hash bounded by its purpose and refused rather than cut past the bound, and the readers it delegates to (`provenance.Read`, `state.PeekDeploymentID`, `hostupgrade.ReadJournal`, `wirecert.SnapshotAuthority`) read through the same package with their own size limits, because a plain open of a FIFO blocks before any stat and nothing else in the report bounds it, so a special file at any of them is could-not-tell with the reason, never a wait; the source scan holds the direct `os` calls of `releaseinspect.go` and its platform files to a listed set and says that syscalls and the delegated readers are outside it, which the FIFO cases prove behaviourally; identity, authority and the DSN come from the inspector's `--config`, made absolute, and `config_binding` is true only when every present unit's LOADED `ExecStart`, read as structured records from the bus property (`busctl --json=short get-property … org.freedesktop.systemd1.Service ExecStart`, `a(sasbttttuii)`, where argument boundaries survive; `systemctl show` joins argv with spaces and `systemctl cat` shows text the manager may not have loaded) is one record whose argv is exactly `<managed path> <role> --config <that absolute path>`, and every running process's own four-argument command line names that absolute path AND the file its own root resolves that path to is the inspector's file by identity (a bind mount removed from the unit and reloaded without a restart leaves the process in the namespace it started in, where the same path is another file, and the root's name reads `/` in both); false beats unknown beats true; a unit whose fragment is gone binds trivially only when positively inactive with no main process. The process's command line and view, not the unit file, bind a process, because a unit edited and reloaded without a restart names a path the process never read; the config file's mtime after the start is refusal evidence only and `loaded_config` is always unknown, because nothing on the disk proves what a process loaded. The supported unit `shape` is exactly what billet ships: one loaded record, argv `<managed path> <role> --config <absolute path>`, path the managed path, the rendered view equal to the argv joined by spaces, no filesystem-remapping directive (`RootDirectory`, `RootImage`, `BindPaths`, `BindReadOnlyPaths`, `MountImages`, `ExtensionImages`, `ExtensionDirectories`, `TemporaryFileSystem`: under those an absolute path names another file while the root still reads `/`, a configuration extension overlaying `/etc` included), at most one `EnvironmentFile` (the package has none, the role's template adds one; every `EnvironmentFiles` property line is read with exactly the ` (ignore_errors=yes|no)` suffix stripped and the whole path kept, because a path can itself contain ` (`), no `Environment=`; a wrapper, an expansion, a quoted multi-word argument, a relative path or a second record is could-not-tell, and a drop-in that loads as the supported shape passes, because the loaded records are what is judged. `NeedDaemonReload` IS REPORTED AS A FACT (`need_daemon_reload`) AND IS NOT PART OF THE SHAPE, because on systemd 255 it answers yes when this unit's fragment, source or drop-ins changed since load OR when the manager's flag `unit_file_state_outdated` is set, and the second cause dominates in practice: the flag is set by any bus unit-file operation that changed something (`EnableUnitFiles`, `DisableUnitFiles`, `PresetUnitFiles`, `MaskUnitFiles`, `LinkUnitFiles`, `RevertUnitFiles`, `AddDependencyUnitFiles`, so every `systemctl enable` a snap refresh, a package or the role itself performs) and cleared only by `daemon-reload`, and while it is set EVERY unit answers yes whatever its own file's state; measured on the reference controller on 2026-09-07 (systemd 255.4): 464 of 464 units after snapd enabled a new mount unit, billet's unit files unchanged since the last reload. `UnitsLoadFinishTimestamp` is the boot-time load and is not moved by a reload, so there is no manager property that dates the last reload. The loaded records are what systemd runs either way, so the flag decides nothing here; the host role's dry-run refusal reads the same flag and is the place a pending reload is acted on. On PostgreSQL the DSN variable is compared with the unit's one environment file INSIDE the process, the whole file validated first as bytes (valid UTF-8, LF only, no control character but LF and TAB, because systemd reads a carriage return as a newline and one inside a comment would hide an assignment, and no Unicode noncharacter, which systemd's stricter UTF-8 rule refuses and Go's `utf8.Valid` accepts) and then against the restricted `NAME=value` grammar the role's template writes (a name assigned twice, whitespace systemd would trim, a quote or backslash or hash in an unquoted value, an `export` are unsupported syntax and could-not-tell), and only `equal`, `differs`, `not_in_file` or `absent` leaves it. `installed_config` says which roles, which ledger backend and which controller mode the configuration declares, and carries the file's digest, bracketed like every hash and needing no running process. The deployment identity is `state.PeekDeploymentID`, never `DeploymentID`, which mints; the authority is `wirecert.SnapshotAuthority`, confirming reads and no lock; a node's bundle is read through the public-read seam without its key, and the PEM the report publishes is re-encoded from the validated DER, never the file's bytes. The claim under the upgrade root is classified by `Lstat` (`none`, `host-upgrade` for a symlink dangling or not, `legacy-role` for a regular file, `converge-guard` for a directory holding `guard.json`, `unpublished-guard` for one without) and the transaction lock is tried through a read-only descriptor and released at once. `internal/ops/host/releaseinspect_test.go` pins the JSON field set exactly, so a rename under schema 1 is a failed test; holds every direct filesystem call in the inspector to a listed few, so a read beside the observed seams is a failed test too; and its fake `systemctl` answers only the properties asked for. THE NODE'S REGISTRATION RECORD is the inspector's evidence of what the running process dials: `internal/nodeclient/record.go` writes `/run/billet/registration/current` (seven members: `schema` 1, `node`, `deployment`, `incarnation`, `invocation_id`, `endpoint` as `internal/endpoint`'s canonical text of the client's request base, `registered_at`) through the zero-value `durablefile.Installer` after EVERY accepted registration and never before one, a drain's re-registration included, a failure logged on every registration that fails to record with the node kept serving and nothing retried without another registration; the path is `nodeRegistrationRecordPath(hostOS)`, one spelling, empty on darwin; the node unit's `RuntimeDirectory=billet/locks billet/registration` (packaged and templated, the server declaring none, because systemd re-owns a declared directory recursively at a start where its owner differs and removes it at that unit's stop, measured on systemd 255, 2026-09-09) is what makes `/run/billet/registration` writable under `ProtectSystem=strict` and empty at every node start. `internal/ops/host/releaseinspectregistration.go` reads it INSIDE the node's process sample (between the identity reads, so a record is never reported beside evidence of another incarnation), through `regularfile.Open` with `NoFollow`, judged on the admitted descriptor's fstat (root-owned, 0600, at most 4 KiB), decoded under the exact member set by name, and reports `host.registration` as known only when the record's invocation is the node unit's sampled `InvocationID`, its node and deployment are this host's (the configured `node.name` or the bundle's CommonName; the bundle's Organization, else the server's identity, else the node state directory's, peeked without minting) and its endpoint is a canonical spelling under its own scheme; `host.installed_endpoint` is the configuration observation's `node.server_addr` through `endpoint.Parse`, and the two are reported apart because a configuration installed after the start changes nothing the process publishes.

**A node's endpoint is moved by three commands, and the role calls them.** `billet node migrate-endpoint` (internal/ops/host/nodemigrate.go, nodeendpoint.go) decides from the running node's registration record read under a bracket of unit observations, installs nothing (the render precedes it), refuses `KillMode=process`, stops under `--stop-timeout` signalling only its own `systemctl` (the lifeops runner's TERM-then-KILL cancel, `WithWaitDelay` shared with the guard's `guardWaitDelay`), proves the stop by `inactive`/`dead`/`Result=success` on its own observation after `StopAndProve` returns (a zero exit is not the proof: systemd's own timeout completes the job as done), re-observes the unit immediately before the stop (`closeInstalledConfig` and a fresh `observeUnit`: the same process as the bracket's, not `deactivating`, `LoadState=loaded`, the KillMode judged on that observation), closes the configuration again before the start, binds the post-start wait to the started invocation and pid, waits for the record under the new `InvocationID`, and closes every successful answer against the configuration (identity, size, mtime through `closingLstat`) and the process (`MainPID`, `InvocationID`, not `deactivating`); `reported` and `unchanged` retry a moved process three times through `judgeMigration` (`migrateJudgementAttempts`; `closeUnitObservation`'s second result says whether the process moved), `migrated` never (`unknown` `process`, `state: started`). `planned` is true when either the effective or the installed endpoint differs from the rendering's, deliberately. Node presence is the unit's, never a configuration's: an absent installed configuration is `config: absent` and the unit is still observed; two configurations without a node section are observation-only (`record: unread`, the record reader never called); a missing, empty or malformed `MainPID` is could-not-tell. A recordless running node is pre-R only when its image is the managed binary's AND the managed binary answers "unknown command" to `prepare --dry-run` AND the installed configuration has a node endpoint; anything else is `unknown` `record`, never a migration over it. `billet rollout registration` (rolloutregistration.go) polls `StatusSnapshot` alone, re-peeks the identity at every poll and refuses when it is absent (an absent identity proves nothing), reports the epoch and never compares it, answers a timeout as its own struct with `last` always present (null for no row) and no `live` or `epoch`, and preserves the child's exit through `runAsLedgerOwnerCode`. `billet node receipt` (nodereceipt.go, releaseinspectreceipt.go) reads the two answers strictly (`strictObject`, `exactAnswerMembers` at both depths because Go's decoder matches member names case-insensitively, the booleans by their bytes), re-verifies the record under the bracket, judges the receipt directory's parent and the existing file through `receiptLstat`/`receiptOpen`/`receiptOwnerOf`, validates an existing receipt whole before the `current` shortcut (a valid equal one is left alone, both flushes done, and only when the name still holds the inode read: `receiptEvidence.info`), removes an invalid file only when it is still the file judged (`receiptRemoveInvalid` compares identity, size and mtime), proves the directory's identity before the shortcut, before the write and after it (`sameDirectory`), reads the written receipt back before answering `written`, and writes through the durable installer with the parent flushed before the directory is used. `preRProcess` judges only a completed probe: a run the bound ended or whose output overflowed is never pre-R. The endpoint representation is `internal/endpoint`: scheme from `node.tls`, a canonical literal address or a lower-cased name with its rootedness kept, a zone refused. The fixtures a role consumes are written by the producers (`fixtures_test.go`, `fixturesprod_test.go`, `nodemigrate_more_test.go`, `nodereceipt_test.go`, `rolloutregistration_test.go`; `BILLET_UPDATE_FIXTURES=1`), the report ones normalised by key (`normaliseReport`) and re-encoded with sorted members.
