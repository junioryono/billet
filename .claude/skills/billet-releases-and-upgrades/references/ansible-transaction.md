# The Ansible host role's transaction

Part of the `billet-releases-and-upgrades` skill. Each rule is stated in full, with the measurement or incident behind it.

**The Ansible host role is the second implementation of the transaction, and it runs inside the guard the role's preparation holds.** `prepare-exclusion.yml` runs before everything else (the holder from `BILLET_CONVERGE_GUARD_HOLDER` or `-e`; the first call `prepare --validate` acquires or validates BEFORE anything is decided or staged; the staging into an exclusively allocated recovery directory under the guard; the second call declares the intent and is judged under the lock; `settle` last; a refusal inside the acquirer's window releases the guard this invocation acquired and nothing else; a bootstrap and a pre-R host with a candidate hold through the staged candidate after the staging). The transaction then inspects the candidate digest, preserves config, units, binary and enablement in a manifest, publishes its pointer `active/recovery` inside the guard by `ln -sT` proved by `readlink` (a managed binary that predates the guard, with no candidate, claims `active` with the pre-R no-replace hard link under the legacy protocol), proves the configured images compatible, drains node then server, removes `/usr/bin/billet`, fences, snapshots, installs and migrates as sole writer, runs `--upgrade-probe` units that never poll or dispatch, then installs steady units, records the decision, opens the fence and starts server then node. ADR-006 records that consolidating the two means running the role's test suite against the Go command first; replacing a proven implementation with an unproven one to remove a duplicate is the wrong trade. `make host-upgrade-order`, `unit-parity` and `emitted-block-check` are the gates.

**The transaction's node stop, its recovery's stop and finalize's start each go through the node's ending (#127).** `services.yml` records the node's `InvocationID` before "Gracefully stop the billet node before changing its guest contract" and proves the stop afterwards through `tasks/node-ending.yml`, asking in order the installed `/usr/bin/billet` (the stopped node's own release) with the installed configuration, then the staged candidate with the installed configuration and with its own (`billet_ending_with`), with `--drain` exactly where the transaction asked for one (`request-node-drain.yml`'s condition) or a drain is owed (`/etc/billet/node-drain-owed`, which it records before its stop where it asks for one, and whose record it then judges through `--state-dir`); a node with no process to stop is judged without `--invocation`, by what its last process left. An unproved stop fails the block before anything is installed. `upgrade-rollback.yml` records the invocation before the drain request (whose guard is the stop's), no longer swallows a failed node stop (`failed_when: false` is gone), and proves recovery's stop with `--drain`, asking each release the transaction kept (`billet.previous`, then `billet.candidate`) with the configuration installed now and then with its own copy (`billet.yaml.previous`, `billet.yaml.candidate`); only when every one predates the record is systemd's triple the floor. `upgrade-finalize.yml` stops a readiness probe still up, proves a node with no process to stop drained while a drain is requested or owed, passes `admit-start` through the committed binary, then starts the node (`state: started`, never a restart, whose stop no check would see). An updater older than this release stops its node with the old check one last time.

**The Ansible role gives way to the rollout.** `upgrade-inspect.yml` refuses a converge over a symlink claim (the Go transaction's) naming `--status` and `--resume`; `account.yml` compares the two binaries' `version` output and refuses a proved downgrade before the drain unless `billet_allow_downgrade`; `billet_automatic_updates` (default true) renders and enables the two timers wherever they apply; the role's own transaction still refuses a PostgreSQL host, and its message says the timer does that upgrade. `make unit-parity` compares the timers' directives too. A fleet on automatic updates pins `billet_version` for a host's first install and then leaves the binary to rollouts.
