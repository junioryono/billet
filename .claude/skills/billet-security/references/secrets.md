# Secrets: where each may appear and how each is redacted

Part of the `billet-security` skill. Each rule is stated in full, with the measurement or incident behind it.

**The JIT registration is never in argv and never in a log.** Docker gets it in an env file, firecracker in MMDS placed before `InstanceStart`, tart on stdin through `tart exec -i` to the guest agent's socket (never the clone, never SSH), EC2 in single-use instance user data with `HttpTokens=required` and `HttpPutResponseHopLimit=1` so a container inside the job cannot reach the metadata service, and CodeBuild in an SSM SecureString resolved by the service into `ACTIONS_RUNNER_INPUT_JITCONFIG`, so only the parameter's name is ever rendered. CloudWatch logs each buildspec command's source text, not its expansion, so a buildspec that echoed the variable would leak it; billet's never names it. A staged parameter is deleted only on proof the compute is gone; a 5xx from `StartBuild` is not permission to delete.

**Inside the guest, the runner's environment crosses the privilege drop on descriptor 3, never in argv (#352).** The Firecracker agent and the EC2 entry point both launch `setpriv … env -i billet-exec-env <runner> 3<<EOF`, one `NAME=VALUE` per line and then `end`; `internal/guestassets/exec-env.sh` reads and validates the whole stream before it exports anything, then exports with only keywords and special builtins and execs the runner: a listed `PATH` naming dash's `%builtin` after a directory makes `[` and `echo` external commands (measured on `ubuntu:24.04`, dash 0.5.12, 2026-10-03; `export`, `shift` and `exec` stay builtins), so a helper that exported as it read handed later values to a process's argv, and a listed name equal to one of its variables rewrote its state. A value is compared with `case`, never `[`. `OPTIND` is refused and skipped by the writers: dash parses an assignment to it as a number and aborts on anything else, printing the value. A NUL byte cannot reach the helper, because both writers build the stream from shell variables and neither dash nor bash can hold one (measured, 2026-10-03). Until 2026-10-03 the whole environment, registration and cache bearer included, sat in setpriv's and env's argv, readable by every process in the guest through `/proc/<pid>/cmdline` until the runner started. The here-document reaches the helper through a pipe or an unlinked file, and `printf`, `read` and `export` are builtins, so no process on the way carries a value. The guest-image publication gate refuses an image whose helper is not byte for byte this tree's and whose agent is not byte for byte the build script's quoted `AGENT` here-document (mawk extracts exactly the bytes bash installs, measured), and the AMI verifier compares the entry point's and the helper's digests, because an agent or helper that put a value in some argv would still launch every job and keep every substring a gate looks for. The helper refuses a stream with anything after its terminator, read with `od` because dash's `read` answers a read error as it answers the end of the stream (measured) and macOS's `wc -c` counts a regular file by its size, a stream without its terminator, a line that is not `NAME=VALUE` and a name that is not a variable's, with exit 2 and without printing a value; the launch refuses a value holding a newline, naming only the variable, because one line per variable cannot carry it. Writers skip an image-env line whose name is not a variable's rather than let the helper refuse the launch. Measured on `ubuntu:24.04` (dash 0.5.12): values with spaces, quotes, `$`, backslashes and `=` arrive exactly, a 100 KB value crosses, the descriptor survives `setpriv`'s drop, and dash exports `PWD` under `env -i`, which the helper unsets; bash as sh also exports `SHLVL` at the exec, which no unset prevents, and every guest's `/bin/sh` is dash. AMI contract 3 records an image that launches this way.

**Nothing the guest wrote is ever quoted into a billet error.** A launch failure destroys the VM, and the guest's log is a pathname in a filesystem the guest controls: a job dispatched the moment the runner registers can unlink it, leave a symlink to anything readable, and choose the bytes billet prints. billet quotes only tokens from a closed set its own launcher wrote (`command-missing`, `started`), validated against that set.

**Every type that holds a credential redacts itself, on a value receiver, and the table proves it by mutation.** `String`, `GoString`, `Format`, `MarshalJSON` and `LogValue`, because each ignores the others: slog's JSON handler never consults `fmt`, `%#v` never consults `String`, and a pointer-receiver `String` is not consulted when a value is formatted. A defined type (`type Static awssig.Credentials`) inherits none of them. A type that stores a credential in an unexported field needs its own methods, because `reflect` refuses to call methods through one (`awscreds.IMDS` printed the secret through `%+v`; it keeps a pointer receiver only because it holds a mutex). A container renders its members' types, never their values (`awscreds.Chain` recursed forever and depended on every member redacting). The redaction test renders the containers with a member that can actually leak; a member that redacts itself makes the container's behaviour unobservable. 29 mutations, each neutering one path, each shown to fail a test. The access key ID is shown deliberately; the secret and session token never, not even a prefix. The residual: a credential reached through an unexported field of a struct that does not itself redact, and any serializer that is neither `fmt`, `encoding/json` nor `slog`.

**A failed fetch names the URL it was on, and after a redirect that URL is signed.** A GitHub release asset redirects to a pre-signed `release-assets.githubusercontent.com` URL carrying a SAS signature and a JWT, and `http.Client` reports that URL in its `*url.Error`, not the one billet asked for. On 2026-09-25 a TLS timeout on that hop put both into a rollout refusal that `billet rollout status` printed and the journal kept (#253). Every release or image fetch wraps its transport error with `imagesource.WithoutSignedQuery`, which keeps scheme, host and path and drops query, fragment and userinfo.

**A typed nil satisfies an interface and panics on use.** `WithCredentials((*awscreds.IMDS)(nil))` passes `== nil`; `isNilValue` checks the underlying kind. A signed request never goes out in plaintext: `node.ec2.endpoint` must be https, loopback excepted (`config.CheckEC2Endpoint`), because the session token and a replayable signed `RunInstances` cross the wire. The instance role is preferred over an access key, and IMDSv1 is not a fallback (v1 is an unauthenticated GET any request-forgery primitive can read).

**A connector token is a bearer credential and travels in the environment, never argv.** The `cloudflared_connector` and `warp_connector` roles read their tokens from per-host environment variables (`BILLET_CLOUDFLARED_TOKEN_<HOST>`, `BILLET_WARP_CONNECTOR_TOKEN_<HOST>`), decode and compare them under `no_log`, and write cloudflared's to `/etc/cloudflared/token` 0600 root beside a unit the role renders, never through `cloudflared service install`, whose only interface for the token is argv (measured). The residual: `warp-cli connector new <TOKEN>` has no file, stdin or environment form (measured, 2026.6.880.0), so the one enrolment exec carries the token in the host's process list for its duration, as root, once; `no_log` keeps it out of Ansible's output and the gate proves it reaches no other exec.

**The converge action's credentials land in files or the environment, never argv, and its cleanup removes only what the run created.** The CI key and the App key are written under `RUNNER_TEMP` by a shell builtin under `umask 077` (BSD `install` refuses a pipe as its source, so not `install /dev/stdin`) and named through `ANSIBLE_PRIVATE_KEY_FILE` and `BILLET_GITHUB_PRIVATE_KEY_PATH`; the WARP service token goes into `mdm.xml` through `install -m 0600 /dev/stdin` on the Linux runner; the `environment` input is validated line by line into a 0600 file and reaches every Ansible call (the listing, the render and both passes) through `with-environment.py`, which puts the lines into a dictionary and `execvpe`s, never `env(1)`, whose own argv would carry the values until it execs, and never a shell assignment, because bash evaluates the value assigned to `RANDOM`, `SECONDS` and their kin as arithmetic (a subscript there runs a command substitution), a failed `export` inside a subshell does not stop the run, and an exported loop cursor is overwritten by the next iteration; the script's own decisions are readonly under a `billet_action_` prefix the input refuses by name; a name that would change Ansible, ssh or the runner (`ANSIBLE_*`, `GITHUB_*`, `RUNNER_*`, `SSH_*` (an askpass helper runs, an agent socket changes the identities offered), `DISPLAY`, `PATH`, `HOME` and their kin) is refused by name; a line carrying a control character is refused, because a carriage return inside a value is one line to the shell and two to a reader with newline translation, the second of which can set `PATH` (the launcher reads with `newline=""` and refuses the same bytes); a malformed line is reported by its number, never its contents, and a host-key refusal (`actions/converge-fleet/judge-ssh-options.py`, with a `--decode` mode so a test can observe what it reads) interprets ONLY `-o` in the tokens Ansible hands ssh, which are `shlex`'s, each stripped and the empty ones dropped (its connection plugin's `_split_ssh_args`; a token that opens with a space is a flag to ssh, not a non-flag), and refuses every other flag by name, because ssh parses flags with getopt and `-4oStrictHostKeyChecking=no` or `-4F/tmp/x` is a cluster the action would otherwise skip (`AddressFamily=inet` is the `-o` spelling of `-4`); inside an option the keyword is read the way readconf's `strdelim` reads it (a double-quoted keyword runs to its closing quote and the value starts right after, so `"StrictHostKeyChecking"no` is the keyword and `no`; otherwise to whitespace or `=`) and the value the way `argv_split` reads one argument (single or double quotes, concatenated fragments; a backslash escapes a quote or a backslash in either quote mode and a space outside quotes only, any other backslash kept as written; a hash is a comment only where a token would begin; an unquoted space or tab ends it, and nothing else does), so `'no'`, `n"o"` and `no # x` are all `no` and `"key\"name"` is `key"name`; a keyword is a letter followed by letters and digits (`ForwardX11`), one with a quote in its middle and an unclosed quote are unreadable, and what the two parsers do not model is refused rather than guessed at; the refused keywords are each a way of accepting a key the pins do not hold: `Include`, `UserKnownHostsFile`, `GlobalKnownHostsFile`, `KnownHostsCommand`, `HostKeyAlias`, `StrictHostKeyChecking` off, `CheckHostIP` off, `NoHostAuthenticationForLocalhost`, `VerifyHostKeyDNS`, `GSSAPIKeyExchange` (a patched client authenticates the server without a host key), and `ControlPath` or `ControlMaster`, because ssh reuses an existing master socket before it verifies anything and that master was authenticated under whatever checking it had; the refusal names the canonical option, never the SSH arguments, which may carry a ProxyCommand (`-e` is for non-secret values, because argv is world-readable for the run). Host-key pins are appended to the runner user's `known_hosts` and an inventory that disables checking is refused, since an inventory's own SSH arguments replace anything the action sets. The reach step proceeds only on a positive `Registration Missing` or `Missing registration` from the client (both spellings have been observed from `warp-cli`, the second as `Error: Missing registration.`) (any other answer, or none, is could-not-tell and refuses, because a stopped daemon still has its registration on disk), writes its ownership marker before the daemon can register, bounds every call with `timeout -k`, and cleanup removes the key files unconditionally, checking each removal's status, deletes the registration only under that marker, treats a delete that finds it already gone as gone, reports every failure and keeps the marker until both the registration and `mdm.xml` are gone, so a deploy runner's or a laptop's own registration survives `reach: none` and a registration that could not be deleted is not forgotten. The residual is the roles' own: `warp-cli connector new <TOKEN>` on the host, once, at enrolment.
