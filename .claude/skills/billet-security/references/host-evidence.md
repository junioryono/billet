# Root-owned evidence: the upgrade root, the registration record and the receipt

Part of the `billet-security` skill. Each rule is stated in full, with the measurement or incident behind it.

**The upgrade root is a trust boundary, proved through descriptors before any lock, and the executable a guard records is verified by digest and never run.** `cmd/billet/upgradetxlock.go` and `convergeguard.go`: every ancestor of the root's parent (walked from `/`, one component relative to the one above it, owned by root or by the account running billet's transactions and group/other-writable only under the sticky bit), the root's parent, the root, `active` and `transaction.lock` are each required to be owned by the account running billet's transactions (the process's euid: root on Linux, the launch agent's account on a Mac), writable by nobody else, and not a symlink, with each component opened relative to the descriptor of the one above it (`openat`, `O_NOFOLLOW`) and judged on the descriptor that is then used, because `/var/lib/billet/upgrades/active` is a name every updater on the host acts on and a symlink there, at the lock, or on the way to them would make a name checked a different thing from a name used; once the lock is held the root's name must still hold the locked directory, and a resume or a takeover reads the journal through the root (the claim's target exactly one child of the root by its text, opened relative to the root and judged owned and unwritable by others, the journal judged on its own descriptor), never by a name; the record, a candidate and an existing lock are opened identity first (`O_PATH` on Linux, then `regularfile.Reopen`), so a device planted at any of them is refused without its driver being invoked; a link on the way to the root is admitted only when the link itself is owned by root or by that account, because a sticky directory protects billet's entries and not a link another account made beside them; the record is judged on its own descriptor (owned, writable by nobody else), because a hard link from a foreign file is a record that account can rewrite; and a stale `guard.json.tmp` is examined through an identity descriptor (`judgeStaleTemporary`: regular, owned, writable by nobody else, ONE LINK) in EVERY command that removes one (the preparation, the settlement, the release, the takeover and `recover --unpublished`) and then removed by name, never opened for writing or truncated, so no inode is ever emptied under another name and a foreign-owned, loose or hard-linked file at that name is refused rather than deleted (a review found the preparation unlinking any regular file there, 2026-09-10). A takeover retires the acquirer's window with the holder: the rewritten record carries no `token` and `preparing: false`, because the token authorises the cleanup release by the invocation that acquired the guard and the new holder never did. A probe's answer that overflowed the command's output bound is refused as not read whole (`errOutputOverflow`), never decoded as complete, since a valid object, padding past the bound and garbage would otherwise pass the trailing-bytes check on the prefix that was kept; an exit 0 beside any other run error (`exec.ErrWaitDelay` from a descendant holding the output open past `guardWaitDelay`, a pipe failure) is refused the same way, since what was kept is what arrived before the wait ended; and the status decoder refuses a repeated member at any depth (`jsonRepeatedMember`, walked with `UseNumber` so a number the walk cannot hold is not where it stops, a walk that fails being a refusal and a repeated empty name being repeated), as the record's reader does. The fallback reader refuses a repeated member (`_one_of_each`) as the Go decoder does, in both orderings. A `--candidate` is admitted only inside a `recovery-*` child of the root, opened relative to the root, hashed through its descriptor, and the name compared with the descriptor afterwards, so a file swapped under the hold is refused rather than recorded under another file's digest; `prepare --candidate` hashes it again after its `version` and `status` probes executed it and refuses when the digest moved, so the candidate judged is the candidate recorded, and a probe that did not run or answered another shape is could-not-tell rather than a candidate with no version to compare. A transaction pointer's target is admitted only as its canonical absolute spelling (a `..` or a relative target is refused, never resolved), the recovery directory it names opened by that name relative to the locked root without following anything (a symlink at the name refuses) and judged owned by the root's owner and writable by nobody else; a guard record must carry its five members typed, and an `id` that is present but not 32 hex characters (null included) is malformed rather than a record from before the protocol, so nothing is adopted that two writers could disagree about. `status --json` answers `release_executable_verified` by hashing, never by executing (`TestTheRecordedExecutableIsNeverRun` plants a script that records its own run). The process scan behind `recover` and a takeover is an extra refusal under the operator's `--old-driver-stopped` assertion, and its blind spots (an unmarked driver, another pid namespace, work dispatched after the scan) are written down rather than papered over.

**The role runs a guard's recorded executable only after the fallback module proved it, and holds under a name the driver chose.** `plugins/modules/guard_fallback.py` reads `guard.json` in three phases (every component's metadata from `/var/lib/billet` down, owned by the root's owner and writable by nobody else, never a link, the record 0600 and at most 4 KiB; then the five members required and the protocol's `id`, `token` and `preparing` admitted and typed when present, the token judged as a string and never printed; then the candidate's components and its digest through the descriptor), executes nothing, and a candidate that fails any step is never run by the role, which refuses naming what to install by hand rather than falling back to the legacy protocol; hard links are admitted because the command imposes no one-link rule. The holder comes from `BILLET_CONVERGE_GUARD_HOLDER` or `-e billet_converge_guard_holder`, never a default. THE TOKEN an `acquired` answer carries is the acquiring invocation's one authorisation, the cleanup release inside its own preparation window (`release --cleanup --token`, refused for a settled guard, a wrong token or a transaction pointer): it is printed only in that answer, kept in a fact no report prints, and passed in the argv of the second call, `settle` and the cleanup under `no_log`; on a default kernel other local users can read that argv, and a party holding it can do nothing to a root-owned guard without being root, and root needs no token. The role releases only what this invocation acquired and only before it changed anything; a converge that dies holding a guard leaves it, and the preparation's report names `release --holder` and `recover --holder --old-driver-stopped`. The gate proves no token reaches the play's output by grepping the captured one from every case, one under `-vvv`.

**The node's registration record is root-owned evidence under the node unit's own runtime directory, and it is judged on the descriptor that is read.** `/run/billet/registration/current` is written 0600 by the node (root) through the durable installer after every accepted registration; the inspector admits it only when the fstat of the descriptor it then reads says root, 0600, regular and within the bound, never from an `Lstat` beside the read, because a record another account owns or could write names any endpoint and incarnation that account likes, and a foreign file swapped at the name between a lookup and the read would otherwise be judged by the lookup and read as the record. The directory belongs to the node unit alone: a server unit declaring the same `RuntimeDirectory` would re-own the record at its start and remove it at its stop (measured on systemd 255, 2026-09-09).

**The endpoint receipt is root-owned evidence, and the migration signals only its own subprocess.** `/var/lib/billet/node/endpoint-migration.json` is root 0600 in a root 0700 directory whose parent must be a root-owned directory and not a link; the reader (`readEndpointReceipt`) examines the name before the open (a link or a special file is positively not a receipt and is never opened, so a FIFO never waits), opens identity-first without following, requires the owner root and mode 0600, bounds the read at 4096 bytes, and decodes under the exact ten-member set; a failed examination, open, reopen or read is `unreadable` and never absence. `node migrate-endpoint` bounds the node's stop with its own deadline and, on expiry, TERMs then KILLs the `systemctl` it ran and nothing else; the node and its compute are never signalled by a converge, and a stop systemd began runs on under the unit's own bound. The guard's `note` is bounded (200 bytes, printable, no newline) before it is written and validated again by every reader, so a record cannot carry a line an operator's terminal would misread.
