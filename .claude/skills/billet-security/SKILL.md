# Security

## What this area is

billet holds a GitHub App private key per target that can mint tokens for a whole organization, or for one repository through `administration: write`, the only permission GitHub offers for registering a repository's runners and a far wider grant than the organization one (used for registration and nothing else, disclosed at creation, and installed on the one repository rather than every one the owner has); a node-wire CA, per-job runner registrations (JIT configs), per-guest cache bearers, an optional TLS interception CA, and on cloud nodes AWS credentials that can create and destroy machines. The threat model is stated in the README: billet is not a sandbox for untrusted code, and a job can affect the host it runs on unless the backend is a real boundary and the network is its own. Everything here exists because a quiet mistake with one of those credentials is expensive and invisible.

## Rules

**The server is unprivileged; the node is a root custodian.** `billet-server.service` runs as `billet` with an empty capability set, `ProtectSystem=strict` and a syscall filter. `billet-node.service` runs as root because Firecracker needs TAP devices, block-device nodes, cgroups, chroots and verified process signalling, and Docker's rootful socket is host root anyway. The isolation boundary is downstream: the jailer drops each VMM to its own uid before Firecracker reads guest-controlled state, and guests never receive the Docker socket. On a Mac the node is a launch agent in the user's session, never root (Virtualization.framework needs the login keychain and tart's store is per-user).

**Trust belongs to a pool, not to the assignment that scaled it up.** GitHub may hand a registered scale-set runner any job in the set, so billet never derives authority from `push` versus `pull_request`. Every tier is `untrusted` unless promoted; a `trusted` tier requires a non-default runner group and an exact `workflows` allowlist, and the plane reads GitHub's `restricted_to_workflows` policy at startup and before every JIT mint, refusing drift. A repository target has no runner groups, so nothing on GitHub's side can restrict a pool there: every tier under one is untrusted, refused at load and again at `server.Run` with `trusted`, `runner_group`, `workflows` or `intercept`, which is also why docker cannot serve a repository target. The operator remains responsible for those workflows not executing untrusted revisions.

**Untrusted work needs a real boundary and a network of its own, and each backend answers differently.** `docker` refuses it outright (shared kernel). `firecracker` refuses until `node.firecracker.untrusted_bridge` names a separate network, because a microVM isolates the kernel and not the bridge, and the ordinary bridge reaches the Ceph cluster and the control plane. `tart` refuses until `node.tart.untrusted_isolation: softnet`, because tart's default NAT reaches the host and lets a guest spoof the bridge. `ec2` admits it only with `node.ec2.untrusted_security_group_ids`. `codebuild` refuses it outright: a reserved fleet's instances survive between builds and share cached data across projects by design, and on-demand builds are strictly weaker than an EC2 instance (the service role is readable from inside the build at `169.254.170.2`, and the same role reads the JIT parameter path, so untrusted forks and trusted tiers must never share a CodeBuild node). `TrustUnknown` is refused as malformed. `Accepts` and the flag builder are one function in tart, because written as two a mechanism admitted and not applied boots untrusted work on the trusted bridge.

**The JIT registration is never in argv and never in a log.** Docker gets it in an env file, firecracker in MMDS placed before `InstanceStart`, tart on stdin through `tart exec -i` to the guest agent's socket (never the clone, never SSH), EC2 in single-use instance user data with `HttpTokens=required` and `HttpPutResponseHopLimit=1` so a container inside the job cannot reach the metadata service, and CodeBuild in an SSM SecureString resolved by the service into `ACTIONS_RUNNER_INPUT_JITCONFIG`, so only the parameter's name is ever rendered. CloudWatch logs each buildspec command's source text, not its expansion, so a buildspec that echoed the variable would leak it; billet's never names it. A staged parameter is deleted only on proof the compute is gone; a 5xx from `StartBuild` is not permission to delete.

**Nothing the guest wrote is ever quoted into a billet error.** A launch failure destroys the VM, and the guest's log is a pathname in a filesystem the guest controls: a job dispatched the moment the runner registers can unlink it, leave a symlink to anything readable, and choose the bytes billet prints. billet quotes only tokens from a closed set its own launcher wrote (`command-missing`, `started`), validated against that set.

**Every type that holds a credential redacts itself, on a value receiver, and the table proves it by mutation.** `String`, `GoString`, `Format`, `MarshalJSON` and `LogValue`, because each ignores the others: slog's JSON handler never consults `fmt`, `%#v` never consults `String`, and a pointer-receiver `String` is not consulted when a value is formatted. A defined type (`type Static awssig.Credentials`) inherits none of them. A type that stores a credential in an unexported field needs its own methods, because `reflect` refuses to call methods through one (`awscreds.IMDS` printed the secret through `%+v`; it keeps a pointer receiver only because it holds a mutex). A container renders its members' types, never their values (`awscreds.Chain` recursed forever and depended on every member redacting). The redaction test renders the containers with a member that can actually leak; a member that redacts itself makes the container's behaviour unobservable. 29 mutations, each neutering one path, each shown to fail a test. The access key ID is shown deliberately; the secret and session token never, not even a prefix. The residual: a credential reached through an unexported field of a struct that does not itself redact, and any serializer that is neither `fmt`, `encoding/json` nor `slog`.

**A typed nil satisfies an interface and panics on use.** `WithCredentials((*awscreds.IMDS)(nil))` passes `== nil`; `isNilValue` checks the underlying kind. A signed request never goes out in plaintext: `node.ec2.endpoint` must be https, loopback excepted (`config.CheckEC2Endpoint`), because the session token and a replayable signed `RunInstances` cross the wire. The instance role is preferred over an access key, and IMDSv1 is not a fallback (v1 is an unauthenticated GET any request-forgery primitive can read).

**A connector token is a bearer credential and travels in the environment, never argv.** The `cloudflared_connector` and `warp_connector` roles read their tokens from per-host environment variables (`BILLET_CLOUDFLARED_TOKEN_<HOST>`, `BILLET_WARP_CONNECTOR_TOKEN_<HOST>`), decode and compare them under `no_log`, and write cloudflared's to `/etc/cloudflared/token` 0600 root beside a unit the role renders, never through `cloudflared service install`, whose only interface for the token is argv (measured). The residual: `warp-cli connector new <TOKEN>` has no file, stdin or environment form (measured, 2026.6.880.0), so the one enrolment exec carries the token in the host's process list for its duration, as root, once; `no_log` keeps it out of Ansible's output and the gate proves it reaches no other exec.

**A registration proves who you are; only a command proves what you may do.** A node may mint exactly the registration for a launch it currently holds, remove exactly the runner the ledger attributes to it, and act on exactly the leases it was given. Authentication answers which host; the command table answers what it was given.

**Destruction is scoped by deployment identity.** Every container, instance, jail, VM directory and build carries the identity; `List`, `Find` and every destructive AWS statement filter on it, and a missing or unreadable tag is not ownership. Two billets on one machine share a hostname and must not see each other's compute.

**Never signal a pid you have not proved is still yours.** A pid file holds a number the kernel reuses and a node signals as root. The firecracker backend proves the pid still names its microVM by the `--id <jail id>` pair in `/proc/<pid>/cmdline` (matched as the pair, not the id anywhere in the line), re-checks immediately before escalating to SIGKILL, and treats an unreadable `/proc` entry as "could not tell" rather than "gone". Only "gone" lets teardown continue to unmap disks and remove the jail.

**Giving away a hard link gives away the inode.** The kernel is linked into each jail and the jail tree was then chowned to the VMM's uid, which chowned the host's one kernel to an account every VMM shares; the owner may `chmod` and write it, so one escape rewrites the kernel every later microVM boots without leaving the chroot. Chown the chroot alone; what a jailed process needs is to read. The same rule refuses a key file with more than one link in `lifeops`.

**The node's registration record is root-owned evidence under the node unit's own runtime directory, and it is judged on the descriptor that is read.** `/run/billet/registration/current` is written 0600 by the node (root) through the durable installer after every accepted registration; the inspector admits it only when the fstat of the descriptor it then reads says root, 0600, regular and within the bound, never from an `Lstat` beside the read, because a record another account owns or could write names any endpoint and incarnation that account likes, and a foreign file swapped at the name between a lookup and the read would otherwise be judged by the lookup and read as the record. The directory belongs to the node unit alone: a server unit declaring the same `RuntimeDirectory` would re-own the record at its start and remove it at its stop (measured on systemd 255, 2026-09-09).

**Privileged operations go through a descriptor, never a pathname.** `os.Chown` follows symlinks and a name checked is not a name changed. Open `O_NOFOLLOW`, verify it is the same regular file the planner saw, `fchmod` before `fchown` (reversed, a chown that succeeds beside a chmod that fails leaves a key owned by the service account with whatever bits it had). `os.Root` does not refuse a symlink inside the root (measured); `unix.Openat` against a real directory descriptor honours the flag. `uid_t` is unsigned 32-bit, so parse ids with `ParseUint(…, 10, 32)`, reject `MaxUint32` and reject 0.

**A cache bearer lives exactly as long as the compute it belongs to.** Every microVM gets its own 32-byte bearer scoped to its five drive slots; EC2 carries it in user data and sends it back only over HTTPS; it is never a cache key, a log field or a deployment secret. Cleanup marks the session closed before discarding, so a later guest request answers gone. Trust gates publication, not reads: an untrusted job may hydrate from the trusted baseline and its clone is discarded unpublished, so cached bytes are a deployment-and-site trust boundary and a private image pulled by one trusted job is readable by a later job in that boundary. Registry mirrors serve public content without an upstream credential.

**Interception is opt-in and off on unqualified tiers.** `ACTIONS_RESULTS_URL` carries artifact metadata as well as cache traffic, so interception terminates TLS only for that host and handles only three CacheService methods; a mistake there breaks a deploy. Untrusted jobs get no interception and no CA.

**The IAM grants have no delete where the credential would sit beside what it could destroy.** The backup grant (`internal/archivestore`) and the identity-store grant carry no delete; the CodeBuild controller sweep grant is list-and-delete on the registration path with no `GetParameter` and no KMS, and the missing KMS grant is not the confidentiality boundary under the default key (measured: `WithDecryption=true` returned plaintext with no `kms:*` anywhere), so the boundary is billet's request stating no decryption and a response type with no `Value` field. The build's service role is a different principal from the node role.

**The upgrade root is a trust boundary, proved through descriptors before any lock, and the executable a guard records is verified by digest and never run.** `cmd/billet/upgradetxlock.go` and `convergeguard.go`: every ancestor of the root's parent (walked from `/`, one component relative to the one above it, owned by root or by the account running billet's transactions and group/other-writable only under the sticky bit), the root's parent, the root, `active` and `transaction.lock` are each required to be owned by the account running billet's transactions (the process's euid: root on Linux, the launch agent's account on a Mac), writable by nobody else, and not a symlink, with each component opened relative to the descriptor of the one above it (`openat`, `O_NOFOLLOW`) and judged on the descriptor that is then used, because `/var/lib/billet/upgrades/active` is a name every updater on the host acts on and a symlink there, at the lock, or on the way to them would make a name checked a different thing from a name used; once the lock is held the root's name must still hold the locked directory, and a resume or a takeover reads the journal through the root (the claim's target exactly one child of the root by its text, opened relative to the root and judged owned and unwritable by others, the journal judged on its own descriptor), never by a name; the record, a candidate and an existing lock are opened identity first (`O_PATH` on Linux, then `regularfile.Reopen`), so a device planted at any of them is refused without its driver being invoked; a link on the way to the root is admitted only when the link itself is owned by root or by that account, because a sticky directory protects billet's entries and not a link another account made beside them; the record is judged on its own descriptor (owned, writable by nobody else), because a hard link from a foreign file is a record that account can rewrite; and a stale `guard.json.tmp` is examined through an identity descriptor (`judgeStaleTemporary`: regular, owned, writable by nobody else, ONE LINK) in EVERY command that removes one (the preparation, the settlement, the release and the takeover) and then removed by name, never opened for writing or truncated, so no inode is ever emptied under another name and a foreign-owned, loose or hard-linked file at that name is refused rather than deleted (a review found the preparation unlinking any regular file there, 2026-09-10). A `--candidate` is admitted only inside a `recovery-*` child of the root, opened relative to the root, hashed through its descriptor, and the name compared with the descriptor afterwards, so a file swapped under the hold is refused rather than recorded under another file's digest; `prepare --candidate` hashes it again after its `version` and `status` probes executed it and refuses when the digest moved, so the candidate judged is the candidate recorded, and a probe that did not run or answered another shape is could-not-tell rather than a candidate with no version to compare. A transaction pointer's target is admitted only as its canonical absolute spelling (a `..` or a relative target is refused, never resolved), the recovery directory it names opened by that name relative to the locked root without following anything (a symlink at the name refuses) and judged owned by the root's owner and writable by nobody else; a guard record must carry its five members typed, and an `id` that is present but not 32 hex characters (null included) is malformed rather than a record from before the protocol, so nothing is adopted that two writers could disagree about. `status --json` answers `release_executable_verified` by hashing, never by executing (`TestTheRecordedExecutableIsNeverRun` plants a script that records its own run). The process scan behind `recover` and a takeover is an extra refusal under the operator's `--old-driver-stopped` assertion, and its blind spots (an unmarked driver, another pid namespace, work dispatched after the scan) are written down rather than papered over.

**The role runs a guard's recorded executable only after the fallback module proved it, and holds under a name the driver chose.** `plugins/modules/guard_fallback.py` reads `guard.json` in three phases (every component's metadata from `/var/lib/billet` down, owned by the root's owner and writable by nobody else, never a link, the record 0600 and at most 4 KiB; then the five members required and the protocol's `id`, `token` and `preparing` admitted and typed when present, the token judged as a string and never printed; then the candidate's components and its digest through the descriptor), executes nothing, and a candidate that fails any step is never run by the role, which refuses naming what to install by hand rather than falling back to the legacy protocol; hard links are admitted because the command imposes no one-link rule. The holder comes from `BILLET_CONVERGE_GUARD_HOLDER` or `-e billet_converge_guard_holder`, never a default. THE TOKEN an `acquired` answer carries is the acquiring invocation's one authorisation, the cleanup release inside its own preparation window (`release --cleanup --token`, refused for a settled guard, a wrong token or a transaction pointer): it is printed only in that answer, kept in a fact no report prints, and passed in the argv of the second call, `settle` and the cleanup under `no_log`; on a default kernel other local users can read that argv, and a party holding it can do nothing to a root-owned guard without being root, and root needs no token. The role releases only what this invocation acquired and only before it changed anything; a converge that dies holding a guard leaves it, and the preparation's report names `release --holder` and `recover --holder --old-driver-stopped`. The gate proves no token reaches the play's output by grepping the captured one from every case, one under `-vvv`.

**The converge action's credentials land in files or the environment, never argv, and its cleanup removes only what the run created.** The CI key and the App key are written under `RUNNER_TEMP` by a shell builtin under `umask 077` (BSD `install` refuses a pipe as its source, so not `install /dev/stdin`) and named through `ANSIBLE_PRIVATE_KEY_FILE` and `BILLET_GITHUB_PRIVATE_KEY_PATH`; the WARP service token goes into `mdm.xml` through `install -m 0600 /dev/stdin` on the Linux runner; the `environment` input is validated line by line into a 0600 file and reaches every Ansible call (the listing, the render and both passes) through `with-environment.py`, which puts the lines into a dictionary and `execvpe`s, never `env(1)`, whose own argv would carry the values until it execs, and never a shell assignment, because bash evaluates the value assigned to `RANDOM`, `SECONDS` and their kin as arithmetic (a subscript there runs a command substitution), a failed `export` inside a subshell does not stop the run, and an exported loop cursor is overwritten by the next iteration; the script's own decisions are readonly under a `billet_action_` prefix the input refuses by name; a name that would change Ansible, ssh or the runner (`ANSIBLE_*`, `GITHUB_*`, `RUNNER_*`, `SSH_*` (an askpass helper runs, an agent socket changes the identities offered), `DISPLAY`, `PATH`, `HOME` and their kin) is refused by name; a line carrying a control character is refused, because a carriage return inside a value is one line to the shell and two to a reader with newline translation, the second of which can set `PATH` (the launcher reads with `newline=""` and refuses the same bytes); a malformed line is reported by its number, never its contents, and a host-key refusal (`actions/converge-fleet/judge-ssh-options.py`, with a `--decode` mode so a test can observe what it reads) interprets ONLY `-o` in the tokens Ansible hands ssh, which are `shlex`'s, each stripped and the empty ones dropped (its connection plugin's `_split_ssh_args`; a token that opens with a space is a flag to ssh, not a non-flag), and refuses every other flag by name, because ssh parses flags with getopt and `-4oStrictHostKeyChecking=no` or `-4F/tmp/x` is a cluster the action would otherwise skip (`AddressFamily=inet` is the `-o` spelling of `-4`); inside an option the keyword is read the way readconf's `strdelim` reads it (a double-quoted keyword runs to its closing quote and the value starts right after, so `"StrictHostKeyChecking"no` is the keyword and `no`; otherwise to whitespace or `=`) and the value the way `argv_split` reads one argument (single or double quotes, concatenated fragments; a backslash escapes a quote or a backslash in either quote mode and a space outside quotes only, any other backslash kept as written; a hash is a comment only where a token would begin; an unquoted space or tab ends it, and nothing else does), so `'no'`, `n"o"` and `no # x` are all `no` and `"key\"name"` is `key"name`; a keyword is a letter followed by letters and digits (`ForwardX11`), one with a quote in its middle and an unclosed quote are unreadable, and what the two parsers do not model is refused rather than guessed at; the refused keywords are each a way of accepting a key the pins do not hold: `Include`, `UserKnownHostsFile`, `GlobalKnownHostsFile`, `KnownHostsCommand`, `HostKeyAlias`, `StrictHostKeyChecking` off, `CheckHostIP` off, `NoHostAuthenticationForLocalhost`, `VerifyHostKeyDNS`, `GSSAPIKeyExchange` (a patched client authenticates the server without a host key), and `ControlPath` or `ControlMaster`, because ssh reuses an existing master socket before it verifies anything and that master was authenticated under whatever checking it had; the refusal names the canonical option, never the SSH arguments, which may carry a ProxyCommand (`-e` is for non-secret values, because argv is world-readable for the run). Host-key pins are appended to the runner user's `known_hosts` and an inventory that disables checking is refused, since an inventory's own SSH arguments replace anything the action sets. The reach step proceeds only on a positive `Registration Missing` or `Missing registration` from the client (both spellings have been observed from `warp-cli`, the second as `Error: Missing registration.`) (any other answer, or none, is could-not-tell and refuses, because a stopped daemon still has its registration on disk), writes its ownership marker before the daemon can register, bounds every call with `timeout -k`, and cleanup removes the key files unconditionally, checking each removal's status, deletes the registration only under that marker, treats a delete that finds it already gone as gone, reports every failure and keeps the marker until both the registration and `mdm.xml` are gone, so a deploy runner's or a laptop's own registration survives `reach: none` and a registration that could not be deleted is not forgotten. The residual is the roles' own: `warp-cli connector new <TOKEN>` on the host, once, at enrolment.

## Measured facts

- `%+v` on `awscreds.IMDS` printed the secret access key and session token through an unexported field.
- 29 redaction mutations run; three pre-existing gaps found (`Chain`'s three renderers, and both provider clients' tests holding members that could not leak).
- A CodeBuild service role holding only `ssm:GetParameters` resolves the parameter; `ssm:GetParameter` was dropped from the grant.
- `169.254.170.2` serves the build's role credentials inside a VPC on-demand build.
- `os.Root` opened a relative `link.lock -> real.lock` as `os.SameFile` with its target.
- 31 on-demand CodeBuild builds: 31 distinct host boot ids (2026-09-02); reserved fleets keep a marker written by one build readable by the next.

## Where the tests are

- `internal/awscreds/*_test.go` and the provider clients' redaction tables; `internal/github`'s `App` redaction tests.
- `internal/provider/firecracker/*_test.go` (pid proof, chown scope), `internal/lifeops/*_test.go` (descriptor rules, link counts).
- `internal/nodeplane/*_test.go` (JIT entitlement, register-before-decode with a counting body), `internal/e2e/wire_test.go`.
- `actions/convergefleet_test.go` (credentials 0600 and exported, environment lines never in argv, pins appended, `ssh-keyscan` never run, cleanup scoped to the run's marker).
- `internal/provider/codebuild/*_test.go` (never echoes its registration, `TestTheSweepNeverDecodesAValue`), `internal/provider/tart/*_test.go` (`Accepts` and the flag builder), `internal/provider/ec2/*_test.go` (metadata options, endpoint scheme).
