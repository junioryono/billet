# The blocks of billet.yaml

Part of the `billet-config` skill. Each rule is stated in full, with the measurement or incident behind it.

| Key | Read by | What it is |
|---|---|---|
| `server` | `billet server`; a certless node sharing the file reads it to learn which deployment it joins | `listen` (loopback means plain HTTP; anything else requires mTLS), `bootstrap_listen` (the enrollment listener; absent means no network enrollment), `node_tls_hosts` (required when `listen` is a wildcard; both listeners present one certificate), `state_dir` (shorthand for `identity_dir` plus `state: {backend: sqlite}`; writing both is refused), `identity_dir`, `state` (`backend: sqlite` or `postgres`; `postgres.dsn_env` names the variable holding the DSN, never the DSN), `controllers` (`single` or `active-passive`, refused on SQLite), `identity` (`backend: file` or `aws-ssm` with `aws_ssm.region/prefix/kms_key_id`), `max_vcpu` and `max_memory` (required, positive, the deployment ceiling), `placement` (`pack` or `spread`), `drain_timeout`; `metrics` (the role's Prometheus endpoint, absent meaning none: `listen`, a literal loopback address unless `allow_remote`; `pprof`, refused on any `listen` that is not a literal loopback address; no socket shared with any other listener in the file, the other role's endpoint included; ADR-016), `flight_recorder` (a bool, off by default: the controller's execution trace, written under `identity_dir/flight-recorder` on a heartbeat overrun or a lost claim) |
| `github` | `billet server` | the target named `default`: exactly one of `org` or `repository` (`owner/name`), `app_id`, `client_id` (optional), `installation_id` (required; creating an App does not install it), `private_key_path`; `name` is refused here |
| `targets` | `billet server` | further targets, each `name` plus the `github` fields; requires the `github` block (always the first target, always `default`); names label-shaped (`CheckTargetName`) and unique, `default` refused; no two targets share a key path; every tier then needs `target`. `max_vcpu`/`max_memory` on a target block are its share (`TargetShares`, keyed by name through `ShareTarget`, `""` meaning `default`), refused by `TargetShareErrors` above the deployment ceiling, below a tier's shape or below its tiers' floors, and re-applied by `alloc.New`. A file identity needs a key path per target, a store identity refuses one (`validateTargetKeyPaths`); `TierTargetPolicyErrors` refuses `trusted`, `runner_group`, `workflows` and `intercept` under a repository target and a `cache_scope` outside the target's owner (and repository), and `server.Run` re-applies it because `alloc.New` is a second entry point |
| `node` | `billet node` | `name` (from the certificate when there is one; required on loopback), `server_addr`, `bootstrap_addr`, `provider`, `site`, `max_vcpu`/`max_memory` (what this host contributes; required for `ec2` and `codebuild`), `tls` (all three of `cert`, `key`, `ca`), `lock_dir` and `allow_unlocked_deployment`, `state_dir` (required), `max_custody`, `drain_timeout`, and one provider block: `firecracker` plus `ceph` (both required for firecracker, refused otherwise), `tart` (optional), `ec2`, `codebuild`, plus `ebs_s3`, `cache`, `registry_mirrors`, `monitoring` (`interval` 250ms to 30s, the bound set by RAPL's wrap; `rapl`; `idle_package_watts`, which requires `rapl`; `perf`, the vCPU threads' hardware counters, off unless true; refused on any provider but firecracker, docker and tart, `rapl` and `idle_package_watts` refused on tart, whose VMs carry macOS's own per-process energy estimate, and `perf` refused on any provider but firecracker, and at node startup rather than in config on a platform without `perf_event_open`, since a config is also validated on machines that will not run it; absent means off); `metrics` (as the server's, on a port of its own) |
| `tiers` | both roles | one tier is one scale set; `label` is the tier's identity in the ledger and allocator, unique in the file, and `runs_on` (default `label`) is the scale set's name and the `runs-on` value, unique per GitHub owner (`validateTierTargets` keys on the target's path, and refuses a repository target reusing a name its organization's target has, since the organization's set would take the same jobs), so targets on different owners can share one name; `teardown --tier` names the set and `--target` scopes it to one target. Everything that talks to GitHub by name (the server's `EnsureScaleSet` and record, the provenance report, the plane's describe and mint, `teardown`) goes through `Tier.ScaleSetName()`; the node still sends the label on the wire and the plane translates, so no wire version was needed. `trust`, `workflows`, `cache_scope`, `provider` or ordered `providers` (never both), `guest_os`, `node` and `site` pins, `runner_group`, `command`, per-provider `launch`, `vcpu`/`memory` or `sizes` with `memory_per_vcpu`, `disk`, `shm`, `buildkit_cache_mount_limit`, `image`, `intercept`, `max_concurrent` (ceiling), `reserved` (floor); `warm_pool` is refused when non-zero because no provider implements it |
| `nodes` | control plane | per-host policy, not a roster: `name`, `provider`, `guest_os` allowlist, `macos_vm_limit` |
| `sites` | control plane | `name` (matched exactly), `store` (`ceph` or `ebs-s3`) |
| `backup` | `local backup`, `local restore --from-backup` | `s3.bucket`, `s3.region` (required even with an `endpoint`), `s3.prefix`, `s3.endpoint` (path-style; RGW, MinIO, R2), `s3.kms_key_id` |
| `images` | `images pull` | `source` (empty means billet's own), `signing_identity` and `signing_issuer` (required for a non-default source) |
| `release` | the rollout starter, `host-upgrade --from-rollout`, `images refresh` | `channel` (`stable` or `candidate`), `version` (an exact tag or a 40-hex SHA; `latest` and `main` refused; exclusive with `channel`), `automatic` (a `*bool` whose nil is TRUE, read only through `AutomaticUpdates()`; the one switch for starting rollouts, acting on them and refreshing images), `maintenance_window` (bounds when a rollout may begin; refused beside an explicit `automatic: false`), `signing_identity` and `signing_issuer` (both or neither) |

Provider kinds are `firecracker`, `tart`, `ec2`, `codebuild`, `docker`, and `simulated`, which is in the closed set only so a test can register a simulated host: `ProviderKind.TestOnly` names it and `Config.Validate` refuses it at every site a file could name it (`node.provider`, `tiers[].provider(s)`, `tiers[].launch`, `nodes[].provider`), deliberately outside the per-tier and per-node rules `alloc.New` re-applies, so a catalogue built in code can still name it. The whole catalog is duplicated on every machine with nothing checking the copies agree; tiers and `nodes` are read at startup, so changing either needs a restart, while nodes register dynamically.
