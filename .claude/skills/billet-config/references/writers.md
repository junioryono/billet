# The commands that write billet.yaml

Part of the `billet-config` skill. Each rule is stated in full, with the measurement or incident behind it.

**Two commands write `/etc/billet/billet.yaml` under different rules, and each says which; a third writes a directory.** `billet init` generates a whole file, so it replaces one only where `initconfig.PlanReRun` proves the bytes are its own output (or under `--force`) and otherwise writes `<path>.new`. `billet github-app create --config` edits five scalars under `github:` in place, preserving comments, mode and owner, because the App identity is the one thing no generator can merge. `configEditRule` states the rule before a browser opens; `planConfigEdit` decides every failure (missing file, `github:` holding a list, an unwritable directory) before `github.Onboard`, using the real renderer against a probe identity, because the key is issued once and a failure after registration used to exit 0 with the key spent. Do not add another writer without choosing a rule. `billet init hybrid --out DIR` (`internal/initconfig/hybrid.go`, `internal/ops/setup/inithybrid.go`) never touches `/etc/billet`: it writes a Terraform root, an inventory with both hosts, `site.yml`, `requirements.yml` and `RUNBOOK.md` into a directory, replacing a file only when its first line carries `HybridMarker` and writing `<file>.new` beside an operator's own. Three renders of one generation: plan (placeholders `<terraform output NAME>`, each proved to name an output the root declares), prepare (`--terraform-output`, filled, controller still server-only and `billet_server_prepare_only: true` because the co-located ec2 node names a certificate bundle the role's `billet check` refuses to find missing), commission (`--commission --ami`). The local host's config carries no `server:` and no `github:`, and both absences are load-bearing. `--cache` adds the cloud half's store: `sites:` on the controller (the local place is `ceph`, the cloud one `ebs-s3`), `node.site` on each node, and on the commission render `node.ebs_s3` plus a `node.cache` HTTPS listener on the controller's address at the module's cache port — every one of which config validates at load (`node.cache` on EC2 needs `node.ebs_s3`, which needs `node.site`, whose declared store must be `ebs-s3`, and the guest endpoint must be https naming the same address and port). Both rendered configs are proved with `config.Parse` like every generation; `--instance-type TYPE=vcpu,memory,usd` declares a shape without an AWS fetch, which is what the gates use.

**`billet init` refuses what it cannot measure.** `--provider tart` is refused anywhere but Apple Silicon (the ceiling, the node name and the paths all come from the machine running it) and requires `--node-name`, because a stock Mac hostname is not a legal node name and sanitising one would name a host the operator never chose. It writes `untrusted_isolation` only for an untrusted generation, because `billet check` is fatal when it is named and softnet carries no setuid grant. A docker generation needs a non-default runner group and at least one exact workflow. `--emit ansible` prints the `billet_config` block instead of writing a file. `--join ADDR` is a transform of the generation (`initconfig.Join`), never a second generator: it drops `server`, `github` and `targets`, moves the measured `server.max_vcpu`/`max_memory` onto `node.max_vcpu`/`max_memory` (unset, the node contributes its whole machine against a ceiling sized for less), names `node.tls` under the config directory's `tls/`, skips the App-identity carry, proves the result with `config.Parse`, and prints the control plane's half; it is detected by presence (an empty `--join "$ADDR"` is refused, not a control plane), refused beside `--emit ansible`, and never replaces a config whose server state holds a live or unreadable deployment identity (`refuseServerRemoval`), because the generated state directory being the same one is exactly the case `refuseIdentityMove` lets through.
