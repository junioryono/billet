# Hosts, macOS and sites

Part of the `billet-config` skill. Each rule is stated in full, with the measurement or incident behind it.

**A contribution is detected only for a backend that runs work on the host.** `ProviderKind.RunsOnHost` is the one reader of that distinction and is keyed on the host backends, so a second remote backend nobody remembers to add is treated as remote. An `ec2` or `codebuild` node is an orchestrator: `node.max_vcpu`/`max_memory` are required, the overcommit warning is skipped, and those numbers are hard resource budgets rather than price budgets. Placement charges the first fitting declared shape rather than the smaller tier request, and every fallback is authorised atomically against the node and deployment ceilings before the request reaches AWS.

**The macOS limit is a default about a host somebody owns.** `DefaultMacOSVMLimit` is 2, pinned to Virtualization.framework's own refusal of a third guest rather than to a licence reading; `NodePolicy.MacOSLimit()` answers it for a host nothing was declared about, and the default is keyed on `RunsOnHost` because a CodeBuild `MAC_ARM` fleet runs under AWS's agreement (left alone it capped a five-instance fleet at two and blamed Apple). The limit is enforced against `Tier.GuestOS`, never a label. `MinMacOSGuestMemory` is 4GiB because the framework answers `LessThanMinimalResourcesError` below it and `provider.Spec` carries no guest OS, so config is the only layer that can hold the rule. `macos_vm_limit > 0` beside a `guest_os` allowlist excluding macOS is refused.

**A macOS tier pins a node unless it spans several backends.** Placement counts macOS guests per host whether or not the tier named one; the pin gave the load-time guard one host to check. `providers: [tart, codebuild]` is the shape a pin cannot express, so `validateUnpinnedMacOSTier` holds each backend's declared `nodes[]` policy to the pinned rules instead, `max_concurrent` defaults to and is bounded by what those hosts permit between them, and a reservation stays pinned. Per-entry `max_concurrent` ceilings may overlap on the same host, including entries expanded from `sizes`; runtime placement counts actual leases against the shared host limit. `billet init --provider tart` still chooses one preferred Xcode shape as its default, but gives every Linux rung the same whole usable ceiling. Every generator keeps individually fitting entries rather than summing sibling shapes; remote feasibility uses the first fitting charged shape, and local ceilings still reserve operating-system headroom.

**Storage is a property of the site.** `node.ceph` is a sibling of `node.firecracker`, required for firecracker and refused for every other backend. `siteAcceptsProvider` maps each store to the one backend that uses it; `validateCodeBuildNode` refuses a `codebuild` node that names a `site`, and `validateSites` refuses a sited tier that lists codebuild, because placement confines a sited tier to hosts at that site and a codebuild node declares none, so the tier advertises 0 while `billet check` reports healthy (measured on a live acceptance). The MIRROR of those refusals — a store block with no `node.cache` to serve it — is deliberately not a load refusal, because `billet decommission` and `billet init iam` both read a store block on a config whose listener has gone; it is `judgeNodeCache` in `internal/ops/host/cachecheck.go`, fatal for `node.ebs_s3` and reported for `node.ceph` (see `billet-storage-and-cache`).
