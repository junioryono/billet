# Firecracker

Part of the `billet-providers-local` skill. Each rule is stated in full, with the measurement or incident behind it.

**Every guest runs under the jailer**, chrooted, dropped to its own uid, in a cgroup, under seccomp, and the jailer names its chroot after the resolved `--exec-file`: the reference host installs `firecracker-v1.16.1` behind a stable symlink, so the jail is at `/srv/jailer/firecracker-v1.16.1/<id>/root`, and `List` enumerates every directory a jailer has built in rather than the path the config names, or every guest started before a version bump sits where the new process does not look.

**`jailer --daemonize` exits 0 for a VM that died on startup** (a pid file and a socket beside a VMM that exited 1), so `Launch` believes the VMM's own API and nothing else. The registration travels in MMDS v2, placed before `InstanceStart`, which is why the backend drives the API rather than a `--config-file` (a config file starts the machine as it is read). A unix socket address is a fixed-size field, so the API socket six components below the chroot base is refused at construction.

**The jailer creates a per-VM cgroup only when given a `--cgroup`, and the two cgroup forms cannot coexist on a host** (`CgroupMove … Resource busy`). It also enables a controller along the path (`+memory` in every ancestor's `cgroup.subtree_control`) only for the controllers its keys name (`write_values` in v1.16.1's `cgroup.rs`), so with `cpu.weight=100` alone a job's cgroup has no memory or io accounting. `WithJobAccounting` (what `node.monitoring` passes) adds `memory.max=max` and `io.weight=default 100` only for a controller `probeAccounting` proved at construction, because the jailer refuses a launch whose key names a file the kernel lacks, and `io.weight` exists only with blk-iocost; the proof for io is `io.weight` in a child that already has io enabled. A node that does not ask launches with the argv it always had. A node that asks on a host that did not prove both controllers does not start: `Node.open` refuses through `requireJobAccounting`, and `billet check` through the same `RequireJobAccounting` before it opens /dev/kvm, naming each controller as missing or could-not-tell (an unreadable `cgroup.controllers` or mount table refuses rather than reading as missing), because a controller never asked of the jailer is a group recorded unmeasured on every job. `billet images` builds its probe's provider through `NewProvider` and is not held to it. Since the refusal trusts the io probe, `io.weight` counts only as a regular file in a child whose `cgroup.type` is `domain` (or `domain threaded`): a directory of that name, a threaded child and a child gone since the listing each say nothing, the scan goes on past them, and io reads as missing only from a domain child still there without the file.

**There is no API action that kills a microVM.** The API has `FlushMetrics`, `InstanceStart` and `SendCtrlAltDel`, and a real guest ignored the last for twenty seconds. billet signals the VMM after proving the pid is still that microVM's (the `--id <jail id>` pair in `/proc/<pid>/cmdline`), re-checks with the pidfd held, sends SIGKILL and nothing gentler first, waits for the pid to stop being that microVM's, and treats an unreadable `/proc` entry as could-not-tell. SIGTERM does nothing: `--new-pid-ns` makes the VMM its namespace's init, Firecracker installs no SIGTERM handler, and the kernel drops a default-disposition signal sent to a namespace init from an ancestor namespace (measured 2026-09-30, v1.16.1 under the jailer: `SigCgt 0000000441801449`, `kill -TERM` ignored for over two minutes, `kill -KILL` immediate). billet passes `--new-pid-ns` because the jailer's documentation says the pid file is written only then, and a future version honouring its docs must not make "no pid file" read as "nothing running". Teardown never continues past a VMM it could not stop, because removing the jail removes the pid file that is the only handle for ever stopping it.

**The kernel is linked into each jail and stays root-owned.** Chowning the jail tree chowned the host's one kernel to an account every VMM shares; chown the chroot alone. The owner marker stays root-owned too, because `List` and `Find` trust it.

**Two defects survived every unit test and died on the first real launch**: `os.Stat().Sys()` holds a `*syscall.Stat_t`, not the structurally identical `*unix.Stat_t`, and the shutdown action above. That is the argument for `realfirecracker_test.go` existing at all. The generation's recorded kernel wins over the node's configuration (`kernelForGeneration`), a recorded name that is not a plain base name is refused because cluster metadata is writable by any client with pool access, and an unpaired generation falls back to `node.firecracker.kernel_image`.

**A restore loads paused, links its snapshot read-only, and is configured only by the jailer.** `Restore` takes `Launch`'s whole path (lease lock, lifecycle record, claimed jail, clone, unwind) and changes only the last step. The published `snapshot.state` and `snapshot.mem` are hard-linked into the chroot after it is chowned, as the kernel is, and are never chowned themselves, because every fork of a golden maps the one memory file and a jailed uid that owned it could rewrite what every later fork resumes from. `placeSnapshot` works through descriptors: the snapshots directory and the snapshot's own directory are opened without following a symlink and must be owned by the account billet runs as and writable by no one else, each file is opened for its identity alone through `regularfile.OpenIdentityAt` (O_PATH on Linux, so a device published by mistake is never opened) and judged through that descriptor (a regular file, mode 0444, owned by billet), then linked by `linkat` relative to the directories held, and the link is then proved to be that inode. Absent, a symlink, or the wrong shape is `errSnapshotNotPublished`; an inspection that failed for any other reason is returned without that sentinel, because could-not-tell is not no. A failure before the tap exists (the clone, the filesystem growth, building the jail, placing a snapshot) is marked `errNoTapMade`: the unwind first rewrites the jail's record without the tap (`forgetTap`), so a later Destroy retrying a failed discard has no tap to delete, then returns the name to the pool, and deletes no device this launch never made; `deleteTap` of an empty name does nothing. A link that would cross filesystems is refused rather than copied, since a copy writes the whole memory again and loses the page cache the forks share (measured on 2026-10-16, v1.16.1: ten forks of a 2 GiB guest were 227 MiB PSS together). `restore` always loads with `resume_vm: false`, then checks that the VMM reports `Paused` under the jail id, puts the lease's MMDS document, resumes and confirms `Running`, because the MMDS data store is `{}` after any load (measured). Nothing configures logging or metrics after the jailer's `--log-path`, because Firecracker answers both with 400 once a snapshot is loaded (measured). `network_overrides` points the restored guest at the tap billet allocated, and the `restore` primitive can also pass `vsock_override` for a socket of its own (both measured to work), though `Restore` sets no vsock yet because a cold launch configures none, and `clock_realtime` only corrects a guest that keeps time on `kvm-clock`: with the guest kernel's default `tsc` it was accepted and changed nothing (measured). A restore never grows the root disk, because the restored kernel has it mounted at its captured size. Writing a Full snapshot answers only after the memory is written and fsynced (4.0 s for 2 GiB), so `capture` runs that one call on `snapshotTimeout`, not `apiTimeout`. Restored forks keep the golden's MAC and address, so more than one on a shared bridge needs the per-workspace network namespaces of #510. `TestRealFirecrackerRestoresACapturedMicroVM` restores a captured guest through the real jailer (2026-10-16 on the reference node: 334 ms from request to running, 224 ms of it the clone).
