# Measured facts

Part of the `billet-guest-images` skill: what was measured, dated where it was recorded.

- Guest image built from GitHub's template: `contents: 53779M used, 22176M free of 81920M`, the same within a few megabytes on three builds (2026-09-28, image builder); usable space is about 0.927 of `SIZE_MB`. EC2 image 26.8GiB x64, 24.9GiB arm64.
- The first trials on the builder ran 22, 66, 71 and then all 84 template steps: a TLS stall to `azcliprod.blob.core.windows.net` that did not recur (the path MTU is a clean 1500), the pipx pin, and nspawn's `/tmp` tmpfs.
- A guest boots, takes its registration and runs a container in about ten seconds.
- `actions/runner` history: v2.285.3 published 2023-01-30, after v2.301.1 on 2023-01-19; one releases page is ~5MB and reaches back five years, so the walk bound is two pages.
- The macOS Xcode image is about 87GB to pull; `ubuntu-runner-arm64` 11.3GB compressed.
- `check-config.sh` exits 1 for host facts unrelated to the config; `grep | head -30` on its 2.9MB output exits 141.
- The shipped image's apt source names TWO HTTPS mirrors (`archive.ubuntu.com`, then `mirrors.edge.kernel.org`) with `Acquire::Retries 3` and 30-second timeouts in `/etc/apt/apt.conf.d/90billet-fetch`, written by `install_cloud_base` before GitHub's build; since the `ubuntu24/20260920.314` pin GitHub's `configure-apt.sh` writes `zz-retries` (one retry, 15-second timeouts on x64, for fast failover), which apt reads last, so those are the image's effective values from that step on and GitHub's apt tests assert them; GitHub's `configure-apt-sources.sh` rewrites only `azure.archive.ubuntu.com` URIs, so it leaves them as they are. Two URIs in one deb822 stanza are two repositories: apt fetches both index sets and takes a package from whichever lists the version (measured on a guest 2026-09-11 with the first URI black-holed and a 5 s timeout: strict update failed in 13 s naming the dead mirror, lenient update passed in 13 s, a package installed from the second in 4 s), while `mirror+file:` with a priority list did not finish a strict update in nine minutes under the same black hole. `Acquire::Retries` retries the failing URI and the timeout is per read, not per download. Measured 2026-09-11: every `archive.ubuntu.com` IPv4 address refused port 80 for hours from two unrelated networks (the reference deployment's site and AWS), two answered nothing on 443 either, and a job's apt stalled 30 s per attempt on one of those (`docs/reference/records/shared-uplink.md`).
- The first trial completion of every left-out component (#584, 2026-10-21, run 39521577087, built from #602) installed android-sdk 12.0 (cmdline-tools), codeql 2.27.2, firefox 158.0.1, google-chrome 156.0.8078.47 and microsoft-edge 155.0.4283.62, each passing GitHub's own tests on its own copy, and declared their space as 15.8, 3.6, 1.6, 2.8 and 2.2 GB (the peak growth plus a quarter); each component took 2 to 5 minutes, about 20 in all.
- The first real build with the notices step (#584, 2026-10-21, run 39570066996) fetched the GitHub Copilot CLI 1.0.98's `LICENSE.md` and the agentic workflow firewall's `LICENSE` for each of the three bundles the template installs (0.28.70, 0.28.71, 0.28.72) from raw.githubusercontent.com at their tags, found Miniconda's `/usr/share/miniconda/LICENSE.txt` and Packer's `/usr/local/bin/LICENSE.txt` where their downloads put them, and the gate passed counting 6 licenses.
- The first real build with the source manifest (#584, 2026-10-21, run 39574003320) listed 1106 packages installed with apt, 857 classified `gnu` (the rule errs towards it) and 14 of those with origin `none`: their versions came from sources the template removed again, so their source must be taken while the build runs. The gate's pass line names those sources since the next commit.
- The first full fetch of a guest image's corresponding source (#584, 2026-10-21, against build 39574003320's manifest, on the shared test host) verified 440 source packages and the kernel, 1342 files, 3,406,676,484 bytes, in 5:13 with a 47 MB resident set. The largest were mysql-8.0 (493 MB), linux (240 MB), five LLVM toolchains (137 to 227 MB each) and three GCCs (90 to 99 MB each). The 7 rows `unclassified` were six vendor sources with no copyright file in their debs (docker-ce, gh, kubectl, powershell, session-manager-plugin, adoptium-ca-certificates), each Apache-2.0 or MIT upstream.
- arm64's apt source is one site (2026-11-04): `https://ports.ubuntu.com/ubuntu-ports/` answers 200 for noble, `archive.ubuntu.com` answers 404 for `binary-arm64`, and `mirrors.edge.kernel.org` 404 for `ubuntu-ports`. GitHub's `configure-apt.sh` says the same of 24.04 arm64. The first arm64 guest build stopped at step 20 of 75 on the x64 list, with `Unable to locate package aria2`.
- The first arm64 guest kernel (2026-11-04, a c7g.metal, 64 vCPU) built from Firecracker v1.16.1's `microvm-kernel-ci-aarch64-6.1.config` over Linux 6.1.155 in 27 s real, a 19,921,408-byte `Image` with arm64's magic at offset 56, passing the gate on its first run: every required option present, no module, moby's checker exiting 0. The two kernels share the required lists and otherwise keep what each base chose, so they are not the same kernel on two machines. Beyond machine support, arm64 leaves off `RANDOMIZE_BASE`, `FORTIFY_SOURCE`, `SCHED_STACK_END_CHECK`, `BUG_ON_DATA_CORRUPTION`, `STRICT_DEVMEM`, `IKCONFIG`, `BLK_WBT`, `IPV6_SUBTREES` and `IPV6_SEG6_LWTUNNEL`, and turns on `FUSE_FS`, `LRU_GEN`, `HZ_100` and always-on transparent huge pages. What is proved of it is the gate and the workloads below, not parity.
- The first arm64 guest build (2026-11-04, the same host, 500 GiB gp3) ran all 75 steps of `plan-arm64.json` under nspawn in about 28 minutes and needed no difference beyond the apt source. Firefox 159.0.1's trial completion passed GitHub's two tests and measured 1,272,971,264 bytes. The builder's disk grew by about 33 GiB over the build, and the image packs to 12.5 GB.
- The first arm64 guest boot (2026-11-04, Firecracker v1.16.1 on a c7g.metal) reached the agent's refusal of contract 999 at 5.6 s, `BOOT VERIFIED`. Booted with the provider's arguments, `systemd.run` then ran dockerd on overlay2 and cgroup v2, pulled and ran arm64 containers, answered 200 on a published port, reached github.com from a container on a custom bridge and ran `docker build`, and the runner (2.337.0), billet, pwsh, Java and dotnet answered. `multipathd` fails at every boot on either machine, as both kernels leave `CONFIG_MD` out; nothing in a job uses it. The whole set packs to 7 rootfs parts (12.5 GB) and 3.4 GB of source, and the kernel built from the committed config is byte-for-byte that config: `make olddefconfig` over it is a no-op.
- `rbd image-meta list --format json` is not safe to parse (2026-11-04, a reference image): rbd does not escape a key, and that image holds one with a raw newline from a hand-run publish in August, so `jq` and Python's strict parser refuse the whole output. An image with no metadata prints zero bytes, not `{}`. The plain table survives both, which is why `ceph.GenerationArches` reads it, but what follows the newline there is a row of whatever the key said, so what decides a machine asks for its exact key: `ceph.GenerationArch` and `refuse_another_machine` use `image-meta get`.
