# Building the guest image

Part of the `billet-guest-images` skill. Each rule is stated in full, with the measurement or incident behind it.

**The guest image is GitHub's own build, run on Ubuntu's own base (#250).** GitHub does not publish the image its runners boot, only the Packer template that builds it for Azure. `scripts/runner-images/upstream/` vendors that tree at one commit (`COMMIT`, equal to the toolset pin), every file held to its git blob id and every directory to its tree id (`BLOBS`, `TREES`). `plan.json` is the template's provisioner list, derived by a test-side reader and pinned; `scripts/run-runner-images.sh` runs it step by step, with Packer's environment, through a target driver. The target is Ubuntu's pinned cloud root filesystem (`base.pin`, its SHA256SUMS signature checked against Canonical's key), booted with `systemd-nspawn --boot` inside the image file the build writes through. Everything billet does differently is one reviewed file, `differences.tsv`: a `skip`, or a `prepare:<name>` the runner performs just before a step, each with its reason; an entry naming a step the plan no longer has stops the build before anything runs. So parity holds by construction, and the gate checks GitHub's paths (`/usr/bin/yq`, apt's ruby), not billet's.

**The template drifts from what it downloads, and each drift is carried as a difference until the pin moves.** A pinned template installs whatever its scripts fetch today, so a script that built GitHub's July image can fail in September: `install-python.sh`'s unpinned `pip install pipx` took pipx 1.17.7, which needs packaging 26 and cannot replace Debian's 24.0, fixed upstream in be22fc2981aa after the pin, and carried as `prepare:pipx-pin` until the bump to the `ubuntu24/20260920.314` release (e7563390) took GitHub's own pin and retired it. Before adding a difference, look for GitHub's own fix after the pin (`gh api repos/actions/runner-images/compare/<pin>...main`) and copy its effect. Bumping `COMMIT` retires such entries; it moves the toolset pin with it, which the EC2 build also reads. Pin to an `ubuntu24/<date>.<n>` image release's own commit (it sits on a `releases/ubuntu24/<date>` branch, not on `main`), the newest GitHub no longer marks a prerelease. A bump also brings GitHub's new tests and new assumptions about Azure, each of which becomes a difference: that bump's `configure-environment.sh` runs `update-grub` under `bash -e` for ext4 root options GRUB passes on Azure, and the cloud root filesystem has no GRUB, so `prepare:grub-absent` installs a stand-in that answers the call and removes itself; its tests assert those options on `/proc/cmdline` and the root mount, which the build's container shows as the builder's, and that apt goes through GitHub's mirror list; each such test is marked `-Skip` by name through `skip_upstream_test`, which refuses unless exactly one test has that name, so a renamed test stops the build at its prepare. The tests do not run only at the end: a script's `invoke_tests <File>` runs that file mid-build, optionally filtered by a Pester FullName in its second argument (`install-apt-common.sh` runs all of `Apt`), so such a prepare goes on or before the first step that can select its test, which `TestEachPrepareIsInPlaceBeforeTheStepThatNeedsIt` holds. Diff `scripts/runner-images/upstream/` against the new commit and read every changed script and test for what it assumes, because only a real build would otherwise find it, an hour in. Upstream bugs GitHub ships are parity too: `install-bazel.sh` writes `USE_BAZEL_FALLBACK_VERSION=silent:` with no version, because it reads a `bazel --version` line Bazel 9 no longer prints, and the gate holds the variable, not a value GitHub's image lacks.

**The nspawn driver proves what it stops, three ways, before the workspace is touched.** `scripts/runner-images-nspawn.sh` starts the machine in a transient unit with `--keep-unit`, `DevicePolicy=closed` (only `/dev/net/tun` and terminals; with every capability and no user namespace a block class would be the builder's own disks), `--network-veth` and owned FORWARD rules on the exact link `ve-<machine>` (names of at most twelve characters, so the link name fits). A stop is proved by the unit inactive or failed, the machine unregistered (`No machine`), and the unit's `cgroup.events` saying `populated 0` under a cgroup v2 root it can read, a missing cgroup counting as gone only where its parent can be searched; anything it cannot read is "cannot tell", never stopped. Before clearing a workspace the build finds every machine by what it holds (machined's `RootDirectory` equal to this rootfs), stops it through the unit machined names, and refuses on a failed listing, an unreadable or empty property, or a machine gone before its root was read. The listing is split with parameter expansion and the recovery is called inside an `if`, where errexit does not reach, so every failure is returned explicitly. nspawn mounts its own tmpfs on `/tmp` capped at a tenth of memory, which the toolset's downloads fill; `SYSTEMD_NSPAWN_TMPFS_TMP=0` keeps the image's `/tmp`, and `start` proves it is not a tmpfs.

**The build runs on a fleet tier, not a hosted runner.** GitHub's image does not fit a hosted runner's disk, so `guest-image.yml` runs on `billet-image-builder-ubuntu-2404` (16 vCPU, 64GiB, 320GiB), a Firecracker guest with no `/dev/kvm`: nspawn needs none, and the in-CI Firecracker boot is gone. Every generation is still booted by `images pull --verify` before it can become `@verified`. The EC2 AMI still builds from the declaration with the shared toolcache installers (`install-toolcache.sh`, `billet_tc_run`, `BILLET_TC_ARCH`, `.billet-unpublished`); see `billet-shell-gates` for that seam.

**The build job checks out the release the stable channel names, never `main`.** An image that reaches the guest channel fans out to every deployment on its next refresh, and `main`, gated as it is, is not a tree a fleet should inherit unreviewed at 04:17 on a Monday. So `guest-image.yml`'s build job resolves the stable channel (the same pointer deployments follow) and builds that tree; a tag named by hand must be an immutable, published, non-prerelease release; a dispatch with `source=main` builds for testing and cannot publish. The workflow file itself stays on `main`, because every deployed binary verifies the channel's signature against this workflow running on `refs/heads/main` (`imagesource.PublishRef`); only the tree the build checks out moves. That leaves YAML on `main` driving scripts from an older tree, so the seam between them is frozen by a test in `scripts/scripts_test.go` rather than left to drift. The dated guest tag points at the source release's commit, the provenance the closed manifest schema cannot carry. Never recreate a rolling guest release: its tag and assets freeze on first publication, and the publisher creates the dated tag before `gh release create --verify-tag` so a conflicting tag fails rather than relabelling the build.

**The guest carries billet itself, for the build caches (#226).** `install_guest_billet` builds `/opt/billet/bin/billet` from the checked-out tree with the newest go the image's toolcache installed, because the hosted build runner's own go is removed to make room and the workflow's seam with the release tree is frozen, and installs `/opt/billet/bin/bazel-credential-helper` beside it. The agent reads the MMDS leaf `guest-caches` (`go`, `go-test-results`, `bazel`, `git`, derived by the node from the tier's cache block and sent only beside a cache session) and, only when the image carries billet, configures each cache in the block between `BILLET_GUEST_CACHES_BEGIN`/`END`, which `scripts/guest_agent_caches_test.go` executes: `GOCACHEPROG=/opt/billet/bin/billet cache gocacheprog` and `GOFLAGS=-count=1` unless test results are shared, `/etc/bazel.bazelrc` with the remote cache and the credential helper (never the bearer), and `/etc/gitconfig` with the `insteadOf` rewrite of `https://github.com/`, an identity `pushInsteadOf`, and `billet cache git-credential` as the node's credential helper. The container hook runs where it has something to add: the docker shim only under interception (`BILLET_CONTAINER_SHIM`), and under the go cache a read-only mount of the binary and the helper's variables, where the job's own env wins. `check-guest-image.sh` refuses an image missing the binary, the wrapper or the agent's wiring. No `GuestContract` bump: every piece is additive, and an older image simply builds cold.
