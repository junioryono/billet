**A dry run of the preparation is answered by the executable a converge would be answered by.** `prepare-exclusion.yml` under `--check` runs `prepare --dry-run --json` through the managed binary, or, for a guard directory beside a managed binary that is absent or answers "unknown command", through the executable the guard records after `guard-fallback.yml` verified it (the same import, a second time, under `billet_exclusion_dry_via_record`), and refuses an unpublished guard, an untrusted record and a pre-R recorded executable as the converge does; without that a dry run read a guard carrying a transaction pointer as no claim and planned a binary change over an interrupted bootstrap (round 3, 2026-09-10). EVERY ANSWER OF THE PROTOCOL IS READ THROUGH `junioryono.billet.from_json_strict` (`plugins/filter/strict_json.py`, proved by `tests/strict_json_check.py`, run by the gate), never `from_json`, because `from_json` keeps the last of a repeated member and an answer ending `"pointer": true, "pointer": false` read as settled where the Go decoder refuses it; the parser's `id`, `token`, `reason`, `why`, the record's paths and `pointer_target` are required `is string` before their pattern, because a 32-digit number matched the coerced pattern, was stored as a number, and the rescue's `length` over it ended the cleanup diagnostic; and `record_error` is read by presence (present: a non-empty string; absent: the healthy members), with `pointer_problem` and `pointer_target` typed when present (round 5, 2026-09-10). THE PRE-R OBSERVATION REQUIRES AN EXIT THE EXECUTABLE CHOSE, defined, POSITIVE and not the bound's (`rc > 0 and rc not in [124, 137]`; a kill that reaches `timeout`'s own process group is a NEGATIVE status in Ansible, because GNU timeout signals its group and SIGKILL cannot be ignored, and the gate's `BILLET_GATE_PRE_R_IGNORE_TERM=1` makes the fake reach it) before the diagnostic is matched, at all four sites (the parser, the dry run's two reads, the closing recheck), because an executable that prints "unknown command" and then hangs exits 124 under `timeout` and would otherwise have selected the unheld legacy protocol (the gate's `BILLET_GATE_PRE_R_HANG=<cmd|all>` makes the pre-R fake do that). EVERY GUARD COMMAND CARRIES `expand_argument_vars: false`, because `ansible.builtin.command` expands environment variables inside `argv` by default (ansible-core 2.21), so a holder spelled `ci-${USER}`, which the command accepts as a name, was published as `ci-root` and the parser refused the answer's holder before the token was saved, stranding the guard (round 15; the order test requires the parameter of all ten commands, the gate's `b1c` publishes such a holder as spelled), and the collection's floor in `meta/runtime.yml` is therefore `>=2.16.0`, which the order test pins (round 16).
