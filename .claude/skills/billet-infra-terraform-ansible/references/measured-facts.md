# Measured facts

Part of the `billet-infra-terraform-ansible` skill: what was measured, dated where it was recorded.

- `DeleteProject` succeeds during a live build; the build runs to completion and `BatchGetBuilds` keeps answering for it.
- A lexical time comparison in the destroy guard was seven hours wrong on a laptop in a non-UTC zone.
- Two terraform modules were added and went green through every gate without being validated, linted or scanned, because the module list was a constant.
- `tflint --config` with a relative path: silently linted with bundled rules only.
- Terraform 1.14.0 and 1.15.9 on Linux and 1.14.1 on macOS (2026-10-17), each behaving the same: with `TF_PLUGIN_CACHE_DIR` set, an init takes a provider from the cache only when the lock file holds this platform's h1 checksum. With another platform's h1 and the zip hashes it downloads and adds this platform's h1; with no lock it downloads too, unless `TF_PLUGIN_CACHE_MAY_BREAK_DEPENDENCY_LOCK_FILE=true`. A root with no lock resolves the newest provider (cloudflare 5.28.0 against the lock's 5.24.0 that day), and its init fills the cache, so a second root given its lock takes the cached copy. A cached binary altered after the fact is caught by a locked init, which downloads the signed package again and replaces it in the cache; a root with no lock always installs a signed download. The aws provider's linux_amd64 zip for 6.62.0 is 194 MB; the reference node fetched it in 11.6 s on a quiet line.
- trivy 0.74 needs `GOEXPERIMENT=jsonv2` to install under Go 1.26.
- The bridge's dnsmasq at its defaults holds 150 names and forwards 150 queries at once; a fleet's guests ask for the same few hundred names thousands of times an hour, so the role sets `billet_guest_dns_cache_size: 10000` (the largest dnsmasq holds without warning) and `billet_guest_dns_forward_max: 1000` (2026-09-11). The guard table drops every guest-to-host packet but DHCP, DNS and the cache endpoint, so a guest's `ping` to its gateway fails on a healthy host and proves nothing.
- A compute host behind a residential gateway shares that gateway's NAT table with everything else at the site. For the reference deployment's gateway class its users REPORT a cap of 8192 sessions on older firmware and 32767 on newer, with new connections dropped near it; the deployment's own session count was not read (2026-09-11, `docs/reference/records/shared-uplink.md`), so the cap is a reported number and the saturation a hypothesis consistent with the symptoms, not a measurement.
- cephadm's default image is a floating tag, `quay.io/ceph/ceph:v19`. On 2026-11-08 it was 19.2.7, against Ubuntu 24.04's ceph-common 19.2.3, which could not parse the admin key 19.2.7 wrote ("error setting modifier for [client.admin] type=key ... Malformed input"), so every `ceph` and `rbd` on the host failed to connect. The role bootstraps with the tag of the installed client's own release unless an image is named (#816).
- `ceph orch device ls --format json` on Ceph 19.2.3 (2026-11-08) is a list of hosts, each with its `devices`, not a flat list of devices, and on a fresh cluster it lists a disk only once cephadm has inventoried it, so the role waits for the named disk to appear (#816).
- `ceph config set global osd_pool_default_size 1` after a cephadm bootstrap on one host (Ceph 19.2.3, 2026-11-09): the monitor and one of the two managers read 1 at once, and the other manager kept 2 and reported `TOO_FEW_OSDS` until `ceph orch restart mgr`, after which the cluster was `HEALTH_OK`. The pool host prelude restarts them.
- The x86_64 guest image of 2026-11-08 (15.8 GB of parts) peaked at 97 GB of staging during a pull: its parts, the assembled archive and the decompressed image at once. A 40 GB staging disk filled and the pull failed (2026-11-09, the pool host prelude's run on a nested-virtualisation `m8i.2xlarge`).
