# The host role

Part of the `billet-infra-terraform-ansible` skill. Each rule is stated in full, with the measurement or incident behind it.

**The host role owns the fail-closed ledger mount and the upgrade transaction.** With `billet_ledger_volume_id` set to the module's output, the role resolves the volume by its NVMe identity (never a filesystem UUID, which a snapshot clone duplicates), formats only when blank, mounts through a systemd unit with no `nofail`, adds `Requires=` and `RequiresMountsFor=` to `billet-server.service`, proves the state directory is served by the expected volume and refuses to shadow a root-disk ledger. Without that, a failed mount lets the controller start on the root disk with a new ledger, identity and CA. `billet_server_prepare_only: true` is the stopping point for moving a control plane: it mounts and proves the volume and leaves both services installed, disabled and refused by their own units, so nothing can mint an identity until the old host's state is copied in; both are held because whichever role starts first mints the identity. Do not `systemctl mask` here, because the role renders the unit at the path masking would write. The upgrade transaction is in `billet-releases-and-upgrades`.

**The role gives way to a rollout, and renders the timers that carry one out.** `billet_automatic_updates` (default true) installs `billet-upgrade.{service,timer}` on a host whose server should run and `billet-images.{service,timer}` on a firecracker host, and enables the timers (installed disabled when false); `tests/unit-parity.yml` compares their directives with `deploy/`. `prepare-exclusion.yml` first clears per-inclusion settlement and answerer facts with a connection-free `set_fact`, retaining a held run's holder, public id and learned claim/recovery facts so reinclusion validates the same guard. The preparation (the role's second task, and every fleet play's first pre-task) refuses a converge when `/var/lib/billet/upgrades/active` is a symlink, which is `billet host-upgrade`'s claim, naming `--status` and `--resume`, classifies a regular file as the pre-R role's claim by its own stat, and otherwise is a THIN CALLER of `billet converge-guard prepare --holder H --json`, TWICE, through one parser (`guard-answer.yml`, every member judged by name, the token kept in a fact no report prints): the first call `--validate` (acquire or validate, before anything is decided or staged), then the staging under the guard, then the second call with the intent (`--candidate <staged> [--allow-downgrade]`, `--no-change`, or `--recovery` when the first answer carried a pointer), then `settle --token` exactly when this inclusion acquired; a refusal between the acquisition and the settlement runs the block's rescue, `release --holder H --cleanup --token T`, which the command refuses for a settled guard, a wrong token or a pointer. Which executable answers: the managed binary; when it predates the guard or is absent and a guard exists, the executable the record names after the `guard_fallback` module proved it (the five members plus `id`, `token` and `preparing`, typed when present); on a bootstrap or a pre-R host with a candidate, the STAGED candidate after the staging (`--expect-bootstrap` on a bootstrap). Every call is bounded by platform (`timeout -k 10` on Linux, the task's `async` bound with no escalation on a Mac) and the calls that carry the token run under `no_log`; a later inclusion sends `--expect-id`; a second answer must carry the pointer the intent was declared from (`--recovery` exactly when the first answer carried one) and, with it, the target the first answer named, and the interruption facts are the first answer's alone, or a second answer that cleared the pointer would send the ordinary path over the recovery directory's material before the pointer refused its publication; check mode runs `prepare --dry-run` before any shape dispatch and then the read-only staging. `stage-candidate.yml` judges nothing about the guard: the channel resolves into the private `billet_resolved_version` (the public pin is never assigned by a task), the recovery directory is allocated by `allocate-recovery.yml`, one `mkdir -m 0700` without `-p` inside a five-attempt loop that draws its suffix from `billet_recovery_dir_suffix_command` under `sh -c` on every attempt (`file: state=directory` accepts an existing directory, so two stagers would share one journal), and the candidate is copied into it; the floor, the downgrade and the intent against the record are the command's, under the lock. The role's transaction still refuses a PostgreSQL host, and a PostgreSQL controller whose binary predates the guard is refused rather than run under the legacy protocol; billet's timer upgrades that host. The claim under the guard is the pointer `active/recovery` (`ln -sT`, outside the transaction block, proved by `readlink`), every `slurp` of `active`'s content is gated by a legacy shape, recovery requires an owned claim by shape before it stops anything, and the finalizer removes the pointer alone and sets the shape back to `guard`. `converge-guard-check.sh` is the gate: THE REAL BINARY AT ITS REAL PATHS inside a per-case mount namespace (`sudo -n unshare -m --propagation private`, a tmpfs backing overlays over `/usr/bin` and `/var/lib`; `plant_root` binds a directory from that tmpfs at `/var/lib/billet` before planting its contents, so the directory and its locks share `st_dev` even when the overlay has mixed filesystems without xino; cases that start without the parent keep it absent, and the diagnostic copy includes the bind-mounted state; nothing outside the namespace sees these changes), the managed binary and every staged candidate RECORDING WRAPPERS around backing binaries built once with `-tags billetgatecrash` and release version stamps (a wrapper logs its argv and invocation number, fires the case's hook `BILLET_GATE_HOOK=<cmd>:<n>:<script>` before its own invocation, runs its backing binary exactly once, captures the real answer privately and prints it, a substitute `BILLET_GATE_ANSWER=<cmd>:<n>:<file>`, or nothing `BILLET_GATE_DROP_ANSWER`; `BILLET_GATE_FAIL=<cmd>:refuse|hang|crash:<seam spec>`), the pre-R and hang fakes as scripts, the unescalated cases run inside their namespace as the gate's invoker through `setpriv`, the simulated-darwin cases on the fake with the role's path overrides and the committed corpus, every assertion from the state the namespace dumps after the play, the captured token grepped for in every case's output; the local container needs `--cap-add SYS_ADMIN --security-opt apparmor=unconfined`; `billet_upgrade_root`, `billet_managed_binary` and `billet_upgrade_root_owner_uid` exist for it. The gate in `host-upgrade-order.yml` counts `billet_enable_server` occurrences in `services.yml`, so a new task gates on `billet_server_should_run`, never on `billet_enable_server`. `tasks/backup.yml` renders and enables `billet-backup.{service,timer}` under that predicate and `billet_backup_timer`, and refuses an effective drop-in on the backup unit the way `account.yml` refuses one on the services (asked of systemd through `DropInPaths` after a reload, status judged), because the ledger fence is rendered into the unit; a consumer that carried the fence as a drop-in removes it before converging with this role.

**The role keeps needrestart away from billet's services.** `tasks/needrestart.yml`, imported in the ordinary block after every refusal and before `account.yml` (whose apt install is itself an upgrade needrestart answers), stats `billet_needrestart_binary` and `billet_needrestart_dir` and, where either exists, creates `conf.d` and renders `needrestart-billet.conf.j2` to `90-billet.conf`, root:root 0644; the template is byte-for-byte `deploy/needrestart.conf` (`deploy/needrestart_test.go` compares them and refuses a Jinja delimiter in it), so a host that installed the package and was then converged sees no change. Unlike the package the role owns the file and puts back an edit. It is skipped on the retained retirement route (`when: not billet_retirement_node_ordinary | bool`), whose writes are admitted one destination at a time; adding it there needs the operation document and the drift catalog. Its register and the two defaults are bound in `retained-drift.json`'s `definitions`, which any new register or default anywhere in the role changes. `tests/needrestart-check.yml` (`make needrestart-check`, the `shape` group, escalated) drives the tasks against a temporary tree.

**A converge restarts services, so never drive one from a runner billet manages.** The drain destroys the jobs on that host, including the one running the playbook. The role refuses by default; `billet_allow_converge_from_billet_runner` exists for an operator who has established the runner is backed by another host.

**The ordinary node restart is requested, never awaited.** `tasks/node-restart.yml` (imported by services.yml under the name "Restart the billet node after non-binary inputs change", whose `when` the gates pin as text) records `MainPID`, runs `systemctl restart --no-block billet-node.service`, and polls `systemctl show` in short `until` steps every `billet_node_restart_poll_interval` seconds until a deadline `billet_node_restart_wait` (3600) after the request on the controller's clock (`'%s' | strftime | int`, epoch seconds: `now(utc=true).timestamp()` reads a naive UTC datetime as local time and moves an hour across a daylight-saving change, measured 2026-09-30 on a Pacific-time Mac as hours off `date +%s`; the retries only cap the loop), proving active, running, an empty `Job=` and a MainPID other than the recorded one (a node that was not running recorded 0; a new process beside a queued job may predate the request). A `systemd_service: state=restarted` held one SSH session for the whole drain, which has no bound: on the reference deployment on 2026-09-30 the session closed 34 minutes in, the converge failed as unreachable and released its guard, and systemd finished the restart afterwards. Past the deadline the last read decides the words, naming `systemctl show billet-node -p ActiveState,SubState,MainPID` in each: a read without exactly the four properties is could-not-tell, the old process still in charge (deactivating, or its MainPID still there) or an active node with a job queued is "still draining", anything else (failed, a new process never ready) "did not come back"; a poll that lost the connection (`ignore_unreachable`) fails as could-not-tell. On ansible-core 2.21 `retries: N` runs N+1 attempts, sleeping between them without subtracting run time, and an exhausted `until` under `failed_when: false` is not failed (measured 2026-09-30), so the loop ends on the deadline rather than a count and the judgement is the tasks after the poll. `tests/node-restart-check.yml` (`make node-restart-check`, the `shape` group) drives it against a scripted systemctl that refuses a waiting restart; the whole-role fake rotates a restarted unit between two live pids (`BILLET_GATE_SERVICE_PID_NEXT`), because the proof needs a new one. The network drain's stop and the transaction's stops still wait on the drain over one session.

**The role's variables that must be supplied, never guessed.** `billet_binary_src` or `billet_version` (with `billet_release_url_base` and the channel); `billet_config` (what `billet init --emit ansible` prints); `billet_github_private_key_src` (never replaced implicitly; the role refuses a converge when the managed key path holds nothing) and `billet_github_target_key_srcs` (target name to a local key file for every further `billet_config.targets` entry, installed at `/etc/billet/app-private-key-<name>.pem` under the same owned-versus-foreign rule, computed as one `billet_github_target_keys` list in `tasks/main.yml` and looped in `tasks/account.yml`; `tests/key-policy-check.sh` runs the target cases too); capacity, network ranges, `billet_networks` and guest DNS; `billet_ceph_*` (bootstrap is destructive and never inferred; every disk it may consume is named); `billet_firecracker_version` and checksums. The role installs nothing it cannot verify and refuses to start either service before `billet check` passes.

**The host role migrates a node's endpoint through billet's own commands, and infers nothing from the configurations.** `endpoint-decision.yml` (imported by `account.yml` before the render), `endpoint-migration.yml` (by `services.yml` in place of the ordinary node restart) and `endpoint-receipt.yml` (after the node's start) call `billet node migrate-endpoint --dry-run`, `migrate-endpoint`, `rollout registration` (delegated to `billet_migration_controller`) and `node receipt`; the answers go through `endpoint-answer.yml`, `registration-answer.yml` and `receipt-answer.yml`, one strict parser each, in the shape `guard-answer.yml` set. A first start, a removed node, an absent configuration and a leftover node beside a server-only installation are the command's to report. The executable is `billet_exclusion_answerer`, which `prepare-exclusion.yml` sets in every mode (empty under the legacy shape in a real converge, a pre-R managed binary with no candidate, or no billet; check-mode preparation may publish a non-empty legacy answerer), and without one the role compares endpoints through `junioryono.billet.endpoint_change` (`tests/endpoint_change_check.py`) and refuses a change. The order test pins the decision before the staging and the render, the migration before the restart, the receipt after the start, and the restart's gate on `billet_endpoint_migrated`. A COMMA INSIDE A FLOW-SEQUENCE `argv` IS AN ITEM SEPARATOR: `argv: [systemctl, show, billet-node.service, --property=LoadState,ActiveState,MainPID]` handed systemd `--property=LoadState` and two unit names, which answered `LoadState=not-found` three times and refused every fresh-machine dry run (measured 2026-09-11 on the fleet's guest); quote any argument that carries a comma, and assert the exact argv in the gate (`converge-guard-check.sh`'s E7 does). ANSIBLE RESOLVES `delegate_to` BEFORE IT EVALUATES `when` (measured 2026-09-11: "Empty hostname produced from delegate_to" on a task the block's `when` skipped), so a delegation must template to a host even when the task is skipped; `endpoint-migration.yml` defaults it to `inventory_hostname` and asserts the controller before it. AN ASSERT'S `fail_msg` IS RENDERED BEFORE THE ASSERTION DECIDES, so a member the failing branch has and the passing branch lacks needs a default in the message (the guard's `next`, the migration's `state`). THE HOLDER GRAMMAR HAS ONE PYTHON TWIN, `plugins/module_utils/holder.py`, exposed to templates as `junioryono.billet.valid_holder` (`plugins/filter/holder.py`, a re-export) and imported by `guard_fallback.py` for a record's `taken_over_from`, held to `tests/fixtures/holder-vectors.json`, which `checkHolder`'s Go test writes (`holder_check.py` imports both by the collection's dotted name and requires the filter to expose the shared function); a regular expression counted characters where the command counts bytes and admitted U+FFFD and the C1 controls (round 3 of commit 4c), and the fallback reader's own `startswith("C")` refused a format character such as U+200B that Go's `IsControl` admits, so a chain Go wrote blocked the fallback (commit 5b's first review). THE ROLE'S OUTER BOUNDS around the endpoint commands are sums over the phases and observations the commands may make, from role vars in `vars/main.yml` that `TestTheRoleMirrorsTheEndpointCommandsPhaseBudgets` holds to the Go constants.

**The scenario tests are make targets, each one converging the role in a specific state.** `host-upgrade-order` (drain, migration, image, restart and rollback ordering), `unit-parity` (packaged units and the role's templates agree), `ledger-mount-render`, `postgres-profile`, `alert-lifecycle`, `development-check-mode`, `emitted-block-check` (a block `billet init --emit ansible` generated converges), `example-check`, `key-policy-check`, `converge-guard-check` (the guard, and the exclusion's whole preparation against fakes, escalated), `ssh-access-check` (the ssh_access refusals and install against a fake sshd), `cloudflared-connector-check` and `warp-connector-check` (the connector roles against fakes), `fleet-playbook-check` (the shipped playbook's shape and guard), `release-fetch-check`, `firecracker-example-check`, `fetch-retry-check` (every `get_url`/`uri` in both roles carries `timeout`, `register`, `until`, `retries` and `delay`, driven by the `billet_fetch_*` and `billet_development_fetch_*` defaults; one stalled connection once failed a converge behind an approval gate), `hybrid-emission-check` (the inventory and playbook `billet init hybrid` writes pass Ansible's syntax check and `ansible-inventory --list` proves the tier catalogue crossed the anchor onto both hosts), `host-fresh-check` (the documented first step against a fresh machine), `needrestart-check` (the needrestart exclusion, absent, installed, idempotent and restored). CI's `host-lifecycle` job runs them all; `host-upgrade-live.sh` is the destructive one. CI builds billet once per run for every group (the `gate-binaries` job, uploaded as a one-run artifact): `tests/gate-binaries.sh` is the one definition of the guard gate's four stamped `billetgatecrash` binaries, which `converge-guard-check.sh` builds itself on a laptop or, given `BILLET_GATE_PREBUILT`, verifies (the version each reports and the tag, never the VCS stamp, which does not follow a git worktree) and copies; the ordinary CLI reaches the other gates through `BILLET_EMITTED_BLOCK_BINARY` and `BILLET_HYBRID_CHECK_BINARY`.

**The collection's `galaxy.yml` carries the release version.** A collection installed from a Git tag reports the version in that file, so the cut-release workflow rewrites it.

**Every JSON a role consumes has fixtures written by the Go test that produces it.** `tests/fixtures/<command>/*.json` for `guard-status`, `guard-prepare`, `node-migrate-endpoint`, `rollout-registration`, `node-receipt`, `rollout-status` and `release-inspect` are the commands' own answers over planted shapes (cmd/billet's `TestThe*FixturesAreTheCommandsOwn`), with paths, identifiers, digests and times spelled as the packaged host's; `fixtureSetIs` refuses a committed file no producer writes and a producer no file matches. A gate's fake answers from those files and never from a shape written by hand; a role-side parser is written against the complete object of every fixture, nullability per branch included (a migration's `unchanged` has a null `endpoint` only under `record: none` or `unread`, a `reported` a null `to` only beside `node_removed: true`).
