# Measured facts

Part of the `billet-state` skill: what was measured, dated where it was recorded.

- `SQLITE_BUSY_SNAPSHOT` (517) appeared the moment operator commands were admitted alongside the plane, with deferred transactions.
- A real promotion (2026-09-04, `scripts/gates/dist.sh && scripts/promotion-rehearsal.sh`): with `tcp_keepalives_idle=10`, `_interval=5`, `_count=3` on PostgreSQL 18, the standby was promoted 21 seconds after the leader was partitioned, the node re-registered with it 62 seconds after, and the healed old leader stopped on `ErrLeadershipLost`, was restarted by systemd and stood by within 10 seconds. Under `controllers: active-passive` the first controller logs `standing by` and then `promoted to`, never `claimed`.

- The commit is the write (2026-10-25, `docs/reference/records/ledger-write-budget.md`). `fdatasync` took 3.6 ms at the median on an EBS gp3 volume and 0.14 ms on an instance-store NVMe. One renewal held the writer slot 3.8 to 4.1 ms on SQLite on gp3, 3.0 to 3.8 ms on a PostgreSQL 18 on its own gp3 machine, and 0.09 ms of billet's own work on tmpfs. A laptop's macOS `fsync` does not wait for the disk, so benchmarks that decide a budget run on the Linux test host.
- A packed list cut one record off the front, with the rest carried, copies the string once a record. For 256 renewals of 83 characters (`HeartbeatLeases`) that took 30 ms a statement in SQLite's command line, against 3.5 ms when the string is cut in halves (2026-10-25). The halving term names its CTE once, joined to two rows, because PostgreSQL refuses a recursive term that names the query twice.
- SQLite's `length()` stops at a NUL, so a statement that measures a packed string has to refuse one (`length(s || 'x') = length(s) + 1`), or a split by length never shrinks; PostgreSQL refuses a NUL or invalid UTF-8 in a text parameter as an error, which ends the transaction (2026-10-25).
