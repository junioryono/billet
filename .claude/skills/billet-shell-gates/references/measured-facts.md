# Measured facts

Part of the `billet-shell-gates` skill: what was measured, dated where it was recorded.

- Canonical's plain-HTTP mirrors (`archive.ubuntu.com`, `security.ubuntu.com`, their IPs 91.189.91.82, 91.189.92.23, 185.125.190.82) answered nothing on port 80 from AWS us-west-2, from the fleet's Firecracker guests and from a laptop for hours on 2026-09-11, while the same names answered over HTTPS in under two seconds and other HTTP hosts answered at once; every gate that ran apt failed (`Connection failed`, a `Network is unreachable` for the AAAA records a guest without an IPv6 route tries first). CI's own apt runs over HTTPS from TWO SOURCES since: the runner's and every gate container's `ubuntu.sources` get the amd64 `URIs:` line rewritten to `https://archive.ubuntu.com/ubuntu/ https://mirrors.edge.kernel.org/ubuntu/` before `apt-get update` (arm64's `ports.ubuntu.com` line to its HTTPS spelling alone: kernel.org mirrors no `ubuntu-ports`, checked 2026-09-11), matched as exact lines (`^URIs: http://archive[.]ubuntu[.]com/ubuntu/$`, dots escaped, both anchors) in the runner's steps and in every gate container, so a line with another URI or a trailing space is left alone, and every container started from `ubuntu:24.04`, which carries no CA bundle, gets the host's `/etc/ssl/certs/ca-certificates.crt` bind-mounted read-only at `/usr/local/share/billet-host-ca.crt` and named to apt with `Acquire::https::CAInfo`, the two restore wrappers included; never mounted OVER the container's own bundle path, because `ca-certificates`' postinst rewrites that file and a read-only mount there fails the install of every package that pulls it in (`dpkg: error processing package ca-certificates (--configure)`, measured 2026-09-11 in the PostgreSQL rehearsal). In a standalone script an `update` and its index gate are two lines under `set -e` (a failing left side of `&&` is not a failure `errexit` sees); inside a `sh -c` entrypoint the whole `update && ls && install` chain is one command whose first failure is the container's exit status. Two URIs are two repositories to apt (measured on a fleet guest with the first black-holed and a 5 s timeout: both index sets fetched, a strict update failing in 13 s naming the dead one, a lenient one passing in 13 s, an install from the second in 4 s; `mirror+file:` did not finish a strict update in nine minutes), so `Error-Mode=any` is gone from the gates and each update is followed by `ls /var/lib/apt/lists/*InRelease`, which fails only when NO index arrived, the black-holed-proxy case the strict mode was for. The guest image's own sources are PR #115's.
- A fresh `ubuntu:24.04` container's `apt-get update` against a mid-sync archive mirror (2026-09-05): eighteen minutes of silence inside a thirty-minute job, then killed with nothing to read; the run that did finish said `File has unexpected size ... Mirror sync in progress?` after ten. Every apt call in the rehearsal and lifecycle gates (`restore-rehearsal.sh`, `postgres-restore-rehearsal.sh`, `systemd-lifecycle.sh`, `test-package-lifecycle.sh`, `rehearsal-lib.sh`, `test-systemd-lifecycle.sh`) is now `timeout -v -k 10 300 apt-get -o Acquire::Retries=3 -o Acquire::http::Timeout=30` (the `https` method inherits the `http` timeout), and the two container entrypoint strings keep apt's stderr so `docker logs` carries the reason; the guest image and kernel builds are not gates and keep bare apt. The systemd readiness loops wait 720s, longer than the two bounded calls they follow, and stop at once on a container that has exited. Against a black-holed proxy, `apt-get update` without `Error-Mode=any` exited 0 on "Some index files failed to download"; with it, 100.
- `! cmd | grep -q .` under `set -e`: the script continued and exited 0 (`/bin/sh`).
- `;` chain with a failing `sha256sum -c`: exit 0 under dash in `ubuntu:24.04`.
- `grep -q` early match under `pipefail`: exit 141; late match 0; no match 1.
- `grep | head -30` on 2.9MB: exit 141; `grep | head -20` on 3.2MB: exit 141.
- Base64 payload gzipped: 27235 bytes; heredoc payload: 11327; limit 16384; a 32652-byte CA bundle takes the payload to 24239, hence the 8 KiB bound.
