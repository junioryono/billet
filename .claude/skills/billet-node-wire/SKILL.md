# The node wire

## What this area is

A node dials out and never listens. `internal/nodeapi` declares the request and response types, the command kinds (`CommandLaunch`, `CommandDestroy`, `CommandSweep`, `CommandTend`, `CommandUpgrade`, `CommandInventory`) and the version range. `internal/nodeclient` is the node side (`Register`, `Poll`, `Report`, `Withdraw`, the lease calls, `Renew`, enrollment; `loop.go` drives `Poll → execute → Report` one command at a time). `internal/nodeplane` is the plane side: `Handler` (mTLS routes under `/v1/register` and `/v1/nodes/{node}/…`), `BootstrapHandler` (`/v1/ca` and `/v1/enroll`, no client certificate), `Plane` (dispatch, registrations, the barrier loop), and `Runner`, which implements `server.Runner` so the listener cannot tell whether compute is a goroutine away or a continent away. `cmd/billet/handshakelistener.go` bounds connections on the real wire.

## Rules

**The wire is a range, and the bridge runs one way.** `nodeapi.MinVersion` is 12 and `nodeapi.Version` is 20; registration negotiates the highest both speak (`Negotiate`) and records it on the node's row, which `billet status` reports under `protocol`. The plane decodes bodies with `DisallowUnknownFields` while a node decodes responses leniently, so an old node's registration is a subset of a new plane's struct while a new node's body hits an old plane's strict decoder before any version check runs. Upgrade the server first; the reverse is refused, and the node adds its own range to every registration failure so the operator is not left with `json: unknown field "min_version"`.

**`MinVersion` is a promise about meaning, not about whether fields parse.** 11 and below decided a pooled runner's trust from the assignment that caused it to launch, which GitHub may reassign; lowering the floor to make an old fleet connect is offering to be wrong. A declaration has three answers: absent (`DeclaredRange` treats a zero minimum as "speaks exactly the one version named"), valid, and contradictory (a minimum above the maximum), and the third is refused before any of registration's side effects run.

**What each version added, and whether an older peer is refused or reported.** 2: node-contributed capacity and site (refused; a v1 node reads as zero). 7: a destroy may set `CommandResult.Custody` (refused; the shape did not change and the meaning did). 8: ordered EC2 shapes and charged size on the lease (refused). 9: BuildKit cache-mount ceiling (refused). 10: per-shape price (refused). 12: trust and cache scope are properties of a pool (the floor). 13: the range itself and the node's release (`VersionNodeRelease`, reported). 14: `CommandInventory` for the compute barrier (`VersionComputeBarrier`, mirrored as `alloc.BarrierWireVersion`; an older host is named "too old to be asked" rather than asked, because asking burns its single command slot for the whole timeout). 15: `CommandUpgrade` (`VersionNodeUpgrade`, gated where it is sent). 16: the installed manifest digest (`VersionNodeDigest`, reported; a digest from a pairing below this is dropped, not refused). 17: the CodeBuild fleet ARN (`VersionCodeBuildFleet`, refused, because two nodes naming one fleet each advertise all of it). 18: the CodeBuild registration path and region (`VersionCodeBuildRegistrationPath`, reported, since it only decides where the sweep looks). 19: `POST /v1/nodes/{node}/withdraw` (`VersionNodeWithdrawal`, checked where emitted; an older plane answers a bare 404 and the node says the plane is too old to be told). 20: `POST /v1/nodes/{node}/leases/{lease}/cache` (`VersionCacheObservation`, reported; checked where emitted in `nodeclient.Client.RecordCacheObservation`, which returns success without sending below it, because what an older plane loses is one diagnostic column on `job_history` and nothing a job depends on).

**The release string is reduced on ingest.** It is the one free-form value a node puts in an operator's report, and a node is authenticated without being trusted to behave; stored verbatim it is a newline away from forging a row of `billet status`. An absent release is reported, not refused, because it decides nothing about capacity, fencing, identity or destruction.

**A registration proves who you are; only a command proves what you may do.** The certificate's common name decides which node a request is from, and a path that disagrees is refused rather than reconciled (`claims`); the certificate's organization decides which deployment. `forNode` requires the authenticated name, `forOwnLease` a lease that node was given, `forNewWork` also fences a superseded incarnation. The JIT endpoint once required only a registered node and let a host mint registrations for any scale set under any name; now a node may mint exactly the registration for a launch command it currently holds, because billet's runner names carry the lease id.

**`/v1/register` authenticates before it reads a body.** It names itself in the body, so it cannot use `forNode`; `authenticated` (verified chain, non-empty CN, revocation) runs before the decode. Go's `http.Server` withholds the whole response until an announced body arrives even for a handler that never reads it, so the test wraps `r.Body` in a counting reader and asserts zero bytes read, in both directions. The route is deliberately not method-qualified, because ServeMux would answer 405 before the handler runs, and a certificate holder that reached the path has arrived whatever verb it used.

**A registration discards the host's barrier run before the request is judged.** `Plane.ArrivingForRegistration` runs first on both paths (`Plane.Register` for in-process wiring and `handler.register`, which assembles the sequence itself), before the body is decoded and before revocation is checked, on the certificate's own name (`certificateName` reads the verified chain without the revocation check). A permanently refused registration is still an authenticated host reporting live compute, and the node does not retry. A loopback wire has no certificate, so there every run goes (`InvalidateEveryBarrierRun`) at the very top. Both forms answer 503 on failure, because `decode` writes its own 400 first and a node reads 400 as permanent. `InvalidateBarrierRun` reads before it writes, because it runs ahead of the revocation check and a revoked credential could otherwise reserve the writer slot on every request.

**Incarnation and epoch are different fences.** `RegisterRequest.Incarnation` is a fresh random value per node process, carried on every request as the `Billet-Incarnation` header (`HeaderIncarnation`) because some requests have no body; it distinguishes a restart from a duplicate and routes new commands to the newest registration while a superseded process may still maintain and report the work it holds, because a draining process has to outlive its replacement. The registration epoch lives on the node row and moves on every registration. Two hosts under one name are one host to the plane; after a restart it cannot say which physically holds a container, and the diagnostic says so.

**Commands are a serial queue with a ten-minute timeout that starts when queued.** A node executes one command at a time. Firing twenty destroys at once starts twenty clocks against a queue served in turn, so fan-out is bounded against the server's concurrency, not the client's patience. `CommandDestroy` is addressed by request id because it must work for compute whose lease is already gone. `CommandUpgrade` returns the instant the detached updater starts, because an inline upgrade would hold the slot for the whole drain. `CommandInventory` is asked, not waited for. Redelivery is expected everywhere; the runner's adoption path is what makes it safe. `WithdrawRequest` is an empty body on purpose.

**Two listeners, because a budget taken before the handshake cannot separate callers.** `/v1/ca` and `/v1/enroll` must serve a machine with no certificate; while they lived on `server.listen` their connections shared the fleet's budget, and a caller that handshook and idled held a slot until `IdleTimeout` (about 4.3 requests a second emptied 512). Reserved capacity is not a fix: which caller holds a certificate is unknown until after the handshake, so any pre-handshake quota is shared by construction. So `wirecert.ServerTLS` is `RequireAndVerifyClientCert` and `nodeplane.Handler` registers no unauthenticated route, while `server.bootstrap_listen` carries `BootstrapHandler` under `wirecert.BootstrapTLS` (`NoClientCert`, since asking only parses a chain a stranger chose). Its absence is the refusal: no address means no network enrollment, and `billet ca issue` is the way in. The enrollment route has a concurrency bound (`maxConcurrentEnrollments`) as well as a body bound (`maxEnrollBody`), because recording a request begins `BEGIN IMMEDIATE` against the single writer.

**The permit is charged only to what verified.** Splitting the listeners was half of it: the permit was still taken in `Accept`, before the handshake, so opening sockets and sending no TLS bytes spent the fleet's budget (about 52 connections a second held all 512 for the handshake timeout while `Accept` blocked ahead of the kernel accept). `handshakingListener` accepts unconditionally, bounds handshakes separately under an explicit deadline, and charges the server's budget only for a connection that verified. It wraps the tracking conn beneath the `tls.Conn`, because `http.Server` type-asserts to `*tls.Conn` to populate `Request.TLS`. Releasing a permit is a receive, so releasing one never taken blocks forever; the release is non-blocking so that mistake degrades into an accounting error a test can see. What is guaranteed: anonymous traffic can never displace an admitted node. What is best effort: a handshake slot, refused instantly so the node redials. The handshake deadline is derived: `Server.tlsHandshakeTimeout` is the minimum of the positive `ReadHeaderTimeout`/`ReadTimeout`/`WriteTimeout`, the wire has no `WriteTimeout` on purpose, and zeroing the other two would make it unlimited.

**Enrollment is two fingerprints compared by a person.** The node fetches the authority over the bootstrap listener, checks it against `--ca-fingerprint` (from `billet ca show`), generates a key, sends a CSR (`NewNodeCSR`) with a join token (`billet ca token`: short-lived, counted, stored as a SHA-256 digest; the check and the decrement are one statement), prints its own fingerprint and polls every `enrollPollEvery`. The operator runs `billet nodes pending` and `billet nodes approve <node> --fingerprint <fp>`; approving by name alone approves whatever holds the name. A name is claimed by the first key to ask and a second key is refused. `billet ca issue` records the admission as `issued` so `billet nodes pending --all` is the one answer to what was let in. The listener-level refusal of a certless connection is asserted as a `*net.OpError` with `Op == "remote error"`, measured, because crypto/tls's alert type is unexported.

**Renewal is authenticated by the certificate being replaced, and the subject comes from the identity.** A node renews when less than a third of its life remains, on the sweep pass; the key never crosses the wire (a CSR is sent, a signature returned); the subject is the authenticated CN, never the CSR's, or any node could mint a certificate for any name. The response carries the trust bundle, because a node renewing across a rotation needs the new authority. An expired certificate cannot renew and must be re-enrolled. Revocation is by serial, checked on every authenticated request (`notRevoked`), and fails closed on an unreadable list.

**A loopback wire has no certificates.** The trust boundary is the machine; config refuses `node.tls` against a loopback server, and the wire refuses to bind anywhere but loopback without `RequireClientCert` (`LoopbackOnly`).

## Measured facts

- Idle anonymous connections on the shared listener: about 4.3 requests a second emptied a budget of 512; silent sockets: about 52 a second.
- Dropping the `charged` guard on permit release did not fail a test; it hung the closing goroutine.
- GitHub's session conflict: `409 Conflict … RunnerScaleSetSessionConflictException`.
- A new node against an old plane fails as `json: unknown field "min_version"` before any version check.
- `tls.AlertError` cannot be matched with `errors.As` (unexported type); the refusal is asserted as `*net.OpError`.
