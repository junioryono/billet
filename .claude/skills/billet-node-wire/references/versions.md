# The version range

Part of the `billet-node-wire` skill. Each rule is stated in full, with the measurement or incident behind it.

**The wire is a range, and the bridge runs one way.** `nodeapi.MinVersion` is 12 and `nodeapi.Version` is 37; registration negotiates the highest both speak (`Negotiate`) and records it on the node's row, which `billet status` reports under `protocol`. The plane decodes bodies with `DisallowUnknownFields` while a node decodes responses leniently, so an old node's registration is a subset of a new plane's struct, while a new node's body that carries a field the old plane does not know hits its strict decoder before any version check runs. Upgrade the server first. A node-first upgrade is refused when its registration carries such a field or the ranges do not overlap, and the node adds its own range to every registration failure so the operator is not left with `json: unknown field "min_version"`; when neither holds, the node registers at the highest version both speak (`TestNegotiatePicksTheHighestVersionBothSpeak` holds the arithmetic), so only the gate on the negotiated version protects what follows.

**`MinVersion` is a promise about meaning, not about whether fields parse.** 11 and below decided a pooled runner's trust from the assignment that caused it to launch, which GitHub may reassign; lowering the floor to make an old fleet connect is offering to be wrong. A declaration has three answers: absent (`DeclaredRange` treats a zero minimum as "speaks exactly the one version named"), valid, and contradictory (a minimum above the maximum), and the third is refused before any of registration's side effects run.

**What each version added, and whether an older peer is refused or reported.** 2: node-contributed capacity and site (refused; a v1 node reads as zero). 7: a destroy may set `CommandResult.Custody` (refused; an older host is named "too old to be asked" rather than asked, because asking burns its single command slot for the whole timeout). 15: `CommandUpgrade` (`VersionNodeUpgrade`, gated where it is sent). 16: the installed manifest digest (`VersionNodeDigest`, reported; an older plane answers a bare 404 and the node says the plane is too old to be told). 20: `POST /v1/nodes/{node}/leases/{lease}/cache` (`VersionCacheObservation`, reported; checked where emitted in `nodeclient.Client.RecordCacheObservation`, which returns success without sending below it, because what an older plane loses is one diagnostic column on `job_history` and nothing a job depends on). 21: the tier label on `TrustedRunnerGroupRequest` (`VersionTargetedRunnerGroup`; a plane serving several GitHub targets needs it to know which owner's runner group a node is asking about, so an untargeted request from an older node is answered on a one-target plane and refused naming the version on several, because two organizations can each have a group of that name and guessing would vouch for the wrong owner's policy; the client sends the field only on a wire at or above 21, since the plane's strict decoder would refuse it on an older negotiated wire). 22: `CommandResult.Draining` (`VersionNodeDraining`, checked where emitted in `nodeclient.execute`). A launch a draining node refuses says so in that field, and the plane records it through `alloc.NodeDraining`, which sets `drained = 1` on the host's current registration (fenced on epoch and incarnation) while the host stays live for the destroys its running work needs; `ListPlaceableNodes` then skips it until its next registration clears the mark. The mark is fenced to the process that TOOK the refused command (`pending.takenLedgerEpoch` and `incarnation`, read together at delivery), never the node entry's current fence, which a replacement registering in between would own. Reserved floors are measured over every live host, draining or not (`countFloorLeasesPerTier`, `CountOpenPerTierOnLiveHosts`), because a draining host's leases are running jobs occupying their promised slots; admission modelling keeps the placement fleet's count. An older pairing loses only the memory of the refusal: the plane dispatches launches the node refuses, as it did before, 2440 of them in 23 minutes during one host upgrade (#228). 23: the tier's cache block and the cache authority (`VersionCacheAuthority`, #226): `TierSpec.Cache` carries the normalised `config.CacheSpec`, a completion's destroy carries `Command.CacheAuthority` (the plane's verdict on whether the job's writes may publish), `GET /v1/nodes/{node}/leases/{lease}/cache-authority` answers the Actions cache for a live lease the node holds (`forOwnLease`, never an ended one), `?kind=` selects a cache on the policy route, and the build caches' outcomes ride `CacheObservationRequest`. REFUSED ONLY WHERE AN OLDER NODE WOULD DO MORE than the tier allows, reads included (`config.Tier.NeedsCacheAwareNode`: every `default-branch` tier, whose repository namespace an older node would replace with the pool's wider pre-#226 keys; a trusted pool publishing `off` or `default-branch`; a Docker store or sticky disk turned off or held smaller; an Actions archive below 10GiB), because such a node ignores the block and applies the pre-#226 rule. Placement skips those hosts (`alloc.eligibleNodes` against `alloc.CacheAuthorityWireVersion`, pinned equal by a test), the plane refuses at dispatch, and `pending.minWire` refuses again at delivery, because a process that re-registered older after dispatch must not take the launch; `billet status` names a tier that waits because none of its own hosts is on 23 (`alloc.WaitsForCacheAwareHost`, placement's rule with and without the gate). A node below 23 is never asked for an authority (it answers the zero authority, which writes nothing) and an unregistered client (wire 0) answers an error to retry, never the older answer; the build-cache fields go only to a plane on 23, whose strict decoder knows them, and an observation carrying nothing else is not sent at all. 24: `VersionJobUsage`, two diagnostics. `Job.JobID` (GitHub's workflow-job id, empty for a pooled launch) travels plane to node and needs no gate, because the node decodes leniently and an older one ignores it. `POST /v1/nodes/{node}/leases/{lease}/usage` (`UsageRequest`: an `alloc.JobUsage` summary and an optional `alloc.UsageSeries` blob bounded at 512 KiB so the report fits the 1 MiB body) goes through `forOwnLease`, is validated at the boundary and fenced on the epoch by `alloc.RecordLeaseUsage`; `nodeclient.Client.RecordLeaseUsage` sends it only on 24 and treats an older plane as success. The node sends it from `Runner.destroy` before returning, because the plane releases the lease after the destroy and a report after release is `ErrLeaseNotFound`. 25: `VersionProcessUsage`, what a job measured by its process's own accounting reports (a tart VM): the `oom` group named unmeasured, and energy with the source `process` and no idle share. Checked where sent, in `nodeclient.beforeProcessUsage`: below 25 the report says less, never something else, because an older plane's strict validation knows neither (process energy becomes unmeasured, and memory with no OOM count becomes unmeasured whole, since that plane reads measured memory as a measured count); the downgrade works on a copy of the caller's `Unmeasured`. 26: `VersionJobCounters`, the vCPU threads' hardware counters on a usage report (`JobUsage.Counters`, an `alloc.JobCounters` whose every event is a pointer, nil where it was not counted, stored as NULL by migration 58). A diagnostic, reported rather than refused. Checked where sent: `nodeclient.Client.RecordLeaseUsage` strips the counters below 26 and sends the rest, because an older plane's strict decoder would refuse the whole report for one unknown field. Checked where read: `nodeplane`'s `leaseUsage` drops them from a report whose current incarnation negotiated below 26 (`Plane.NegotiatedWire`), which only a node sending what its wire does not carry could produce; a process the plane does not know the wire of (a superseded one draining) keeps them, since only a build that speaks 26 can have sent them. A counters block that counts nothing is refused by `JobCounters.Validate`, because the ledger would read it back as none. 27: `VersionJobDestinations`, the job's traffic by destination on a usage report (`JobUsage.Destinations`, an `alloc.JobDestinations`: up to 256 named destinations in the node's order, the traffic beyond them, the `incomplete` verdict, and the tap's totals when they were read), stored by migration 59 in `job_destinations` (at most 257 rows a lease, the rest the row with an empty address at ordinal 256) with the verdict and the tap on `job_usage`, NULL where the flows were not totalled. A diagnostic, reported rather than refused, and checked at both ends exactly as 26 is: `nodeclient.Client.RecordLeaseUsage` strips them below 27 and sends the rest, and `nodeplane`'s `leaseUsage` drops them from a report whose current incarnation negotiated below 27. `JobDestinations.Validate` refuses more than 256 named, an address that is not one in its canonical spelling or carries a zone (free text `billet jobs show` would print), one named twice, a rest that names an address, a negative total, and a tap beside a network group named unmeasured. The largest report (a series at its bound, every counter, 256 destinations at the longest address and the largest totals) fits the 1 MiB body, which `TestTheLargestUsageReportFitsOneRequest` holds. 28: `VersionSeriesClock`, a usage report's series may be `lease.UsageSeriesCodecClocked`: the first sample's wall time on the host's clock and the sampler's marks for the intervals it did not see (a missed tick, a failed read of a group it had read, a final sample taken while it was stuck), which `billet jobs show` places a job's steps on. Checked where sent, in `nodeclient.beforeSeriesClock`: below 28 the node re-encodes the series without them (`usage.WithoutClock`), because an older plane validates the codec strictly and would refuse the whole report over it; the caller's series is not changed, and a series that cannot be re-encoded is dropped while the summary is still sent. The plane accepts both codecs at every version, since a clocked series reaching it says more and never something else. 29: `VersionGuestReport`, a node can carry what the agent inside a job's guest told it, once before the compute is destroyed, on `POST /v1/nodes/{node}/leases/{lease}/guest` (`nodeapi.GuestReportRequest`: the epoch and a `lease.GuestReport`, whose `Data` is the node's encoding of the agent's batches under `Codec` 1, opaque to the plane, beside what the node counted of the channel: batches accepted and refused, bytes dropped, hello and final batch seen, a node restart, and the first and last arrival on the node's clock). The guest's own unverified view, never folded into `JobUsage` and never an input to a decision; stored by migration 60 in `job_guest_reports` (one row a lease, the first report kept, fenced on the epoch, refused after release, `recorded_at` indexed for a retention job). A diagnostic, reported rather than refused, and checked at both ends: `nodeclient.Client.RecordGuestReport` sends nothing below 29 and says so once in the node's log (and answers `ErrUnregistered` with no wire negotiated, since that cannot be told), and `nodeplane`'s `guestReport` refuses a report from a current incarnation that negotiated below 29. `GuestReport.Validate` refuses an unknown codec, `Data` over 256 KiB, a version over 64 bytes or outside printable ASCII without spaces (a reader prints it beside what the guest does not control; the refusal names the offending byte, never the value), a schema outside 0 to 65535, a negative count, and arrival times that are one-sided, out of order or outside the years RFC 3339 spells. The route is served only when the lease store keeps guest reports (`nodeplane.GuestReportStore`, which the allocator implements and a compile-time assertion holds); a store that keeps none refuses it permanently. The largest report fits the 1 MiB body (`TestTheLargestGuestReportFitsOneRequest`). 30: `VersionSeriesGaps`, a usage report's series may be `lease.UsageSeriesCodecGaps` (codec 3: codec 2's layout with each point's `usage.GapCause` in place of its 0/1 mark), so `billet jobs show` can say why an interval was not seen (#495). Reported, not refused, and checked at both ends: below it the node re-encodes the series with marks alone (`usage.WithoutCauses`, and without the clock below 28), and the plane drops a codec-3 series from a pairing negotiated below 30 and keeps the summary (`TestASeriesWithCausesFromAWireThatDoesNotCarryThemIsDropped`). No field changed, so `testdata/wire/v30` is v29's bodies. The cause numbers are stored and frozen (`TestTheGapCauseNumbersAreFrozen`); a new cause needs a wire version of its own, below which the node sends it as `unspecified`, because a reader refuses a whole series naming a cause it does not know. 31: `VersionNpmCache`, `TierSpec.Cache` may say the node serves the npm registry to the tier's guests (`config.CacheSpec.Npm`, a bool omitted when false, ADR-020). Neither refused nor reported: the field travels plane to node only, and an older node decodes it leniently and ignores it, which leaves the tier's npm traffic going to the registry, so `config.Tier.NeedsCacheAwareNode` is unchanged. The bodies of `testdata/wire/v31` differ from v30's only where a filled `CacheSpec` now carries `npm`. 32: `VersionNpmObservation`, a cache observation may carry what the npm registry cache did for the job (`CacheObservationRequest.npm_cache`, stored by migration 67 in `npm_cache` on `leases` and `job_history`, in the build caches' closed vocabulary), which `billet jobs show` names beside them. The component names are wire vocabulary: a node refuses to complete or promote while its control plane accepts a component its build does not install, so a new `config.ImageComponent` is accepted in a control plane's config only once every node runs a build that installs it, and until then an older node's image commands refuse, naming it. **The release string is reduced on ingest.** It is the one free-form value a node puts in an operator's report, and a node is authenticated without being trusted to behave; stored verbatim it is a newline away from forging a row of `billet status`. An absent release is reported, not refused, because it decides nothing about capacity, fencing, identity or destruction.

**The encoding is pinned per version (#356 Phase 2).** `internal/nodeapi/golden_test.go` pins every wire struct of the current `Version` as six files under `testdata/wire/v<Version>/`: `<Type>.json` with every field populated from its JSON path, sized to its width and distinct from every other field's sample (so a refactor that keeps the encoding keeps the sample, and two fields' keys cannot swap unseen); `<Type>.zero.json` with every container allocated and every scalar zero, which is what pins `omitempty` at every depth; `<Type>.shape.txt`, the Go kind and width behind each JSON path (an `int64` narrowed to an `int8` encodes a small sample the same way); and `<Type>.bools.json`, the populated encoding once per boolean with only that one true, since two booleans cannot be told apart by any single sample; and `<Type>.empty.json` (the Go zero value, every pointer, slice and map nil) and `<Type>.hollow.json` (every pointer allocated, every slice and map empty but not nil), which with the zero fixture pin how nil, empty and zero values encode at every depth. A `MANIFEST` records their hashes, and no wire type may encode or decode itself (`MarshalJSON`, `MarshalText`, `UnmarshalJSON` or `UnmarshalText`, `time.Time` excepted), because its bytes for those values, and what it accepts from an older peer, are its own. For every version from 25, or `MinVersion` if higher, to `Version`, the directory must exist and match its `MANIFEST`, and each body must still decode as its receiver decodes it, strictly for a request to the plane and leniently for a response to a node, and re-encode carrying every field it had, and each JSON path of its shape must still be encoded with a range that holds the old one: numbers are compared as their exact text, and widening is allowed only within a family (an `int32` to an `int64`, a `float32` to a `float64`, never an integer to a float, which spans the range and loses every value above 2^53): a field added since, or a number widened, is allowed; one lost, retyped or narrowed is not. Every exported type in `nodeapi` is pinned or excused by name, the fill fails on anything it cannot set, and only `BILLET_UPDATE_FIXTURES=1` writes, for the current version only. It exists because a round trip cannot see a rename: `Command.Lease` is `alloc.Lease`, a ledger struct without JSON tags, so a renamed Go field there is a renamed wire field on both sides of a round trip at once. Measured 2026-10-04: the v25 fixtures show the lease travelling under its Go field names (`TargetNode`, `VCPU`) beside the tagged `sticky_cache` and `git_cache` of its embedded `BuildCaches`.

**The wire's vocabulary imports no ledger (#356 Phase 2).** `internal/nodeapi` names a lease through `internal/lease`, which holds the phases, the lease record and the observation vocabularies moved out of `internal/alloc` with aliases left behind, and its non-test files may import nothing of billet's but `config` and `lease` (the `nodeapi` depguard rule). `Command.Lease` carries `lease.Lease` itself, every field of which names its wire key in an explicit tag equal to its Go name (`TestEveryLeaseFieldNamesItsWireKey`), so a Go rename keeps the wire as it was; the golden fixtures proved the tags moved no byte. A separate wire struct with conversions was judged not worth its churn once the fixtures pin every encoding change.
