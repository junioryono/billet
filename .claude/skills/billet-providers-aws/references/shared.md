# Rules shared by both backends

Part of the `billet-providers-aws` skill. Each rule is stated in full, with the measurement or incident behind it.

**billet signs its own requests, pinned to AWS's own signer.** A program constructing an EC2 client and calling `RunInstances` once built to 13.2MB against a whole billet of 21.8MB and pulled fifteen modules, carried by every node including the bare-metal ones the cloud backend exists to fall back from. `internal/awssig`'s output is pinned to vectors generated by `aws-sdk-go-v2` (`sign_test.go` carries the regeneration snippet); CodeBuild gets its own vectors because a signed JSON body with an `X-Amz-Target` header is a different thing from a form-encoded one. Only env-var and IMDSv2 credentials are supported; everything else is projected into the environment.

**A 404 from S3 is two different facts, and only `NoSuchKey` is absence.** `internal/awss3` parses the `<Error>` document every refusal carries, and it exists because billet's two S3 readers — `internal/store/ebss3` for the site cache and `internal/archivestore` for the deployment archive — each turned every 404 into "the object is not there". A bucket that did not exist was therefore indistinguishable from a cold cache: every job fetched cold, the cache path fails open by design, and `billet check`'s own bucket probe printed that the bucket answered. Measured against real S3 in us-east-1 on 2026-09-04, both HTTP 404: a missing key in a bucket that exists is `<Code>NoSuchKey</Code>`, and any key in a bucket that does not exist is `<Code>NoSuchBucket</Code>` — a bucket is resolved before a request is authorized, so the second needs no identity at all. An unrecognised 404 (no code, a code billet will not repeat to an operator, a body it could not read whole, a root element that is not `<Error>`) stays an error, because could-not-tell never collapses into no. The refusal travels as an error, so `billet check` asks `awss3.StatusOf` for its inconclusive-403 branch rather than matching the substring "HTTP 403" in a message anybody could reword.

**The credential chain lives in `internal/awscreds`, not in a backend.** It used to live in `ec2`, so three packages that could not import a compute backend each declared their own interface over the identical method and `cmd/billet` bridged every site with a conversion closure. The move was verified by mutation (29 of them) because the redaction table is where it could have gone wrong (`billet-security`).

**A fake proves the shape of a request, never the values a real service refuses.** Every rule under the two headings below was a defect that passed a fake and died on a real call, so a backend is not finished until one real job has run on it.
