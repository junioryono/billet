# AWS providers: ec2 and codebuild

## What this area is

`internal/provider/ec2` launches one instance per job in one subnet with `RunInstances`, builds and verifies the AMI (`billet ami build|verify`), reads spot interruptions from a per-node SQS queue and reports quotas. `internal/provider/codebuild` starts one build per job on a dedicated tagged `NO_SOURCE` project, stages the runner registration in Parameter Store, and sweeps registrations a dead node left. Neither uses the AWS SDK: `awssig` signs SigV4, `awsjson` speaks JSON 1.1, `awscreds` resolves env or IMDSv2 credentials, `awspolicy` generates least-privilege IAM from action constants each package declares, `awsquota` reads Service Quotas, `awsssm` reads and writes Parameter Store, `awssts` answers which account a credential is in. An `ec2` or `codebuild` node is an orchestrator, a serial launch queue, with `node.max_vcpu`/`max_memory` as hard budgets. `docs/reference/decisions/adr-002-cloud-compute-backend.md` and `adr-007-codebuild-provider.md`, `docs/deploying/aws-codebuild.md`, and the acceptance record in `docs/reference/records/aws-acceptance.md` hold the measurements.

## Rules shared by both

**billet signs its own requests, pinned to AWS's own signer.** A program constructing an EC2 client and calling `RunInstances` once built to 13.2MB against a whole billet of 21.8MB and pulled fifteen modules, carried by every node including the bare-metal ones the cloud backend exists to fall back from. `internal/awssig`'s output is pinned to vectors generated by `aws-sdk-go-v2` (`sign_test.go` carries the regeneration snippet); CodeBuild gets its own vectors because a signed JSON body with an `X-Amz-Target` header is a different thing from a form-encoded one. Only env-var and IMDSv2 credentials are supported; everything else is projected into the environment.

**The credential chain lives in `internal/awscreds`, not in a backend.** It used to live in `ec2`, so three packages that could not import a compute backend each declared their own interface over the identical method and `cmd/billet` bridged every site with a conversion closure. The move was verified by mutation (29 of them) because the redaction table is where it could have gone wrong (`billet-security`).

**A fake proves the shape of a request, never the values a real service refuses.** Every rule under the two headings below was a defect that passed a fake and died on a real call, so a backend is not finished until one real job has run on it.

## ec2

**`ClientToken` is durable.** Measured still refusing a changed relaunch of the same lease long after the fact, so `clientTokenFor` is a safety property: an ambiguous retry cannot start two machines. A shape AWS has none of (`InsufficientInstanceCapacity`) falls through to the next declared shape, but only after a synchronous refusal that launched nothing; after an ambiguous failure it stops.

**`TerminateInstances` returns when the request is accepted.** The machine keeps running for a minute or two, so `Destroy` returns `TeardownRequested`, the node keeps the lease charged, a targeted lookup's explicit `terminated` record is causal proof, and absence otherwise has to stay uninterrupted through the remote-consistency window. Waiting inside the teardown was never the fix, because a node runs one command at a time.

**The AMI is verified by booting it, and the tag is the promotion.** Every other claim a build makes is checked on a builder that has been apt-installed and never rebooted; the Docker gate read `overlayfs` off exactly that machine while the image reports `overlay2`. `billet ami build` launches the produced image, reads its report through the console (`GetConsoleOutput`, nonce-bound, no key pair, no inbound access), and only then writes `AMIContract` with `CreateTags`; `ErrPromotionUncertain` is the third value for a failure after the tag. A `TagSpecification` on `CreateImage` is authorised as a separate `ec2:CreateTags` check keyed on `ec2:CreateAction`, measured with `create-image --dry-run`. The verifier proves the toolcache and the runner execute as the runner account under the job's own `env -i` (`billet-shell-gates`). An AMI id is region-scoped. Measured 2026-08-28: provisioning 3m54s, snapshot to available 11m06s, console report 4m40s after the verifier launched.

**User data is 16384 bytes, gzipped, and `packUserData` is the gate.** The registration is shell-quoted into it (a single-quoted assignment, the one construct with no parsing left; a quoted heredoc inside `$( )` died on a quote in the value), `HttpTokens=required` and `HttpPutResponseHopLimit=1` keep a container inside the job from the metadata service, and `instance_profile` is optional because a profile is readable from inside the guest. Cold-start timing is measured from an epoch billet puts in the user data: three cold runs reached the first job step in 47.6 to 58.7 seconds, which is why `warm_pool` stays refused.

**Spot warnings are one queue per node.** The router resolves the warned instance's `sh.billet.node` tag and targets that node's queue; the queue basename must equal the node's identity, and a shared queue is refused because one consumer hides a message for the visibility timeout. The queue HOST is refused unless its DNS suffix is the one `node.ec2.region`'s partition serves: the validator used to admit both, so a `cn-north-1` node could name `sqs.cn-north-1.amazonaws.com` — not a host — while `billet init iam` derived `arn:aws-cn:sqs:...` from the same region, leaving a correct policy in front of a queue the node never reached and a two-minute warning that never arrived. A live FIS interruption exercised the path. Untrusted work needs `node.ec2.untrusted_security_group_ids`; an instance isolates the kernel, not the VPC.

**`awspolicy` is one generator with three consumers and a measured boundary.** The ownership boundary is per deployment when the owner is known and account-wide otherwise; the tag boundary is destructive integrity and the per-deployment KMS key is confidentiality. Validated against a live account with `iam:SimulateCustomPolicy` in both modes. `Inputs.Build` once emitted the runtime statements unconditionally, so a controller that launches nothing held `ec2:RunInstances` (hence `NoCompute`), and the terraform module hand-wrote the grant until `internal/tfpolicy`'s drift test began reading the generator's rendering.

**`ec2:CreateVolume` from a snapshot authorises the snapshot as well** (the `ebs-s3` store found it: `aws:RequestTag` is not in the snapshot's context, so the one statement conditioned on the new volume's tag denied every clone). `BilletCacheCloneSource` grants it on `arn:<partition>:ec2:*::snapshot/*` conditioned on the owner tag.

## codebuild

**A build cannot be tagged, so ownership is a dedicated project plus markers.** `StartBuild` has no field that becomes a tag; the boundary is a per-deployment-and-node tagged project plus `BILLET_OWNER` and `BILLET_INSTANCE_NAME` environment overrides read back through `BatchGetBuilds`. `List` and `Find` verify both, and an owner-marked build whose lease marker names no lease fails the whole inventory, because this list frees capacity.

**`ListBuildsForProject` has no status filter, keeps a year, returns 100 ids a page and errors if `sortOrder` is passed above 100 builds.** `List` and `Find` are a bounded page walk, bounded by CodeBuild's own enforced ceilings (`timeoutInMinutes + queuedTimeoutInMinutes + slack`). Three things freed a running build's capacity and passed a reading: a page with no ids and a next token ended the walk; `BatchGetBuilds` was assumed to answer in request order (it does, measured, so billet imposes the order rather than observing it); and `Find` returned the newest match, so a lease whose newest build was terminal while an older one ran was reported terminal. `Find` prefers the single live match, refuses two, and returns the newest terminal only when nothing runs.

**`idempotencyToken` is valid for five minutes, so an ambiguous `StartBuild` is not retried.** Two identical calls under one token return the same build id and a changed parameter is refused `InvalidInputException: Request parameter mismatch for idempotency token`; past five minutes an identical retry starts a second build. The provider takes a caller-supplied `*http.Client` with no bound on its timeout, so correctness cannot depend on a retry landing inside a window billet does not control. `client.callCreating` retries only a throttle. The same 4xx/5xx line decides whether the staged registration may be deleted (`conclusiveness`): a 4xx is the service answering no; a 500 carries a code too and had committed the build.

**Two things made the backend unable to run a single job and died on the first real one.** A standard SSM parameter caps at 4096 characters and a JIT configuration exceeds it; every test staged a short placeholder. `putJITConfig` asks for `Tier: Intelligent-Tiering`. And a CodeBuild container runs as root, where GitHub's runner prints `Must not run interactively with sudo` and exits zero, so the build succeeded having registered nothing; the buildspec exports `RUNNER_ALLOW_RUNASROOT=1` in the phase that execs the runner, and the test asserts the phase.

**The registration goes through Parameter Store, and only the name is ever rendered.** Every `StartBuild` field is rendered in the console and CloudTrail, so the JIT config is a SecureString under `<jit_parameter_path>/<instance>` handed over as a `PARAMETER_STORE` environment variable named `ACTIONS_RUNNER_INPUT_JITCONFIG`. SSM rather than Secrets Manager because `DeleteParameter` is immediate. Measured 2026-08-31: `BatchGetBuilds` reports the parameter's name as the value, the staged value appears nowhere, and a service role holding only `ssm:GetParameters` resolves it. The build's service role is a different principal from the node role.

**A staged registration has four removers, and only the control plane's sweep uses the ledger.** The node removes it on a conclusive refusal, a confirmed teardown and custody settlement (`StagedCredentialReaper`, called only from settlement, after something proved the compute gone; a phase predicate that inferred consumption from "not found" was deleted because "not found" and "not appeared yet" are one observation). A node that dies between staging and settling leaks exactly one (measured: three from one killed node), so `RegistrationSweeper` lists the path the node registered (`GetParametersByPath`, `WithDecryption=false`, decoded into a type with no `Value` field, `TestTheSweepNeverDecodesAValue`), takes the whole listing before any delete because the cursor is positional (measured: three parameters at `MaxResults 1`, delete page one's, and page two returns the third while the second is never listed), and deletes only when the ledger's `ClosureLookup` says the lease is terminal and has been for `ServiceInventoryWindow` (36h + 8h + 1h) since both `finished_at` and the parameter's own `LastModifiedDate`. Unknown, open and recent leases and foreign names are kept and counted; a ledger error stops the pass; every pass is recorded in `credential_sweeps`. The controller's grant is `GetParametersByPath` and `DeleteParameter` on the path and its children, no `GetParameter`, no KMS (`awspolicy.CodeBuildSweep`, `billet init iam --controller-sweep`).

**Reserved capacity is not a per-job boundary; on-demand Linux is.** Reserved fleets keep instances alive between builds and share cached data across projects by design (measured: a marker written by one build read by the next), and macOS is reserved-only, so untrusted work is refused whenever `fleet_arn` is set or the environment is non-container. On-demand Linux destroyed its machine between all 31 builds measured (31 boot ids), so untrusted work is admitted there only under `untrusted_vpc_id`, `untrusted_subnets` and `untrusted_security_group_ids`, verified on the project through `BatchGetProjects` because `StartBuild` has no VPC override, and still strictly weaker than an instance (the service role is readable at `169.254.170.2`). A `fleetOverride` on `StartBuild` makes CodeBuild ignore the project's VPC configuration, which is why the terraform module refuses VPC inputs beside an adopted `fleet_arn`.

**A reserved fleet's claim is released by a proof.** Two nodes naming one fleet each register its whole capacity; the ledger refuses a second claimant until `decommission_proven = 1` (`billet-capacity`). A `codebuild` node may not declare a `site`.

**`terraform destroy` refuses under a running build, and it is the module that refuses.** `DeleteProject` succeeds while a build is in its `BUILD` phase (measured 2026-09-02); `refuse-active-builds.sh` walks the project's builds through the operator's `aws` CLI as a destroy-time provisioner, pins `TZ=UTC`, and never calls `StopBuild`. `BILLET_SKIP_ACTIVE_BUILD_GUARD=1` is the operator asserting the fleet was drained.

**`ec2:RunInstances` on `*` authorises every snapshot a block-device mapping names.** The account-wide node policy grants it unconditioned, so a node role can launch an instance with any snapshot in the account attached and read it: in a shared account that is the control plane's ledger snapshots, identity and CA key included. Every other route to a foreign snapshot is closed by the generator's tag conditions (`BilletCacheCloneSource`, `BilletCacheAttach`); this one is open until #39 adds the deny to what `awspolicy` renders. The acceptance role carries it by hand: deny `ec2:RunInstances` on `arn:aws:ec2:*::snapshot/*` when `ec2:ResourceTag/sh.billet.owner` is null, measured with `simulate-principal-policy` (explicit deny on an untagged snapshot, allowed with the tag, allowed for a plain launch; 2026-09-04).

## Measured facts

- SDK cost: 13.2MB and 15 modules for one `RunInstances`, versus 21.8MB for all of billet.
- `CreateSnapshot` takes no `ClientToken` (`UnknownParameter`); the token travels as the `sh.billet.snapshot-token` tag.
- SSM standard parameter: 4096 characters; JIT configs exceed it.
- `StartBuild` idempotency: five minutes; same token same id; changed parameter refused.
- Positional SSM cursor: page two after a delete skips a parameter.
- Default `aws/ssm` key: `WithDecryption=true` returns plaintext with no `kms:*` grant; a customer-managed key refuses `kms:Decrypt` and a mixed page fails whole.
- `DeleteProject` succeeds under a live build; the build runs on.
- EC2 cold start: 47.6, 52.2, 58.7 seconds to the first job step (2026-08-18).
- SQS endpoint suffixes, resolved 2026-09-04: China is `amazonaws.com.cn` for all three forms (standard, legacy `<region>.queue.`, and `vpce`), the commercial names are NXDOMAIN there and vice versa, and **GovCloud takes the commercial suffix** — so the partition is derived from the region's `cn-` prefix (`config.AWSDNSSuffix`, which `awsjson.DNSSuffixFor` calls) rather than from the partition name.
