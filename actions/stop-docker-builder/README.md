# stop-docker-builder

The teardown half of `setup-docker-builder`, which invokes it as one of its own steps — a workflow does not normally reference it directly. Its main step only records the builder's identity; the real work runs in its `post` hook with `post-if: always()`, at the end of the job even when the job failed: it stops the BuildKit container so the sticky disk is quiescent, enforces the per-mount cache ceiling before publication, and removes the discard marker only after that policy held. It is a separate action rather than a step inside `setup-docker-builder` because only an action's post hook is guaranteed to run after every later step, failures included. Inputs are documented in [`action.yml`](action.yml); the cache model and ceiling semantics in [`../setup-docker-builder/README.md`](../setup-docker-builder/README.md).
